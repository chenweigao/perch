# Round 25（2026-11-16）：候选队列穷尽评估（无候选轮）

**结论：本轮为"记录在案的无候选结论"轮**（目标契约允许的轮次收尾形态
之二）：对 round-24 后候选队列的**全部剩余项**逐项给出证据化裁决
（机制探针 / 份额-分离阈算术 / bench 覆盖检查 / 红线与否定清单反查），
**无可立项的可分离性能候选**；唯一存活的增益方向为门控中的"跨实例
渲染缓存"（设计论证前置未满足 + 本轮新识别的 bench 保真难题，见下）。
**停止规则计数 2/3**（round-24 正确性轮 1/3 + 本轮 2/3；round-26 若再
无"超噪声的可采纳收益"即触发停止规则①输出总结报告）。产品树零改动
（本 PR 仅 docs）；无 A/B（无候选）；CI 为 docs-only（math 门槛
changed_inputs=False，比率门不适用）。

## 评估方法

每项裁决按既定纪律给出**可复核依据**：机制探针（swiftc -O 本地，
语义/量级事实）、份额-分离阈算术（候选机制的份额上限 vs 采纳指标
实测 spread——低于噪声带即不可分离，round-13/18/21 先例）、bench
覆盖检查（机械类候选必须双端上下文内粗筛——round-15 教训；无 bench
覆盖=框架内不可裁决）、红线/否定清单反查（round-18 流程规则）。
孤立微基准不用于采纳判断，仅用于机制事实（round-15 纪律）。

## 逐项裁决

### 1. ConversationActivity.outputCharacters 的 utf16.count 扫描 —— 粗筛前否决（探针证据）

队列第 3 项（"可参照 KimiInFlight 的既有缓存口径，不得引入全局
memo"）。written 循环每次派生走全窗口 assistant text/thinking 部件
（流式逐 delta 派生 ⇒ 累计准二次）。**机制探针**（Linux swiftc -O，
SWAR 字节计数正确性 20,000 随机串零失配后计时；归档
[round-25/probe/](round-25/probe/)）：**stdlib `utf16.count` 在全部
产品形态上快于 SWAR 替代**——

| 形态 | stdlib | SWAR | 比值 |
| --- | --- | --- | --- |
| 2000 个 CJK 混排短部件（single_turn 夹具同形） | 0.688ms/遍历组（~362ms/GB） | 1.469ms（~774ms/GB） | stdlib 快 2.1× |
| 2000 个 ASCII 部件 | 0.075ms（~36ms/GB，O(1) 级快路径） | 1.542ms | stdlib 快 20× |
| 4KB CJK 长文 | ~0.000ms（~1.4ms/GB——近乎免费的快路径/缓存行为） | 0.031ms | stdlib 数量级优势 |
| 500 个 emoji ZWJ 部件 | 0.175ms | 0.357ms | stdlib 快 2.0× |

⇒ "手写更快"假设被证伪。缓存变体（KimiInFlight 口径）：份额上限
估算——探针中 2000 部件全窗遍历 ~0.034ms/次 vs activity_init@2000
基线 ~0.76ms（Mac，round-24 v2 数据）≈ **4.6% 上限**，且缓存只能省
其中命中部分；对照该指标历史 spread（4.30～7.50%）——**收益上限低于
噪声带，不可分离**；同时触"不得引入全局 memo"红线的设计论证成本。
双杀 ⇒ 否决。

### 2. find-bar 每 delta 温路径地板（prefix memcmp / hits CoW 拼接 / 最近轮 TimelineEntry.make）—— 份额-阈算术否决（HYPOTHESIS 边界如实标注）

find_bar_query_update（温路径采纳指标）Mac 基线中位 **0.28ms**、典型
spread **10.71%**（round-24 v2 数据）⇒ 可分离阈 ≈30µs/更新。已知
最大分量 TimelineEntry.make：round-21 已放弃叶级评估（ARC 散点
**~4.1% 上限** ≈11µs<阈 + trim 家族否定清单 + API 形变红线）。
prefix memcmp 与 hits CoW 拼接自 round-12/17 后**无独立归因**——
量级需要一轮全新的 Mac xctrace 归因才能确定，而其合计上限的合理
估计（扣除 CF 匹配红线域与已采纳项后的地板残量）不指向 >30µs 的
单一可改机制。**归因成本 vs 合理上限不成立 ⇒ 否决**（此为成本-收益
裁决而非数学证明，HYPOTHESIS 边界如实标注；若未来出现指向该地板的
新归因证据可重开）。

### 3. SessionEditStats lowercased() 每 tool_use 分配 —— 份额算术否决

队列自记份额 **0.22%**（round-12 复剖）。edit_stats@6400 历史 spread
3.02～7.49%——即使 100% 消除也低于噪声带 1～2 个数量级，不可分离；
且需要 round-22 级穷举非 ASCII 映射证明（U+212A 机制）才够正确性
门槛——**证明成本与不可分离收益完全不成比例 ⇒ 否决**。

### 4. TurnStatus.live 的 Array(messages.dropFirst(start)) 拷贝 —— 框架内不可裁决（记录缓议，非实质否决）

bench 覆盖检查：**零覆盖**——`TurnStatus` 无任何 Bench 夹具引用，
调用方仅 AgentWorkbench UI（ConversationActivityBar）。机械类候选
必须双端上下文内粗筛（round-15 纪律）⇒ 现有测量框架内不可裁决；
且拷贝为 CoW 浅拷贝（元素 retain，非深拷贝），机制量级未归因。
**记录为"不可测/未归因"，不消耗否决**；若未来 UI 侧诊断（第 6 项）
显示状态栏更新可感成本，再评估是否值得新建测量面（round-21
long-tail-stream 先例：测量面扩展需独立论证）。

### 5. 跨实例渲染缓存（find-bar 冷搜 1110ms 的 WorkbenchCore 有界缓存）—— 存活但门控（本轮新增保真难题记录）

队列原文门控："WorkbenchCore 内有界缓存需先过'不得引入全局 memo'的
设计论证"。本轮源码评估（ConversationSearch.swift）：缓存单元形状
清晰（第 155 行 `sources.map { Self.renderedText(ReplyDocument.parse($0)) }`
的 per-entry 渲染结果，实例内已按源字节键缓存——round-12 机制），
跨实例静态有界缓存有 NarrativeTextCache 先例（有界静态表已被接受）。
**新识别的 bench 保真难题**：find_bar_cold_query 每迭代新建实例、
夹具窗口不变 ⇒ 跨实例缓存会让"冷"指标从第 2 迭代起变温——**静默
改变既有采纳指标的语义**（round-20 F3 MISS 保真教训的镜像：那轮靠
唯一文本夹具保 MISS 分布；此处等价手段=每迭代唯一窗口或缓存 flush
钩子，两者都动既有夹具/产品 API 面）。立项前置条件（缺一即不可
立项）：① 有界性/驱逐/线程安全/Sendable/生命周期独立的设计论证
成文并过评审；② 保真方案（新指标 find_bar_reopen 形态 + 既有 cold
指标语义保持的证明）；③ 产品对应面论证（重开查找栏/HistorySearchWorker
每键查询=真实复用形态，首开=真冷不变）。**留作 round-26+ 唯一存活
增益方向**。

## 否定清单新增

- **stdlib `utf16.count` 的手写替代不可立项**（round 25 探针否决）：
  Swift stdlib 对 ASCII 有 O(1) 级快路径、对长 CJK 有近免费路径，
  SWAR 字节计数在全部产品形态慢 2～20×（正确性 20,000 随机串零失配
  前提下仍慢）——勿以"utf16.count 是 O(n) 扫描"为机制假设立项；
  探针与数据归档 round-25/probe/。
