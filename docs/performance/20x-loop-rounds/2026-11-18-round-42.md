## 粗筛（上下文内，round-15/40 纪律）

- **机制**：`KimiConversation.displayMessages` 每次调用做 O(窗口)
  `messages + [live]` 拼接（ConversationTimeline.swift:221）+ O(尾距)
  lastIndex/last 扫描 + live 去重字符串比较。产品每个流式更新周期
  ≥2-3 处调用（只读调查 AgentWorkbench 调用点：KimiWorkspaceView:125
  summary + :456 transcript + KimiConnection:804 per-update +
  FindBar/Model 条件路径——零改动，红线区仅读取）。
- **round-38 双层封死论证的逐点重检**：
  1. 「非 mutating getter=public API 红线」——修订计数 box 方案**不改
     getter 签名**：memo 状态存于 struct 内 `private let` 引用 box，
     读写经 box 内部锁，struct 本体不变 ⇒ 不触红线。
  2. 「共享 box 破坏拷贝语义」——采用**只过失效**设计：box 仅存
     (revision: UInt64, cached: [KimiMessage]?)；五个 mutating 入口
     （init/reconcile/prepend×2/apply）bump revision；getter 验证
     `box.revision == cachedRevision` 才命中。共享 box 的副本间任何
     变更至多导致其他副本**多算一次**（过度失效），**永不返回陈旧
     值** ⇒ 值语义（同输入同输出）严格保持。round-38 档案未逐点
     驳倒此变体（其驳倒对象为 eager 维护与无修订号的惰性 box）。
  3. 「eager 缓存令 paging 每 prepend 多付一次拼接（older_page
     −2~3% 反向）」——惰性方案 prepend 只 bump（O(1)），下次 getter
     调用才算 ⇒ paging 每 prepend 仍恰一次拼接，零回归路径。
  4. 「box-lazy 单调用方形态零收益」——产品流式形态为**多调用方**
     （上述 ≥2-3 处/更新），bench 两次调用忠实镜像；单调用方形态
     收益为零但成本亦近零（一次 revision 比较）。
- **上界估算**（既有 A/B stage 中位，无需新探针）：Linux v3 批
  commentary 链 display_workspace+display_timeline ≈ 0.61ms/1.68ms
  ≈ 36%；thinking 链 ≈ 0.57/1.14 ≈ 50%。memo 将第 2..n 次调用降为
  O(1) ⇒ commentary_chain_total 预期 −15~18%、chain_total 预期
  −20~25%（第 n 调用命中率取决于产品调用重数；bench 恒 2 调用 ⇒
  至少一半 stage 成本消除）。远超 8% 采纳阈。
- **红线核对**：不触 AgentWorkbench（调用方零改动）；非全局 memo
  （per-value box，有界=每 box 一个数组；五点论证走 round-30/38
  口径）；否定清单无此机制（round-38 为「入队列」非否决）。
