## 粗筛（上下文内，round-15/40 纪律）

- **机制**：`KimiConversation.displayMessages` 每次调用做 O(窗口)
  `messages + [live]` 拼接（ConversationTimeline.swift:221）+ O(尾距)
  lastIndex/last 扫描 + live 去重字符串比较。产品每个流式更新周期
  ≥2-3 处调用（只读调查 AgentWorkbench 调用点：KimiWorkspaceView:125
  summary + :456 transcript + KimiConnection:804 per-update +
  FindBar/Model 条件路径——零改动，红线区仅读取）。
- **round-38 双层封死论证的逐点重检**：
  1. 「非 mutating getter=public API 红线」——修订计数 box 方案**不改
     getter 签名**：memo 状态存于 struct 内 `private let` 引用 box，
     读写经 box 内部锁，struct 本体不变 ⇒ 不触红线。
  2. 「共享 box 破坏拷贝语义」——采用**只过失效**设计：box 仅存
     (revision: UInt64, cached: [KimiMessage]?)；五个 mutating 入口
     （init/reconcile/prepend×2/apply）bump revision；getter 验证
     `box.revision == cachedRevision` 才命中。共享 box 的副本间任何
     变更至多导致其他副本**多算一次**（过度失效），**永不返回陈旧
     值** ⇒ 值语义（同输入同输出）严格保持。round-38 档案未逐点
     驳倒此变体（其驳倒对象为 eager 维护与无修订号的惰性 box）。
  3. 「eager 缓存令 paging 每 prepend 多付一次拼接（older_page
     −2~3% 反向）」——惰性方案 prepend 只 bump（O(1)），下次 getter
     调用才算 ⇒ paging 每 prepend 仍恰一次拼接，零回归路径。
  4. 「box-lazy 单调用方形态零收益」——产品流式形态为**多调用方**
     （上述 ≥2-3 处/更新），bench 两次调用忠实镜像；单调用方形态
     收益为零但成本亦近零（一次 revision 比较）。
- **上界估算**（既有 A/B stage 中位，无需新探针）：Linux v3 批
  commentary 链 display_workspace+display_timeline ≈ 0.61ms/1.68ms

## 设计转折（实现期，pin 先行击杀了初版设计）

初版按「修订计数」实现：共享 box 存 (revision, cached)，mutator bump，
getter 锁内比对。**差分 pin 当场击杀**：分叉副本（`var branch = memo;
branch.apply(delta)`）与原副本共享同一 box 且修订号相同——先读者以
自己的字段填缓存，后读者同修订号命中**别人的数组**（陈旧值）。
round-38「共享 box 破坏拷贝语义」的顾虑对修订计数形态**成立**，
粗筛论证中「只过失效」推断被证伪：bump 使旧缓存失效没错，但**重填
的缓存对共享同一 box 的其他字段态副本即为陈旧**——失效是 box 全局
的，正确性却要求按副本成立。

**修复=box-per-lineage**：mutator 不 bump，而是**替换** box
（`displayMemo = DisplayMemoBox()`——mutating func 内的普通字段重赋值，
getter 签名与 public API 零改动）。不变量：**共享同一 box ⟺ 字段从未
分叉**（结构体拷贝共享 box；任何相关变更即分叉出新 box）⇒ 缓存恒为
「持有该 box 的每一个副本的字段」的纯函数值，陈旧在构造上不可能；
未变更副本继续共享暖 box（bench/产品的多调用方形态恰是收益来源）。
reconcile 的 `self = KimiConversation(...)` 天然换箱。box 生命周期=
值谱系，旧 box 随副本消亡（有界=每 box 一个数组；五点论证以「谱系
同一性」替代「修订单调性」）。锁：NSLock，compute 在锁外（只读调用
副本的不可变字段，不重入 box）；并发首存者胜（同纯函数值相等）。

## 钉死（checkDisplayMessagesMemo，注册于 checkCommentaryDerivation 后）

- **重放式冷 oracle（v2，电池倒逼的设计升级）**：每步把全部操作日志
  重放进一个**全新** conversation（新 box 必然冷=现算，对任何 mutant
  免疫），memo 侧读两次（冷+暖）逐位对照。v1 的「持久孪生」设计被
  电池 m2 暴露**对称陈旧盲区**：换箱移除类 mutant 让孪生自己的 box
  同样陈旧，两侧同错⇒比较失明（m1 仅靠并发腿的跨线程缓存污染旁证
  击杀）——方法学入册：**差分 oracle 必须对被测机制的失效模式免疫，
  「每步只读一次=冷」的前提本身依赖被测代码正确时即为循环论证**。
- 23 个重放差分步：12×assistant.delta、4×thinking.delta、
  tool.progress、**非变更 apply**（坏 offset 拒绝、子代理忽略——
  memo 不得换箱且值必须正确）、prepend。
- **副本分叉**：branch.apply 后原副本仍返回原数组（暖缓存不被污染
  ——正是击杀修订计数版的断言）；branch 与重放冷算相等。
- **reconcile 换箱**、**dedup（live 文本==末条 assistant 文本）与
  nil-live 形态**、**4 线程共享 box 并发变更**（每线程对私有重放
  oracle 逐位核对；160 次跨线程换箱后，未变更的原副本仍与冷算相等）。
- **反盲**：每谱系冷/暖两路径都必须执行（hits≥1 且 misses≥1——
  「永不缓存」mutant hits=0 死；「恒供缓存」mutant misses=0 死且
  重放比对发散）。box 按谱系换代，计数器语义=当前谱系生命周期。
- 既有 112 PASS 全绿（含 round-41 690 观察与全部 golden digest）。
