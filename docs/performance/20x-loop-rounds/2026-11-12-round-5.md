# Round 5：编辑统计的 contiguous UTF-8 扫描（2026-11-12）

产品基线 `c51ef15`（#324 已合并）；本地报告接续在 `26b121a`，其产品源码与基线逐字一致。
Mac 测量树以干净 `c51ef15` 构建基线，再应用本候选。

## 归因与单一假设

Mac Time Profiler 的一次 activity bench 采样（全部测试进程线程，不只 Main Thread）：
SessionEditStats 派生 inclusive 145ms，其中 lines 61ms、lineCount 46ms；UTF8View
subscript/getter 与 formIndex/index 推进为主要 leaf。计入 fixture 构造的总样本为 331ms，
不能把其全部归为 stats，也不将 inclusive 栈相加。[采样摘要](round-5/profile.json)。

假设：在可获得 contiguous 存储的原生字符串上，按整数 byte offset 扫描可省去逐字节
String.Index 的构造/验证。只有真实 LF 分隔点才需要转为 String.Index。

## 产品修改（WorkbenchCore 24 行净变化）

- `SessionEditStats.lines`：在 `utf8.withContiguousStorageIfAvailable` 内按 byte offset
  找 LF，仅当 LF 前不是 CR 才分隔；在分隔点构造下标，返回引用原字符串的 Substring。
- `lineCount`：同一 contiguous byte 规则计数，空字符串仍为 1，末尾 LF 仍计一行。
- 存储非 contiguous 时，两者都保留原来的 UTF8View 路径。
- 不新增缓存或永久复制，不让 borrowed pointer 离开闭包。lineDiff/patchStat 的
  字符串比较与补丁 marker 判断完全不改；canonical equivalence 仍交给 Swift。
- `Sources/AgentWorkbench` 零差异，没有 UI、连接、权限、用户数据或真实 agent 修改。

## 等价性

新增 `checkEditLineScans`，使用冻结的 Character-level
`split(separator: "\n", omittingEmptySubsequences: false)` 和旧 diff/patch 算法作为预言机。
验证 Edit、Write、普通 patch、Codex add/delete changes：

- nil/empty 的所有方向（包括历史上 empty/empty 的非零删除计数，不趁优化修正语义）；
- LF、CRLF、混合 CR/LF、尾部与空行；Unicode paragraph separators 不当成 LF；
- 中文、补充平面、NFC/NFD、旗帜、ZWJ、Prepend 与 combining marker；
- 公共前缀/后缀相消，原内容与 canonical-normalized 内容的对照；
- 长文本与固定种子的 500 段混合语料，约 5,000 种输入组合。

既有 SessionEditStats、presentation paging 的跨轮/增量 oracle 也全部通过。
新测试不声称强制覆盖 foreign/non-contiguous 内部存储分支；该分支逐字保留旧路径。

## 结论

**已采纳并合并（#325，0711150）**：编辑统计模型派生在 Mac 上 2.05x，其他模型基准
无可靠回归。它不等于整个应用 2.05x，也不声称解决 round 4 的界面切换大头或已实现 20x。

下一轮先剖析候选残余。原采样已有 `path.contains("://")` 的 Foundation 搜索成本；
可考虑在未知/只读 tool 上先分类再处理路径，保持所有已识别 edit tool 的路径拒绝规则，
不要未经预言机验证把 Unicode 字符串包含规则改成裸字节匹配。
