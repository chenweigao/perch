# Round 1：冷投影空白规范化（2026-11-12）

基线：c302a43（origin/main，含 #320）。循环分支 perf/20x-loop-20261112。

## 场景与归因

大会话首访投影（`WORKBENCH_BENCH=1`）：2,333 条消息 cold median 84.4ms，
按消息数线性，16k 条外推 ≈580ms——模型层唯一确认有大余量的场景
（见基线报告"判断"节）。

`perf record --call-graph dwarf` 平坦剖面（本机，bench 1）：

| 符号 | 占比 |
| --- | --- |
| `_swift_stdlib_getBinaryProperties`（Unicode 属性查表） | 18.1% |
| `swift_retain` / `swift_release` | 16.7% |
| `IndexingIterator.next` | 5.1% |
| UTF16View 下标/推进 | ~7.7% |
| grapheme stride / UTF16 解析 | ~3.9% |

调用图全部汇聚到 `ConversationTurnSummary.make → excerpt →`
`split(whereSeparator: \.isWhitespace)`：每个摘要对 ≤320 字符的文本做
Character 级走查，每个 Character 一次 `isWhitespace`（Unicode 二进制属性）。
~1,167 轮 × 2 个 excerpt × ~320 次 = 每冷投影 ~75 万次属性查表。
同一 idiom 还在 ActivityNarrative、ConversationThinkingSummary 出现。

## 修改（单一假设）

`String.collapsedWhitespace`：与
`split(whereSeparator: \.isWhitespace).joined(separator: " ")` 逐字等价的
字节级实现——ASCII 空白 run 折叠为单空格并修剪两端；无法证明等价时回退
原 Character 路径：

1. 出现非 ASCII 的 Unicode White_Space 标量（U+0085/00A0/1680/2000–200A/
   2028/2029/202F/205F/3000，精确集合）；
2. 空白 run 之后紧跟可向后融合的标量（GB9 ×Extend、×ZWJ，GB9a
   ×SpacingMark）——融合 cluster 的 `isWhitespace` 是 stdlib 规则，
   字节路径不猜；
3. 意外 UTF-8（String 上不可能，防御性）。

替换 4 个调用点（ConversationProjection 的 excerpt ×2、ActivityNarrative、
ConversationThinkingSummary）。SessionDirectorySearch 的 terms 拆分语义
不同（保留 term 数组），不动。

**等价性检查捕获的真实差异**：`Character(" \u{200D}")`（空格+ZWJ 融合
cluster）的 `isWhitespace` 为 **true**，而 ZWJ 的 `isGraphemeExtend` 为
false（其 GCB 类是 ZWJ，不属于 Extend 属性）——首版回退判定漏掉 ZWJ，
被新增检查 `checkCollapsedWhitespace` 的对抗用例当场抓住；按标量值显式
判 ZWJ 后全部通过。检查覆盖：NBSP、U+3000、U+2000 系、U+0301/U+0903
紧跟空格、CRLF、emoji ZWJ 序列、变体选择符、3,000 段混合语料，全部与
原实现逐字对比。

## 结论

**采纳**。冷投影 -36.7%（三个规模一致，远超 2% 噪声带），其余场景无回归，
等价性检查 + 全套 + portable 全绿。距该场景 20x 目标（580→29ms）仍有
~12.6x 余量，后续轮次按 INDEX 队列继续（excerpt 的 grapheme 计数残留、
冷投影剩余机制成本）。


## 修订 r2：Codex 评审 P2 —— Prepend 前向吸收（已修复）

评审发现（discussion r4547820890，成立）：GB9b 中 Prepend 类标量
（U+0600 系、U+0D4E、U+110BD 等）会把紧随其后的空格**前向吸收**进自己的
Character，该 cluster 非空白；首版快路径把这类空格当独立空白 run 处理，
与 Character 语义分歧。首版只防了空白**后**跟 Extend/ZWJ/SpacingMark 的
向后融合，漏了空白**前**是 Prepend 的向前吸收。

修复：走查时跟踪前一个已复制标量（ASCII 记 0），空白 run 起点若为钉死的
Prepend 集合成员即回退 strict 路径（集合内多出的 3 个成员在当前 Unicode
版本非 Prepend，属保守方向的过度回退）。新增**穷举一致性检查**：遍历全部
标量（跳过代理区），以 stdlib 自身的 cluster 行为为预言机
（`String(scalar)+" "` 的 Character 数 ==1 即融合），逐一验证快路径逐字
等价——本机工具链测得 27 个融合标量全部命中；Unicode 数据随工具链升级
变化时该检查会点名失败标量，而不是静默分歧。

r2 后 A/B 复核（交替 5 轮中位数）：cold@2,333 条 84.70→53.78ms
（**-36.5%**）、cold@1,167 条 42.39→26.82ms（**-36.7%**）；chain_total
+0.7%、older_page -2.5%（噪声内）。修复零性能代价。
WorkbenchChecks 86 PASS + 1 SKIP、portable 10/10。
