# 任务配置、行动中心与代码反馈

本轮基于主线 8815c9c 整合已有行动中心，并打通文件审阅到任务草稿。

## 使用

- 新建任务先选环境和项目目录，再输入任务。输入框底部的 Agent 按钮打开模型与权限配置；有模型目录时使用选择器，否则仅保留一个模型文本输入。
- 工作台显示新进展；待处理详情可直接审批或回答，并在请求确实消失后进入下一项。确认看过变化、标记结果已查看和批准工具执行是独立操作。
- 文件面板与会话之间的分隔条可拖动，宽度保存在本机；面板右上角可切换全宽审阅。较窄窗口自动使用全宽审阅，关闭面板即可返回会话。
- 在文件或 Git diff 中选中代码，点击“反馈选中代码…”，确认引用内容并填写反馈，再“加入草稿”。现有草稿会保留，不会自动发送。回到输入框检查后，使用原有发送/排队机制。
- “引用文件”只向草稿添加当前读取文件的路径和版本信息，不自动上传本机文件。
- 引用包含执行环境、绝对路径、选区行号和所读取内容的 SHA-256。diff 分开标明旧行与新行，删除行不冒充当前文件行号。指纹标识读到的内容，不代表当前 Git HEAD；后续文件变化不会篡改已经打开的反馈内容。

## 边界

当前审阅仍是只读的未暂存/已暂存 diff；没有暂存、提交、回滚或远端写入。文件引用是可检查的草稿文本，不是原生附件上传。没有加入分支对比、`@` 文件补全或自动发送。

行动中心的外部模型归组保留原有显式生成、预览、选择、撤销流程。真实模型归组准确率和跨设备审批仍需单独验收。

## 验收入口

- `scripts/build.sh`、`WorkbenchChecks`、`ConnectionChecks` 与本地化覆盖。
- `scripts/run-native-acceptance.py --mode workspace`：确认连续处理、独立查看状态与任务组成果。
- `scripts/run-native-acceptance.py --mode review`：使用临时本机 Git 仓库及内存 Agent，检查文件/diff 读取、保留原草稿、不自动发送及拒绝错误任务目标。
- 两个场景均纳入 `scripts/check-functional.py macos`，不连接真实 SSH 或模型。
- 手工界面验收：新任务配置弹层、拖动面板、全宽往返、选择增删行后反馈、草稿核对。
