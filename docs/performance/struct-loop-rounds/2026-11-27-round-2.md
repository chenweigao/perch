## 懒物化正确性契约（钉死版，候选阶段验收依据）

走查坐标均在本轮 base 源码核验。数据源判定是契约的核心：凡消费**源消息**
的表面天然独立于投影物化；凡消费**投影行/几何**的表面须估高占位 +
物化修正不移动视口。

1. **阅读锚点**：锚点=entry id + 行内偏移（ConversationTranscriptView.swift:706–709
   `readingAnchor` → `geometry.readingRow(at:)` → `contents[row].entry.id`）。
   契约：物化修正（估高→实测）不得移动已锚定视口（scroll anchoring）；
   entry id 跨物化稳定。既有 acceptance 钉：InputAcceptance.swift:45–77
   （anchor.entry 相等）、NativeAcceptance.swift:2029+/2092/2151–2165
   （页锚/顶锚恢复）。候选新增钉：未物化前缀滚动进入→物化→锚点 entry 不变、
   视口偏移容差内。
2. **查找**：`ConversationSearch.hits(in messages: [KimiMessage], …)`
   （ConversationSearch.swift:143）扫**源消息**，缓存键=消息内容
   （ConversationEntryCache），与投影行无关→查找语义天然不缩到已物化子集。
   契约：hit 集与 eager 逐值一致（既有钉死不改即过）；reveal 路径
   （ConversationTranscriptView.swift:716 `PerchRevealConversationHit` →
   `reveal(target)`）须触发目标 turn 有界物化。候选新增钉：冷首访未物化
   状态下查找命中前缀 turn → reveal 物化 → 锚点落在命中行。
3. **导航摘要**：`Snapshot.navigation: [ConversationTurnSummary]`
   （ConversationPresentation.swift:400）逐 turn 建于 ConversationProjection.swift:234
   `ConversationTurnSummary.make(group, entries: timeline)`（turns 相位内，
   归因未单列份额）；消费=跳转列表 ConversationScrollControls.swift:308 +
   sizing host ConversationTranscriptView.swift:393。契约：跳转列表覆盖
   **全部** turn，数量/顺序与 eager 相等。设计决策待导航成本分离探针：
   若 summary 提取远轻于行投影→保持 eager（契约平凡满足）；否则懒建 +
   稳定占位（跳转触发物化）。
4. **折叠**：②已合并 split（FoldParents base+overlay，subscript O(1)，
   60420b1a）为前置基础设施。契约：foldParents 对任意已物化子集正确
   （既有 checkFoldParentsSplit 19 步差分不改即过）；折叠态变化不得强制
   全量物化。候选新增钉：未物化前缀的折叠键查询走 base（flat memo）。
5. **滚动高度**：`ConversationRowGeometry(heights:)`
   （ConversationRowGeometry.swift:10–19）纯值类型 heights→offsets+totalHeight，
   二分查找；document view totalHeight 驱动滚动条/锚点恢复
   （ConversationTranscriptView.swift:544/637/1281）。契约：未物化行估高
   单调/稳定到滚动条与锚点恢复可用；估高→实测修正的总高跳变容差钉进
   acceptance 夹具。估高来源候选阶段定（按 presentation 类型常数 vs
   已测行运行均值），容差以 acceptance 实测钉死。

## 架构接缝（走查结论）

- **eager 在模型层**：update() 的 turns 相位对全部历史 turn 建行投影
  （归因 83.8%@16k）；视图层已有 ±12 host 保留（geometry.retainedRows），
  但 contents/geometry 仍来自全量投影行。
- **懒边界**：HistoryTurn 壳（entry id + presentation 类型 + navigation）
  先行，行投影按需；`Snapshot.rows`/`presented` 的拼接序列保持索引稳定
  （占位行携带 entry id 与估高），geometry 由实测+估高混合 heights 构建。
- **配套（10x+ 必需，归因地板）**：tools 全窗 O(n) 扫描（6.76ms@16k）→
  懒/增量/按需（影响历史 tool 解析，需设计评审）；retained messageCosts
  全窗值比较（3.22ms@16k）→大会话既结构性不入缓存，成本会计可延迟/上界化
  （cheap bound 替代精确 cost，retain 守卫语义不变）。仅 turns 懒 ≈6×
  （10ms 地板），配套后理论场景级 20–60×。
- narrative/rows 相位已尾窗受限（<0.2%），无需动。

- **全 per-turn 懒物化**：HistoryTurn 壳=chunk 引用 + entry id 序列；

- 外观零变化：占位行估高容差钉死；跳转文本展开后逐值等于 eager。

### 消费点走查结论：一个 BLOCKING 级隐式求值点

`ConversationTurnNavigation.Snapshot` 是 `Equatable`，`update(session:turns:current:)`
每次 viewport refresh 都执行 `snapshot != next`（ConversationScrollControls.swift:318–326），
而 refresh 由滚动/布局触发（ConversationTranscriptView.swift:2380–2392 →
`updateNavigator()` :851）。候选原 `==` 只比值 → **冷投影后第一次 refresh 就把
全窗 8000 条摘要一次性物化**，34ms 从冷首访搬到首次滚动，正是红线禁止的成本搬迁。

修复（`c1683289`）：`ConversationTurnSummary.==` 增加 `lhs === rhs` 反射短路；
不同实例仍按值比较（Equatable 语义不变，反射性本就要求 x==x）。

其余消费点核验安全：`ConversationContentIdentity.==` 用 `snapshot ===`（不触摘要）；
`ConversationDocumentView.configure` 已改实例 identity（候选自带）；turn rail 只画
刻度，hover 预览与 `accessibilityValue` 各读 1 条；bookmarks 菜单只读 `.id` 过滤、
仅已收藏项读 `.prompt`；`Snapshot`/`History`/`HistoryTurn` 均非 Equatable，无合成
相等陷阱。线程：`update()` 只在 SwiftUI body（主线程）调用，transcript 内所有
dispatch 均 `DispatchQueue.main`；包语言模式 v5，该类未跨并发域传递。引用语义：
Chunk 复用条件是 `sameWindow` 值比较（ToolVisibilityProjection.swift:230），故同 ID
历史编辑产生新 Chunk → 新 HistoryTurn → 新 summary 实例；language/epoch 变更走
`discardPrefix()`；identity 检测不会掩盖内容变化。闭包驻留：只捕获该 turn 的
messages（与其 Chunk 共享缓冲）+ 1 条 user 消息，物化后 `deferred = nil` 释放，
无 self 捕获、无循环引用。

### 方法学教训（新增，入册候选）

**Swift `Array ==` 只在两侧共享同一 buffer 时跳过元素比较。**第一版反射 pin 用
`first == second`（同一 Snapshot 的同一数组）→ 变异体"仅值相等"存活。pin 必须
构造**不同 buffer 持有相同实例**的数组（`flatMap { [$0] }` / delta 后新旧 navigation
对比），才真实覆盖 viewport refresh 的比较形状。

不构成单帧卡顿。**勘误 4 仍然成立**：34ms 若真被一次性触发≈两帧，"低于 100ms
所以无感"不是验收依据；本轮的验收依据是"无一次性触发面 + 单条 12µs"。

**口径披露**：`max_rss_mb` 取自 `/usr/bin/time -l`，是整进程峰值（两档同值，非分档）；
`all_read`/`reread` 都含 harness 的 `String.count` 地板（≈11.8ms@16k），故延期成本按
`all_read − reread` 计；`footprint_*` 是内核 `phys_footprint`，非 source/raster 估算；
物化前后 footprint 差小于该指标分辨率（两位小数同值），据此只能说"未测得驻留上升"，
不能说"闭包零成本"。base cold 67.48ms vs round-2 基线 63.73ms（+5.9%）属跨 job
二进制布局变异家族，不与历史值混合统计，结论只用同 job 内配对差。

**Linux release 筛选（3 对，仅方向性）**：16k cold 421.9/427.1/418.4 → 288.2/282.5/…
（约 −32%），2k 48.8 → 32.0（−34%），两侧 checksum 逐对相同。Linux 收益小于 Mac，
与 nav-split 的平台主导相位翻转一致（Linux timeline 57.8% 主导，summary 32.7%）。

### 结论

shard A 在 16k 冷首访模型层拿到 **2.11×（−52.86%）**，2k 档 2.60×；延期成本已定量
（全量 34.03ms，单条 12µs，无一次性触发面），内存未上升（footprint −3.4%，进程峰值
−1.9%），流式 delta 与分页无回归，行为差分/字节 oracle/变异电池全绿。
**这不是 10x+**：仅省 turns 相位里的 summary 份额，tools 6.76ms + retained 3.22ms
+ timeline/rows 仍在冷路径 → 剩余地板约 32ms。10x+ 需 shard B（timeline+rows 懒）
与 tools/retained 配套，理论 ~10.5ms（6×）→ 配套后 ~1–2ms（30–60×，仍是估计，
勘误 5 适用）。
