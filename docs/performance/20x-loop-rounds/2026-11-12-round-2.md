# Round 2：文本可见性判空（2026-11-12）——不采纳

不等每日调度，本轮由用户要求立即续跑。基线 `3b679fb`（round 1 已合并）；
候选仅改 WorkbenchCore，不改 `Sources/AgentWorkbench`。

## 假设与候选

Linux 的 cold 剖析（perf/cycles，含 fixture 构造）中，Foundation 的
`trimmingCharacters → NSString.substring → UTF16 解码/复制` 累计 46.4%。
`ConversationTimelineEntry.make.visible` 只是检查 trim 后是否为空，却反复生成整段副本。
候选用 `unicodeScalars.contains { !CharacterSet.whitespacesAndNewlines.contains($0) }`
替代该布尔判断，普通文本首个非空白标量即可返回。空白集合不改成 Character.isWhitespace。

## 等价性和构建检查

- 与 Foundation 原实现逐个对照全部有效 Unicode 标量。
- 组合空白/mark、ZWJ、Prepend、CRLF、补充平面、长文本等对照；timeline 的
  thinking/final-answer 状态及原始文本保持完全一致。
- Linux release WorkbenchChecks 87 PASS + 1 SKIP；portable 10/10。
- Mac mini release WorkbenchChecks 88 PASS（包含数学检查），Swift 6.4，macOS 27.0.1。
- 未提交产品候选，未运行本候选的 app build/GUI 验收或 CI，也未开产品 PR。

## A/B 与结论

同机同工具链基线/候选各五次；轮间交替 AB、BA，避免固定先后顺序偏差。

**不采纳**：Linux 收益可靠，但目标产品是原生 macOS。Mac 同路径没有超出噪声的收益，
不能以 Linux Foundation 的额外转换开销冒充产品提升。已撤回代码与候选测试，
保留 [候选补丁](round-2/rejected.patch)、[Linux 各轮数据](round-2/linux.json) 和
[macOS 各轮数据](round-2/macos.json)。各机绝对值不可互比。

## 循环规则修正

以 Linux 做便宜的归因/等价性筛选；任何宣称产品性能提升的候选必须在 Mac
同机 A/B 复核并超过该机本轮实测噪声。不能沿用 Linux 的 2% 作为 Mac 噪声门槛。
round 1 的 -36.5% 也只是 Linux 数字，不据此宣称 macOS 全应用倍率。
