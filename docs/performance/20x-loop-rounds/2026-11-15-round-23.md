## 机制探针（Linux / Swift 6.3.3 / swiftc -O；200k 次比较 × 7 轮取最佳）

| 比较形态 | 耗时/200k | 每次 |
| --- | --- | --- |
| ASCII 同 base 相同（identity） | 0.059ms | ~0.3ns |
| CJK 同 base 相同（identity） | 0.054ms | ~0.3ns |
| **CJK 跨 base 字节相同** | 2.965ms | **~15ns** |
| **CJK 规范等价、字节不同** | 61.757ms | **~309ns** |
| CJK 不同行（快速 false） | 0.071ms | ~0.4ns |

机制事实：`Substring ==` 存在字节快速路径（跨 base 字节相同 ~15ns，
仍含分发开销），规范等价但字节不同时走完整 grapheme 比较（~309ns，
20 倍）。候选的收益面：① 消除两侧 `[Substring]` 全量物化（每行
UTF8View index 运算 + Substring 构造 + 基串 ARC retain + 数组增长）；
② 字节相同行的 ~15ns 分发比较降为裸内存比较（~45B 行约 1-2ns）。
Mac 侧计时探针未做（mini 上裸 swiftc SIGKILL——WORKSPACE-DESIGN.md:166；
解释模式计时无意义）——Mac 机制量级由上下文内粗筛/正式测量直接裁决。
探针脚本与输出归档 `.local/round23/substr-eq-probe{.swift,-linux.txt}`
（复跑数值稳定：61.719/61.757ms 等）。

## 改动（v1=3ba1f1a；单文件 `SessionEditStats.swift` + 新钉死文件）

`fullLineDiff` 连续存储路径：`lineRanges(in:)` 以与 `lines(_:)` 连续
路径**完全相同的分隔谓词**（LF 且前驱非 CR）产出整数 `Range<Int>`
数组；前后缀扫描用 `lineRangesEqual` 比较——长度相等时裸字节逐一
比较（UnsafeBufferPointer 直接下标，无迭代器 witness——round-21
stdlib 陷阱规避），字节全同 ⇒ **确认相等**（规范等价自反性：字节
相同即同一字符串）；长度或字节不同 ⇒ **不可判定**，物化与 `lines(_:)`
完全相同的两个 Substring 走原规范 `==` 裁决。扫描停止位置与数组合并
逐输入一致 ⇒ tally 不变。外部/非连续存储保留原数组走法**逐字不动**；
`lineDiff` 路由（nil/空早退、≤1024 小输入、探针快路径）零改动。

预期回归面（如实预告）：edit512_canonical 场景每行都字节不同 ⇒ 每行
多付一次失败的字节比较后再走规范回落——该指标预期轻微变慢，粗筛/
正式数据单独披露。
