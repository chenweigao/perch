## Round-32 候选设计：跨实例前缀（Earlier）缓存

**假设**：hits() 的前缀路径（最近一条 user prompt 之前的全部轮次）命中共享的
窗口级已验证节点后，reopen 只付一次窗口验证 + hits/entries 收养拷贝，跳过时间线
合成、逐 entry 查表/验证/收养、实例字典构建与其析构。

**设计论证（"不得全局 memo"门五点，round-27/30 同构）**：
1. **纯度**：复用谓词 = round-12 Earlier 的同一契约——sameQueryKey（查询字节精确）+
   options 相等 + sameSearchableWindow(prefix, stored.prefix)（bitwise 存储同一 ∨ 值
   相等+渲染字节相同）；命中返回的 hits/entries 与重建结果逐字节同值（round-12 已在
   实例内钉死该等价，跨实例仅改变存储位置）。收养语义沿 round-12/30：命中后实例
   earlier.source 收养调用方 prefix 副本。
2. **键**：query UTF-8 字节 + options 位（长度前缀单射编码，round-30 v2 模式）；
   前缀身份**不进键**而由验证谓词把关（与 round-12/30 一致——窗口是运行时值，键只
   编码查询意图）。
3. **有界且留存全计**：节点保留 prefix messages（验证材料）+ prefix hits + entries
   字典（含各 entry 的 sources/text/sourceEnds/hits——text 为 NSString 共享引用，
   与 entry 缓存可能双重计数=**保守超估**，如实披露）；成本=round-30 v5 公式的
   前缀级扩展（消息元数据+JSONValue 递归+sources+text×2+摘录+entries 结构）；
   默认预算上调（16k 窗口单节点 ~15-25MB，64→128MiB 量级，A/B 后定）；批量 LRU
   + 超大拒绝 + round-29 F9 诚实 churn 注记。**切片留存边界（评审 replay 实测，
   并入设计）**：共享前缀节点必须物化独立 `Array(prefix)`——replay 显示 prefix
   切片存储时 `suffix_retained=true`（切片保留整个后备存储，含 live-turn 尾部，
   直至切片丢弃才释放），直接存切片会把尾部消息生命周期跨搜索延长且被成本模型
   低估；布局锚点：KimiMessage 实测 73B/stride 80，16k 消息前缀结构字节
   ≈1.29MB（内容另计）。
4. **locale 世代**：hits/摘录内嵌 locale 敏感结果——通知世代失效 + **构建窗口世代
   守卫**（round-30 v2 契约直接复用）。
5. **线程安全**：单锁；验证与重建在锁外；并发双建良性、记账单份（插入减旧）。

**集成点**（ConversationSearch.hits() 前缀分支）：实例 earlier 命中（round-12）→
不变；miss → 共享前缀查询（验证+收养，**不构建时间线**）；再 miss → 现有逐 entry
路径（round-30 entry 缓存生效）→ 建 earlier → store 共享（世代守卫+成本走查）。
**流式语义保全**：同实例后续更新走实例 earlier（不触共享层）；轮边界（prefix 变化）
共享 miss 后由**收养的 entries 字典**提供 previous（与今日实例内行为同构，无 turn-
boundary 回归）；bench 保真：query_update/cold 注入新 PrefixCache（跨实例零复用），
reopen 用默认共享=产品形态。

**尺寸预估**（以本轮归因份额为上界依据，非承诺）：reopen 15.69ms 中可绕过
~85-90% ⇒ **预期 ~2-3ms（-80% 量级）**；剩余=窗口验证（bench 同数组存储 bitwise
层 O(1)；重建窗口值层 ~3MB 比较）+ hits 数组拷贝 + 尾部轮处理。cold：+store 成本
走查（每窗口-查询一次，~1-3ms ⇒ <+0.5%，如实计入权衡）；query_update：轮内零变化
（实例 earlier 路径不变）。配对指标承载：reopen/cold 均配对（round-29 起），可分离性
充分（预期幅度 ≫ spread 2.6-6%）。

**钉死计划**（round-27/30 模式全移植）：机制（键单射含 NUL/重排对+字典级检索拒绝、
精确成本公式手算断言、budget-0 oracle、具体 LRU、超大拒绝、世代守卫竞态、并发单份）
+ e2e（四制度规范+字节级全等、跨实例 staleness 矩阵【前缀编辑/查询变更/options 变更/
轮边界推进】vs budget-0 oracle、running 隔离）+ 变异电池（skip-verification/
canonical-key/stale-earlier-adoption/zero-accounting/reverse-lru/no-generation 等）。

**风险与门槛**：entries 字典跨实例共享的生命周期（Entry 为值类型、NSString 不可变
——预期安全，评审重点）；双缓存并存的双重计数保守性；128MiB 级预算的内存披露；
prefix 节点与 entry 节点的一致性（同世代失效）。

1. **r31-attr 首跑（作废）**：同名 job 发货竞态——runner 在修复发货前消费了首版

   行）排除 checks 套件误录。首跑 XML 保留为温形态伪影，**不作 cold 归因用**。
2. **r31b（计时有效、导出失败）**：sed 改编遗漏无斜杠的 `mkdir -p .local/round31`
   ⇒ round31b 目录未建 ⇒ record 未写 trace ⇒ export 报 "File does not exist"，
   `set -e` 在**还原段之前**中止作业 ⇒ mini 工作树遗留 Tests/ 补丁（脏）。计时段
   有效：cold 615.2ms/9 迭代、reopen 15.86ms/293 迭代（形态确认）。
3. **r31c（构建失败）**：r31b 遗留脏树 + 再次打补丁 ⇒ benchR31Profile 重复声明
   ⇒ build exit 1（作业头部 porcelain_before=2 为证）。处置：远程 `git checkout --
   Tests/` 复位（porcelain=0 确认）。
4. **r31d（干净产出）**：job 加预清理段 + record 真实退出码捕获（不再被 `| tail`
   吞掉）+ export 容错 + 目录修正；porcelain_preclean=0/applied=2/after=0，
   record 双 exit 0、export 成功、计时 cold 605.4/reopen 15.69。
   教训入档：**PerfRunner 作业必须自防御脏树（预清理）、同名 job 不得在消费窗口内
   重发（换名重发）、管道后的 $? 不是目标命令退出码**。
