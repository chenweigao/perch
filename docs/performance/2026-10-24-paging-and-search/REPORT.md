# 长会话的分页、查找与全量历史读取（2026-10-24）

[流式投影修复](../2026-10-23-streaming-projection/REPORT.md)之后，按同一类问题——高频事件
在主线程上对整个已加载窗口重算——继续排查。真机报告中，`snapshot_projection` 的明细
显示已加载窗口每隔几秒增加约 100 条（用户向上滚动逐页加载）；同一批卡顿里的未归因时间
与投影时间相当。

## 发现

1. **向上滚动加载一页仍是整窗重算**：前插一页使"最新提示之前"的历史改变，历史复用失效，
   工具可见性、分轮、行、折叠、payload 成本与活动栏编辑统计全部重算。其中 payload 成本按
   下标复用，前插后下标整体平移，16k 条消息的 JSON 成本全部重新计算。
2. **查找栏打开且有查询词时，每个流式 delta 都对整个窗口重新分轮、取文本并全文搜索。**
3. **`KimiPart.isRuntimeContext` 每次调用都 `trimmingCharacters` 复制整段文本**再做多次
   `hasPrefix`。`isUserPrompt` 与分轮投影的可见性判断对每个文本部件都调用它，长文本按长度付费。
4. **读取全部历史**（查找栏"搜索完整历史"、开启自动命名时的历史补全）每拉一页就发布一次，
   每页都触发上面的整窗更新，总成本约为 页数 × 窗口。
5. 原生会话每次应用快照都为整段消息建 ID 集合，只为清理可能不存在的失败回执。
6. 切换会话后 1.3–1.6 s 的卡顿没有任何探针覆盖，无法判断是否属于本应用代码。

## 修改

- **历史按轮分块复用**：历史改变时，`ToolVisibilityProjection` 把每一轮（提示到下一个提示，
  或窗口开头被截断的半轮）单独投影为 `Chunk`，消息、相关运行 ID、已记住的 live 工具和连接状态
  不变的轮直接复用；展示模型按块复用该轮的行、导航和折叠结果。分页只重建被页边界切开的那一轮
  和新页里的轮；新提示只投影上一轮。仅当拼接结果必然等于整体投影时才这样做：每个工具 ID 只
  出现在一轮且不出现在最新一轮、每个 live 工具锚定在已加载的轮、提示 ID 不重复；否则整体投影。
  历史折叠按轮决定，合并各轮缓存；若摘要叠加移除了某轮的提示行或条目 ID 重复，回退整段折叠。
- payload 成本按被前插页平移后的位置复用；编辑统计对前插页或新完成的一轮只累加增量。
- **查找**：`ConversationSearch` 以最新提示为界缓存之前各轮的命中，查询词、选项与历史不变时
  只搜索最新一轮。
- **`isRuntimeContext` 快速判断**：所有标记都以 `<`/`B` 开头或以 `>` 结尾；首尾非空白字符都不
  符合时直接返回 false（与原实现逐字等价），其余情况走原逻辑。`skillContextSplit` 同理。
- **全量历史读取每秒最多发布一次**：Kimi 用 `KimiHistoryBatch` 按逐页 `prepend` 的规则累积、
  一次性前插；原生端先拼接相邻页再前插。单页加载不变。
- 原生端仅在存在失败/未知回执时才建消息 ID 集合。
- 新增探针：`activity_derive`（活动栏派生）、`session_select`（工作台选择会话）、
  `catalog_refresh`（侧栏目录重建），见 [FRAME-DIAGNOSTICS](../FRAME-DIAGNOSTICS.md)。

## 结果

Linux x86_64，Swift 6.0.3 release，`WORKBENCH_BENCH=streaming`：16,142 条消息（与真机同量级），
另生成 5 轮更早的同形历史，按 100 条一页逐页前插（页边界会切开一轮、分开调用与结果）。
基线为 94483d8 加同一份基准文件。各 3 轮中位数：

| 场景 | 基线 94483d8 | 本修改 |
| --- | --- | --- |
| 向上加载一页（模型 + 折叠 + 活动栏） | 74.4–76.0 ms | 10.0–10.4 ms |
| 　工具可见性投影 | 25.7–26.9 ms | 3.4–4.0 ms |
| 　分轮 / 历史行 | 15.9–16.7 ms | 2.3–2.4 ms |
| 　payload 成本 | 8.5–8.7 ms | 1.7–1.9 ms |
| 　活动栏（编辑统计） | 12.4–12.9 ms | 1.3 ms |
| 　历史折叠 | 7.0–7.2 ms | 0.7–0.8 ms |
| 查找栏有查询词时每个 delta 的搜索 | 303.1–304.0 ms | 1.7 ms |
| 每个流式 delta（不含查找） | 3.91–3.96 ms | 3.67–3.74 ms |

流式一行的基线取自未插入查找阶段的同一基线二进制（插入后基线因缓存干扰为 4.6–5.5 ms）。
释放 16k 会话模型状态约 10–12 ms，两者相当。

## 验证

- `checkConversationPresentationPaging`（新增）：72 轮带各类边界的历史（用户角色的工具结果、
  运行时上下文、压缩摘要、无 ID 工具、未应答调用、跨轮迟到结果），90 步随机组合前插任意长度
  的页、流式 token、新提示、在线切换、早期轮的运行 ID、live 工具、语言切换；每步与完整重算
  比较行、导航、叙事、摘要批次、payload 成本、编辑统计、查找结果，并比较 3 种摘要叠加 × 折叠
  的 `presented`。20 次分页中 19 次复用了未变的轮（另一次因跨轮 ID 回退），新提示也复用。
- `KimiTests`：`KimiHistoryBatch` 与逐页 `prepend` 的消息顺序、去重、`hasOlder` 及下一页请求
  位置一致（含页内与页间重复、全部重复的页）。
- 变异：去掉跨轮 ID 判定、去掉 live 工具归属判定、块复用忽略运行 ID、编辑统计前插范围错一位，
  均被检查捕获；成本对齐偏一位只会退回逐条重算、结果不变，由基准数字体现。
- Linux WorkbenchChecks 71 PASS（除平台相关的 3 项跳过）；portable 套件、preview-sources、
  本地化覆盖、`git diff --check` 通过。

## 未验证

- AgentWorkbench 的连接（批量发布）、视图与工作台探针只能由 macOS CI 编译，`ConnectionChecks`
  也只在 macOS 上运行。
- 真机效果：需在 Mac 上重录诊断报告。基准不含 SwiftUI/AppKit 的行协调、锚点恢复与布局。
- 切换会话的长卡顿仍未定位；新探针用于下次报告区分本应用代码与框架布局。
