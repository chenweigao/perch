# 工作台管理：任务归组、待处理队列、恢复现场

2026-09-20 的产品决定：Kimi 原生对话作为主要工作界面，Herdr 终端保留独立交互；Mac 客户端统一工作组织。

## 使用顺序

1. 把一件需要推进的事情建成任务组，写下目标，关联 Kimi 对话、Herdr Agent 或 shell，可混合选择并搜索。
2. 从工作台总览先处理等待输入、待查看结果，再关注仍在运行的会话。
3. 单击侧栏会话立即切换；右键置顶常用会话，或进行分组和归档。顶部不再重复显示会话标签。
4. 结束这一轮工作时，在任务组写下下一步。打开的工作现场、置顶和所在任务自动保存在本地。
5. 下次打开后连接已配置的机器，按机器、来源与稳定会话 ID 接回打开的会话。缺失会话明确列出。

## 三层对象

- **任务组**：人在推进的事情，保存名称、目标、下一步和关联会话。允许跨机器，也允许一个会话属于多个组。
- **远端会话**：远端真实存在的 Kimi 对话、Agent 终端或 shell。Kimi Web 对话通过 API 接入，终端通过 Herdr 接入；图标区分来源。
- **工作现场**：打开过的会话在后台保持；关闭本地视图只断开本地 attach，不取消远端任务。置顶决定侧栏顺序，与后台是否打开分开。

任务组不会自动被判断为完成。不同 Agent 对状态的识别质量不同；终端队列以 Herdr 的上报为依据；Kimi 队列使用结构化会话状态。

## 队列语义

| Herdr 状态 | 工作台显示 | 操作 |
|---|---|---|
| blocked | 等你处理 | 打开会话处理权限、输入等事项 |
| done 且未查看当前 revision | 待查看结果 | 查看实际输出后，手动标为已查看 |
| working | 运行中 | 查看或继续等待 |
| done 且当前 revision 已查看 | 已查看结果 | 折叠保留，可再次打开 |
| idle / unknown / 普通终端 | 其他会话 | 折叠保留，不据此认定任务完成 |
| 未连接 / 正在重连 | 状态未同步 | 上次快照弱化显示，保留更新时间 |

“已查看”只记录本地查看状态，使用 host ID、terminal ID 与 Herdr revision 关联。
revision 有变化就重新显示待查看，因此内容刷新也可能使结果重新出现；不会把“已查看”变成永久忽略。
缺少 revision 时不提供标记，继续显示待查看。管理快照每 3 秒同步，短暂状态可能未被采样。

Kimi 对应语义：

| Kimi 状态 | 工作台显示 |
|---|---|
| pending_interaction=approval / question | 等你处理：等待确认 / 等待回答 |
| busy=true，无上述交互 | 运行中 |
| last_turn_reason=failed，且不在运行 | 等你处理：出错 |
| last_turn_reason=completed，当前 updated_at 未查看 | 待查看结果 |
| cancelled / 无完成原因 / 未知原因 / 已查看版本 | 其他会话，不当作成功完成 |

Kimi 的“已查看”只存本地 updated_at，不代替审批或回答；同一会话有新版本时重新进入待查看。
初次接入时，已有 completed 会话也会列为未查看，结果清单默认折叠。
全局队列按事项分类混排各个来源，并保留来源、机器和目录。离线数据不计入当前数量，单独折叠显示。
队列顺序固定为等你处理、待查看结果、运行中：需要人动手的排在只需等待的前面。
侧栏“待处理”只列等你处理，与侧栏计数一致；待查看结果留在工作台的结果分区。
每行显示来源、状态与目录末段，完整路径在悬停提示里；并显示最近更新时间，等你处理的行显示已等待多久。
时间来自各来源上报的更新时间，普通终端没有时间戳时不显示；远端时钟快于本机时按“刚刚”处理。
Kimi 列表接收状态事件时刷新，并每 30 秒补充同步；当前对话订阅实时事件。两条连接各自恢复，不相互重连或停止。

## 保存与恢复边界

- 保存在 `~/Library/Application Support/dev.agentworkbench.mac/workspace.json`。
- 保存混合任务组、打开的会话顺序、所选会话和任务组、置顶顺序、本机归档、各组最近会话及已查看版本。
- 单击即打开并保留工作现场；“关闭本地视图”可释放终端连接，远端进程继续运行。
- 侧栏是唯一的会话导航，连接恢复不会覆盖当前选择。任务组“继续上次会话”回到该组最近打开的未归档会话。
- 旧格式中没有 kind 的引用按 Herdr 终端读取，保留旧 ID、任务组、固定标签和已查看记录。
- Kimi 只保存会话引用；未发送草稿与待发附件仍只留在进程内。
- 恢复只接回同一个远端会话。未找到或未连接的引用保留在工作台的等待恢复区，可手动移除。
- 选中任务组进入该组的落地页：显示目标、下一步与“继续上次会话”，可搜索本组会话并提示尚未同步的关联；编辑仍在任务组编辑器里。工作台的等待恢复区与本地存储错误提示只在不选中任务组时出现。
- 本地工作台读取或保存失败时，工作台顶部显示可复制的提示；读取失败不覆盖原文件。
- 文件通过后台串行队列原子写入，正常退出时同步完成最终保存；读取异常明确显示错误，不覆盖原文件。
- 本地保存的名称和笔记没有同步到远端，没有自动向 Agent 发送任务。

## 后续按使用反馈推进

优先完善任务组归档、每个任务组的独立窗口布局、通知与事件订阅。
自动分派 Agent、汇总多 Agent 结果，以及把任务组的完成状态自动化，需在基本管理流程稳定后另行设计。

## 管理操作的边界

置顶与分组保存在本机，分组支持多选和移出。Kimi 归档同步到服务端，终端归档只整理本机列表，不结束进程；两者都可恢复。Kimi 永久删除和结束远端终端分别使用明确确认文案，执行成功后移除本地引用。运行中的 Kimi 不允许归档或删除，需先由用户完成或停止。

队列行的状态图标与侧栏同一套：运行中、等你处理、待查看、离线、已归档，其余按来源显示图标；行右侧的箭头表示单击即打开，不是另一个按钮。行的右键菜单与侧栏一致。

未配置过任何机器时，工作台给出「连接远程机器」和「检测本机 Agent」两条路径。首次运行内置连接的 UUID 单独持久化，保证会话引用和草稿跨启动可恢复，但不计为用户已配置机器列表，因此不会把首启状态遮住；本机执行环境目前只做安装检测，不承诺能在 Mac 上开始对话。

机器可在侧栏「环境」里移除：断开本机连接并从列表移除，远端 Agent 与终端继续运行，SSH 配置不变，保存的会话引用保留。至少保留一台机器。

移除非当前机器不改变当前终端的主机操作目标；移除当前机器时才切换到剩余机器。构建后运行 `python3 scripts/check-host-lifecycle.py`，通过隔离应用域验证跨进程的机器身份、会话与草稿恢复，以及移除非当前、当前和最后一台机器的行为；检查不启动 SSH。

旧版本打开的固定会话自动成为首次升级后的置顶项，原有任务组和工作现场继续保留。

## 原生 Agent 扩展

OMP 与 Qoder CN 使用各自 kind 的稳定会话引用，加入同一任务组、置顶、队列与恢复机制；聊天渲染共用时间线、Markdown、工具结果组件。进展、思考和工具按发生顺序展示；完成的工具保留摘要，参数和输出按需展开。思考与运行上下文单独折叠，无概要时保留过程文字，纯思考则默认展开记录。新建入口统一为 Agent + 当前/最近目录，自动聚焦输入，不要求先取名字。对话按更新时间混排。

审批/提问优先进入待处理，运行中单列；只有正常完成增加结果版本，停止与失败不作为完成。OMP/Qoder 的运行时与托管、历史边界见 [原生 Agent](NATIVE-AGENTS.md)。

## 工作台与待处理（2026-09-21）

工作台是继续工作的总览：先显示需要人操作的会话，再显示待查看结果、运行中和最近会话。
待处理是完整的行动清单，只含等待确认、回答和出错的在线会话，与侧栏计数使用同一套状态。
待查看结果不进入待处理，查看状态不代替远端审批。零待处理时仍保留入口，并提供返回工作台。

工作台最多预览 3 条待处理，并始终提供进入完整清单的入口；待查看和运行中各先显示 5 条，其余可展开。
最近会话按已有更新时间显示最多 6 条，不重复前三个区域，不包含归档或离线记录；查看全部进入会话目录。
无时间戳的终端排在有时间戳的会话之后，不推断最近活动。任务组页面从侧栏或会话右键菜单进入；工作台工具栏的任务组菜单只做筛选。

页面采用平面列表、细分隔线和两行信息；状态图标沿用侧栏。归档入口集中到工具栏更多菜单，候选条件不变，
执行结果与撤销、重试保留在页面中。待恢复与离线记录弱化放到底部；本地保存失败仍在顶部明确提示。

验收：`scripts/build.sh`、`WorkbenchChecks`、`ConnectionChecks`、`scripts/check-localization.py`。
`scripts/build-workbench-preview.sh` 构建生产组件的隔离预览，可检查日常、需要处理、零待处理、离线、首次使用和保存失败；不连接 SSH 或读取真实会话。

## 任务组页面（2026-09-21）

任务组是一个目标及其关联会话的落地页。目标与下一步始终有入口，未填写时点击引导打开编辑器；已有目标完整换行显示。
继续上次会话提供直达入口，不再重复渲染同一会话卡片。当前会话与工作台共用行样式，按待处理、待查看结果、运行中、其他、离线各显示一次。
任务组内的待处理同样只包含真正需要人操作的事项，结果单独展示。

侧栏数字仍表示全部关联。正文明确列出关联总数、当前数量和归档数量；归档关联折叠保留，可恢复，未知引用有独立提示与管理入口。
搜索同时匹配当前与归档会话，不改变目标、下一步、继续入口与关联总数。批量归档仍仅作用于搜索后的当前会话。
`scripts/build-task-group-preview.sh` 提供生产页面与编辑器的内存数据预览，覆盖空目标、已填写、空任务组与未同步，不加载真实工作区或连接远端。

## 工作台的任务组归属与筛选（2026-09-23）

工作台、待处理、侧栏与会话目录的每一行都说明自己属于哪个任务组。行内只写第一个组名，
多出来的收成「+N」，完整列表放在悬停提示里；不属于任何组的行不加占位文字，
因为早期大多数会话都没有归组，占位只会变成噪音。任务组自己的页面不重复显示组名。

组名只读不点：整行仍然是打开会话，跳转任务组走右键菜单，避免一行里出现两个点击区。
组名到会话的反向索引每次视图渲染构建一次并以值传给行，不在行内构建，
也不在行内观察工作区模型，理由与侧栏行一致。
队列已按某个任务组筛选时，行内不再重复该组名，只显示这个会话还属于的其他组。

工具栏的筛选控件按任务组和机器收窄工作台与待处理队列。两个条件相互独立并同时生效，
因为一个任务组可以跨机器；此前的实现里二者互斥，选了任务组就等于忽略机器。
选中后队列上方出现可清除的芯片，逐个取消；芯片整块是按钮，不在里面再放一个小叉。
筛选状态不写入 workspace.json：它是对当前情况的提问，恢复后会在启动第一屏藏起会话。

筛选后没有会话时，空状态说明是筛选造成的并提供清除，不再建议新建会话或连接机器。
筛选没有命中任何组或机器（例如机器已被移除）时，按未筛选处理，不留下看不见的收窄。

侧栏点击任务组仍进入该组落地页：目标、下一步、继续上次会话与关联管理。
工具栏筛选只负责行动队列，两者不合并，避免出现第三份队列实现。
全部会话与已归档列出全部内容，不受该筛选影响。
环境弹层里选择机器同样设置机器筛选，此前它无声收窄列表而页面没有任何提示，现在可见且可清除。
工作台工具栏原本用于跳转任务组的菜单已由筛选控件取代；跳转入口是侧栏和会话右键菜单。

验收：`scripts/build.sh`、`WorkbenchChecks`、`ConnectionChecks`、`scripts/check-localization.py` 全部通过。
预览 fixture 增加了跨机器的任务组数据，覆盖单组、多组「+N」和无组三种行，以及筛选后为空的场景。
`scripts/build-workbench-preview.sh` 在本机跑不起来：没有 `rg`，且源文件清单未跟上活动叙事改动
（缺 `ActivitySummaryController.swift` 与 `ActivitySummarySettings.swift`），两者都与本次改动无关。
改用等价的 swiftc 命令构建同一份预览，启动后持续运行未崩溃。
视觉验证用离屏截图完成：把生产 `WorkbenchDashboard` 挂进一个真实 NSWindow，再用
`CGWindowListCreateImage` 抓自己的窗口；抓自己的窗口不需要屏幕录制权限，
而整屏 `screencapture` 在本机被 TCC 拒绝。`ImageRenderer` 与 `NSView.cacheDisplay`
都抓不到 SwiftUI 的文本，不能用于这个目的。窗口必须显式设为浅色外观，
否则默认文字色在深色外观下是白字白底。截图覆盖未筛选、按组筛选、组+机器筛选为空、
仅机器筛选、待处理筛选五种状态，确认了徽章宽度、「+N」折叠、无组不占位、
筛选时行内不重复组名、芯片与筛选空状态。
`scripts/check-localization-runtime.sh` 同样无法执行：新构建的命令行二进制在本机被直接 SIGKILL，
签名后仍然如此；另外 /tmp 下新构建的可执行文件也会被 SIGKILL，构建产物要放在仓库目录内。
新增键的表覆盖与占位符对齐由 `check-localization.py` 保证。
