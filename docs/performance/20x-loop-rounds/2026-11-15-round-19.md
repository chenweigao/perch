## 改动（fe17ef1；单文件 `ReplyMath.swift` + 新钉死文件）

`splitInline` 每 run 守卫 `run.text.contains("$")` →
`run.text.utf8.contains(36)`：

- **等价论证（超集 + 无操作路径）**：0x24 在 UTF-8 中自同步（ASCII 字节
  不出现在多字节序列内部），故存在 Character 恰为 "$" ⇒ 必存在字节
  0x24——字节测试是精确超集（必要条件方向零漏检）。多准入的 run 只有
  一类：其每个 "$" scalar 都被融合进更大 Character（GB9b：Prepend 标量
  如 U+0600 与后随 "$" 前向融合；或组合符后缀延长 "$"）——对这类 run，
  `split()` 逐 Character 寻找**裸** "$" 找不到（`text[index] == "$"` 对
  融合 Character 为 false），while 循环零命中，终点 `flushText(upTo:
  text.endIndex)` 返回**单个 text/flags 逐字段值相等的 run**——parse 输出
  对一切输入逐位不变。守卫其余条件（link/code/math 排除）不动。
- 与 round-17 normalizeDelimiters 守卫不同，**无不确定角落需要回落**：
  那里字节对匹配不蕴含 Character 序列匹配（须双侧边界证明）；这里方向
  相反——字节缺失蕴含 Character 缺失（充分拒绝），字节存在的误纳被
  split() 的字面值比较自然消化，行为等价不依赖平台分歧路径。

`Sources/AgentWorkbench` 零差异；Linux 与 Darwin 走同一新代码（平台
中立）。

## 行为等价钉死

`checkSplitInlineByteGuard()`（新文件 SplitInlineGuardTests.swift，注册于
ProtocolTests）：

- **结构例逐规则覆盖 splitInline 文档契约**：裸对内联提取、货币规则
  （closer 后接数字保持字面）、opener 后空白不成对、CJK math 内容、
  **Prepend 融合美元**（U+0600+$x$ 永不提取——字节守卫误纳、split()
  无操作的价值等价路径实证）、**组合符融合开启符**（$◌̈x$ 不提取）、
  strong 旗标穿透（**能量 $E$ 守恒** 的 math run 保持 strong）、代码跨度
  隔离（`$x$` 保持字面）与同段兄弟对（code run 字面 + sibling math="y"
  提取并存）。
- **3,000 文本 seeded fuzz 黄金摘要**：碎片含 "$"、"$$"、"$◌̈"、
  "U+0600"、"U+0600$"、"$x$"、"$甲$"、组合符、ZWJ、emoji、CJK、围栏/
  引用/列表/标题前缀、反斜杠、删除线；语料**规避 URL 形态**（运行时断言
  把守 `://`/`www`/`@`）⇒ 链接后端不参与 ⇒ **单一黄金值跨平台成立且 CI
  可执法**（round-16 版本依赖教训的制度化延续）：在未改产品
  （89e5976+pin）捕获 = **5d1506ed4a822a53**，Mac/Linux × 基线/候选
  **四方逐位一致**（999/3000 文本提取 math，密度守卫 >200）+ 确定性
  双跑。matched baseline 编译且通过（两侧同绿，无预期失败）。
