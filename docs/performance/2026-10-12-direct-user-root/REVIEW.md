# 三轮审查记录

范围：`7db9f5d` 的用户行直接承载优化，以及相关正文生命周期。按任务限定三轮，不扩大为全项目重构。

## 第一轮：性能路径

使用 Axiom Performance 的 profiling / Swift performance 指引，复核六次同二进制对照、阶段归因及附近缓存实现。用户行获取、正文刷新和整体返回滚动均改善，并非仅把工作移到另一计时阶段。准备缓存保留 session/message/source 边界，行宽测量与放置缓存仍在；未发现值得追加的热点修复。

没有采用泛化的全行缓存、并行创建 AppKit 对象或更换架构框架建议。现有证据未支持这些改动，先保留已验证的约 19% 返回 P95 改善。RSS 只是当时驻留内存，不是峰值 footprint 或无泄漏证明。

## 第二轮：AppKit 生命周期与交互

按 Axiom macOS 的桥接、响应链、环境更新检查直接根视图切换。原有测试已经覆盖字形、选择、复制和 renderer fallback，但没有覆盖直接根视图的完整响应链及所有转换分支。

补充真实窗口回归：

- Unicode 选区通过 `NSApp.sendAction(copy:)` 复制，确认响应链；检查后恢复剪贴板。
- 回收的直接用户行清空标识、宽度回调和原始文本。
- 新会话中直接原生用户行 → 助手行，而不是先经过通用容器。
- 原生用户行 → RTL fallback → LTR 原生行。

新旧容器路径均通过。结果和构建摘要见 `review-checks.json`。本轮改进的是回归覆盖，没有发现新的生产代码缺陷。

## 第三轮：异步回调与最终差异

参考 Swift Concurrency 的隔离/所有权原则，逐项审查 controller 宽度测量、height report、文档 publication 和退休队列。保留 Swift 5 language mode / macOS 14 的现有边界，不应用技能里较新 SDK 的 API：

- AppKit 操作仍在主线程；新增宽度回调弱捕获 controller，回收时清空。
- 延迟测量读取当前宽度和内容；高度发布继续校验 generation 和 committed width，旧内容报告不会覆盖新内容。
- 退休 controller 的 heightChanged 已被清空，分批释放任务有界地处理现有队列；没有新增后台任务或循环。
- 主体生产代码摘要与六次性能对照完全一致。此次只追加测试，因此沿用已通过的生产 Release、49 项核心检查和签名结果；新增 fixture 已重建并在两种路径运行。
- `git diff --check` 通过，提交证据中的个人绝对路径已替换为变量占位符。

三轮没有发现需要追加生产修复的确定问题。到此结束本轮优化；真实触控板、另一台机器与有效帧展示数据仍未验收。
