# 完整长输出：独立阅读区

本轮把“显示完整内容”接入固定高度的原生阅读区。多行长输出不再让外层会话行按
全部文本高度测量；预览与完整内容均为 360pt，展开按钮的位置保持稳定。完整内容
仍能选择、复制和局部查找。短内容的呈现不变。

## 同一构建内的对照

Release 固定二进制提供 inline / viewport 两条呈现路径；第二轮反转执行顺序。
每种文本形状、组件、呈现方式各有三轮、九次展开。两条路径共享既有顶部对齐修复
和披露生命周期通知，inline 并非当前安装版本的完整复刻。没有同时编译、采样或进行
辅助功能 UI 操作。完整来源身份和逐次结果在 [results.json](results.json)。

2,400 行合成中英文内容，展开提交耗时，单位 ms：

| 文本形状 / 组件 | inline median / p95 | viewport median / p95 |
| --- | ---: | ---: |
| 多行 Bash | 67.60 / 70.62 | 25.66 / 34.00 |
| 多行 Thoughts | 65.60 / 70.16 | 21.27 / 25.17 |
| 单个超长段落 Bash | 174.96 / 179.47 | 169.55 / 186.02 |
| 单个超长段落 Thoughts | 183.89 / 190.47 | 173.40 / 178.26 |

多行展开中位数下降约 62% / 68%。无真实换行的长段落仅小幅变化，Bash 的尾部值
还更高，因此不认定这类内容得到可靠改善。该样本用字面量 `\\n` 连接相同内容，模拟
转义输出，不含真实私人会话。它说明固定阅读区不是任意输入都能保持恒定耗时的保证。

每次切换采样 500ms；`settled_ms` 是包含主执行器唤醒、布局、显示提交与 CA flush 的
高度最后变化时间（高度不变时为第一次采样）。它不是硬件点击延迟或屏幕实际呈现
时间。p95 采用 nearest rank；每组只有九个值，p95 就是最大值。数据不代表 FPS。
复制、末行搜索和生命周期断言在计时窗口外执行；查找到末尾可能触发额外文本布局。
viewport 还多执行了生命周期检查，因此不能用两者最终 RSS 声称内存改善。

2.4 万行扩展检查（单轮、每组件三次展开）：Bash 中位数 306.35 → 29.40ms，
Thoughts 330.65 → 26.99ms。外层行高度分别从 408,210 / 480,065pt 变为 574 / 429pt
（包括工具标题等外围内容，内层阅读区仍为 360pt）。这项规模检查不与九样本组混算。

第一层 4,000 字符预览的展开中位数：Bash 52.64 → 52.96ms，Thoughts 46.11 → 56.91ms，
没有稳定提速。预览仍走现有文本测量路径；本轮收益范围是“显示完整内容”。

## 内容与几何契约

- 原生 text storage 保留完整来源；私有剪贴板的全选复制与来源逐字相等，不改系统剪贴板。
- 完整文本末行查找、反向环绕、无匹配保留选区、中文 UTF-16 范围都通过。
- 内层查找不移动外层会话；展开/收起采样中标题漂移为 0pt，宿主与行高度一致。
- 同样式追加仅写入后缀，挂载检查确认选区和阅读位置保持；缩放仍跟踪宽度，替换内容
  清空旧选区并回到顶部。运行后仍使用 TextKit 2，未访问旧式 layoutManager。

早期 smoke 不计入对照：复制检查最初请求了系统未公布的现代粘贴板类型，改成读取
文本视图支持的类型后通过；系统查找栏原型没有通过末行选区验收，最终改为组件内的
明确查询状态和 UTF-16 搜索。这个结果不足以认定系统查找功能有缺陷。

## 架构与体验取舍

保留 Observation、现有 AppKit 会话虚拟化与连接生命周期。新边界仅负责一块长文本：
SwiftUI 管理展开/查询，NSScrollView + NSTextView 管理内层阅读、选择和文本布局。
参考 Apple 的 [TextKit 文档](https://developer.apple.com/documentation/appkit/textkit) 和
[TextKit 2 介绍](https://developer.apple.com/videos/play/wwdc2021/10061/)。这里没有引入 TCA，
因为测到的收益来自布局范围，而非业务状态组织。

完整内容现在需要在独立阅读区内滚动，这是可见的交互变化。预览也限制为 360pt，
可能少于原先可见的 4,000 字符，但完整来源仍通过展开与复制保留。全文仍常驻内存；
该实现不是文件流式读取，也不是内存上限方案。组件的局部搜索不改变已有会话搜索索引。

如果后续真实反馈仍集中于无换行大段落，应单独实验分段呈现和跨段选择/搜索映射。
当前证据不足以宣称长对话性能已经完全解决，也不支持为此重写全应用状态架构。

## 复现与试用

```sh
bash scripts/build-long-output-preview.sh
python3 scripts/run-navigation-check.py disclosure --full-content \
  --long-output-variant viewport --disclosure-context --assert-atomic-disclosure \
  --output .local/long-output-example
```

使用新的输出目录；同一二进制将 variant 换为 inline 即可对照。
`--output-lines 24000` 检查更大来源；`--output-shape wrapped-line` 检查单个长段落。
离线试用包为 `build/Perch Long Output Preview.app`，直接呈现合成输出，没有保存的
主机或远程连接。生产构建为 `build/Perch.app`。没有替换或重启当前真实 Perch。
