## 机制探针（Linux / Swift 6.3.3 / swiftc -O；200k 次比较 × 7 轮取最佳；v2 为权威，评审 F7 勘误）

**v1 探针两处缺陷（评审核实，勘误体记录归档 probe/probe-erratum.md）**：
① "不同行"案例的计时循环以 `acc && body()` 累积——首个 false 后
`body()` 不再被调用（全程仅 7 次调用而非 140 万），其 0.071ms/200k 与
派生的"~0.4ns 快速 false"**作废**；② 候选裸字节循环成本（"~1-2ns"）
**从未测量**，该估计**删除**。恒真案例（identity/跨 base 相同/规范
等价）未被短路，v2 确认其数值有效。

**v2 探针（防短路：XOR 累积全调用；防提升：64 对预建数组按迭代计数
轮换索引——首版 XOR 改写因常量比较被优化器提升测得 0.000ms，弃用）**：

| 比较形态 | v2 耗时/200k | 每次 |
| --- | --- | --- |
| ASCII 同 base 相同（identity） | 0.040ms | ~0.2ns |
| CJK 同 base 相同（identity） | 0.040ms | ~0.2ns |
| **CJK 跨 base 字节相同** | 3.190ms | **~16ns** |
| **CJK 规范等价、字节不同** | 61.817ms | **~309ns** |
| CJK 不同行 | 2.697ms | ~13.5ns |
| 裸字节循环（跨 base 相同、每次调用 withUTF8 的探针形态） | 5.461ms | ~27ns |

裸循环行的 ~27ns 含每调用两次 `withUTF8` 获取的开销；产品的
`lineRangesEqual` 在每次 fullLineDiff 调用的**外层一次**
`withContiguousStorageIfAvailable` 内运行，每行成本仅为已持有指针上的
下标字节循环——**未单独测量，不声称任何每行纳秒值**。承重机制事实
经勘误后仍成立：跨 base 字节相同 `Substring ==` ~16ns vs 规范等价
字节不同 ~309ns（约 20 倍）——规范回落是昂贵分支、设计只为字节不同
对支付；采纳量级仅由上下文内 A/B 决定（其中亦包含消除两侧
`[Substring]` 全量物化：每行 index 运算 + 构造 + 基串 ARC + 数组增长）。
Mac 侧计时探针未做（mini 上裸 swiftc SIGKILL——WORKSPACE-DESIGN.md:166；
解释模式计时无意义）——Mac 机制量级由上下文内粗筛/正式测量直接裁决。
v1/v2 脚本与输出、勘误记录归档 [round-23/probe/](round-23/probe/)。

## 改动（v1=3ba1f1a；单文件 `SessionEditStats.swift` + 新钉死文件）

`fullLineDiff` 连续存储路径：`lineRanges(in:)` 以与 `lines(_:)` 连续
路径**完全相同的分隔谓词**（LF 且前驱非 CR）产出整数 `Range<Int>`
数组；前后缀扫描用 `lineRangesEqual` 比较——长度相等时裸字节逐一
比较（UnsafeBufferPointer 直接下标，无迭代器 witness——round-21
stdlib 陷阱规避），字节全同 ⇒ **确认相等**（规范等价自反性：字节
相同即同一字符串）；长度或字节不同 ⇒ **不可判定**，物化与 `lines(_:)`
完全相同的两个 Substring 走原规范 `==` 裁决。扫描停止位置与数组合并
逐输入一致 ⇒ tally 不变。外部/非连续存储保留原数组走法**逐字不动**；
`lineDiff` 路由（nil/空早退、≤1024 小输入、探针快路径）零改动。

预期回归面（如实预告，机制表述经评审 F8 更正）：edit512_canonical
场景每行字节都不同——bench 的 é 转 NFD 后**字节长度增加**，比较先
失败于长度检查（不执行逐字节循环），再按需物化两个 Substring 走规范
回落；净增开销为区间数组构建+长度检查+按需物化形态。该指标预期轻微
变慢，粗筛/正式数据单独披露。
