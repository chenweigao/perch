## 分页 prepend 构成（Mac，17,861 样本，三件套 ≈4.1ms bench 口径）

| 区域 | 占比 | 性质 |
|---|---|---|
| arc-copy | **18.22%** | 值拷贝/桥接 ARC（retain/release/bridgeObject/memmove） |
| string-hash | **17.54%** | Hasher.combine(bytes:) 8.02%+_finalize 2.56%+init(seed) 1.46%+String.hash 1.35%+breadcrumbs 1.72%——字符串键哈希 |
| utf16-bridge | **16.28%** | String↔NSString 桥接（含 breadcrumbs 桥接开销符号） |
| string-compare | 9.35% | 字典键相等比较+input sameWindow |
| dict-find | 9.22% | __RawDictionaryStorage.find 7.03% |
| teardown | 7.82% | 临时字典/数组析构 |
| narrative | 3.94% | ActivityNarrativeProjection（inclusive 7.4%） |
| timeline-make | 3.80% | ConversationTimelineEntry.make（inclusive 13.1%） |
| tool-visibility | 3.31% | ToolVisibilityProjection（inclusive ~4.6% 含 Pass.*） |
| model-update 本体 | 2.86% | update 框架残项（inclusive 91.6%=容器） |
| input-compare | 2.28% | sameWindow 输入比较（含 1.65% 叶） |
| cf-match | 0.82% | 匹配残余（分页无查询，近零 ✓） |

**hash/dict 叶消费者归因**（prepend 相）：`History.joined(_:foldsProcess:)`
5.20% + `History.init(turns:turnCount:source:)` 2.67% +
`ToolVisibilityProjection.projectTurns` 5.09% + Pass.collect/normalize/
present ~1.0% + String.hash 内联 7.51%。**字典机械（hash+find+compare+
breadcrumbs ≈ 36%）+其触发的 ARC/桥接 ≈ 分页成本主体**；消费者几乎全部是
History 构建/拼接与 ToolVisibility 全窗口投影。

**结构根因（源码核对）**：`History.init` 逐 turn 重建 rows/navigation/
**entryTurns[String:Int] 全窗口字典**；`presented(activity:)` 有 memo 但
prepend 改变 turn 序号与 activity 集合 ⇒ memo 失效 ⇒ `joined` 全 turn 重拼；
`projectTurns` 同样全窗口重投影。页 prepend 语义上只影响窗口头部，但**位置
敏感**的字典/序号结构使全部既有 turn 的投影作废——O(窗口) 而非 O(页)。

## Round-35 候选方向（草图，五点门控论证留待立项轮）

**假设**：分页 prepend 的 History/ToolVisibility 重算可按 **turn 粒度记忆化**
——prepend 不改变既有 turn 的内容，只平移其位置；若投影产物按（turn 内容
身份）而非（turn 序号）键控，prepend 只需为新页的 ~1-2 个 turn 付投影成本，
既有 turn 的 rows/entryTurns/visibility 以 O(turn 数) 序号平移复用。
- 预期：older_page 三件套中字典机械 ~36%+其 ARC/桥接的大部分 ⇒ 目标 -40~60%
  （4.1ms→~1.6-2.5ms，Mac 可测面充分，非打印地板问题）。
- 关键设计问题（立项轮回答）：turn 身份键的字节精确性与失效语义（内容编辑/
  折叠状态/narrative overlay 变化必须失效——round-12/30/32 谓词族移植）；
  entryTurns 序号平移的 O(turns) 实现；joined 的 parents/rows 拼接增量式；
  ToolVisibility split/activeIDs 的位置依赖剥离；presentation 缓存层
  （ConversationPresentationCache）内的存放位置与预算（有界缓存五点论证）。
- 红线检查：展示层行为等价钉死密集（presentation/paging/fold 测试族既有），
  等价断言零放松；不碰 Sources/AgentWorkbench。
- 风险：turn 粒度 memo 的键碰撞=错误折叠/可见性（用户可见缺陷类）——钉死
  密度须对齐 round-30/32 水准；narrative overlay（activity 参数）与 memo 的
  交互面。
