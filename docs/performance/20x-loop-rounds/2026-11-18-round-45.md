# Round 45 — ToolVisibilityProjection 冷构建 vs 温复用（评估轮，不立项）

日期：2026-11-18。base：`84e1d2e9`（round-44 合并点）。零产品改动。

## 结论

round-44 给出的两个候选（`projectTurns` 6.36% inclusive、`Snapshot.presented` 5.24%）
在本轮探针下都不构成**超噪声的可采纳收益**：

- `projectTurns` 的 6.36% 主要由 **冷缓存时的整窗重建** 构成（8/16 次进入时 `chunks`
  为空，全部 1,864 次 turn 重建都发生在这 8 次里）；另外 8 次进入时 `chunks` 完整，
  **1,846 次 turn 全部命中复用、零重建**。冷构建是首次投影的必经工作，不是每 delta 的
  冗余；温路径已无整窗重算。
- `Snapshot.presented` 5.24% 的主体是 `Presentation.parents` 2.37%，该函数自 round-42
  起已按增量构造（只接收最新行 + 既有 parent 映射）。
- 剩余温路径自身开销（`projectTurns` 本体 20.70% + `identities(in:)` 10.22% 的
  projectTurns 样本份额 ≈ 全样本 2%）低于分类器噪声带，无法用六对 A/B 分离。

因此 round 45 **不立项**，停止规则计数 2/3 → **3/3**，触发停止规则①（连续三轮无超噪声
可采纳收益：round 43、44、45），循环按契约停止并输出总结报告。

## 方法

复用 round-43 归档 XML（`.local/round43/streaming-time-profile.xml`，decode-free
n = 11,691，round-34 F2 ancestry 口径），两步：

1. **静态定位**（`.local/round45/tv_leaf.py`）：对每个含 `projectTurns` 的 decode-free
   样本，取其叶帧与叶上第一个非机械帧，得到 `projectTurns` 内部的成本归属。
2. **动态探针**（Mac mini，base `84e1d2e9` + `probe.patch`，release
   `WorkbenchChecks`，`WORKBENCH_TV_PROBE=1 WORKBENCH_BENCH=streaming`）：统计
   `update(splittingAt:)` 的 `canReuse` 命中/失败原因、`projectTurns` 进入次数、
   命中/重建 turn 数、进入时 `chunks` 是否为空。探针跑完即从产品树还原，未进入任何提交。

## 证据

静态（744 个 `projectTurns` 样本，占 decode-free 6.36%）：

| 叶上第一个非机械帧 | 样本 | 占 projectTurns |
| --- | --- | --- |
| `Pass.normalize(_:)` | 270 | 36.29% |
| `projectTurns(_:split:sessionID:activeIDs:online:)` 本体 | 154 | 20.70% |
| `Pass.collect(_:)` | 128 | 17.20% |
| `Pass.present(id:call:result:)` | 84 | 11.29% |
| `identities(in:)` | 76 | 10.22% |
| 其余（数组/集合分配、`identity(of:in:offset:)` 等） | 32 | 4.30% |

叶帧以 `Hasher.combine(bytes:)`（9.95%）、`swift_retain/release`、`__RawDictionaryStorage.find`
为主——是 turn 字典与身份集合的机械成本，非可消除的重复工作。

动态（`round-45/probe-counters.txt`）：

```
updates=150 prefixHits=134 ptRuns=16 reused=1846 rebuilt=1864 empty=8 present=8 whole=0
failures: count=8  (no session/anchor/online/active/observed/separates/sameWindow failures)
```

- `canReuse` 134/150 命中；失败的 8 次全部是 `prefix.source.count != split`（前缀窗口
  长度变化，例如页边界/新提示），属于必须重算的情形。
- `projectTurns` 16 次进入按缓存状态 **恰好对半**：`chunks` 空 → 全量重建（1,864 次
  重建全部在此）；`chunks` 完整 → 全量复用（1,846 次复用，零重建）。
- 非 split 的 `update(_:messages:...)` 在本次 bench 中未被调用（`whole=0`），所以
  “交替调用冲刷 chunk 缓存”的假设被排除。

| 候选 | 观测 | 裁决 |

## 方法学入册

- inclusive 份额不能直接当作可攻头寸：`projectTurns` 6.36% 中约一半是**冷缓存整窗
  构建**，属于首次投影的必经成本，只有温路径份额才可谈判。
- 判读“某函数每次更新都跑”之前，必须用探针区分 **进入次数 / 缓存状态 / 重建数**；
  栈上符号只能给出 inclusive 份额，不能给出触发分布。
