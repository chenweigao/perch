# 侧栏行更新边界：未采用的对照实验

**本轮不采用候选架构，生产侧栏保持原实现。** 两层值比较/Observation 边界确实减少
了行 body 重算，但三轮对照没有端到端收益：目录刷新慢约 4.1%，联合更新基本不变，
内存没有明显改善。最终仅保留诊断场景、功能验收、实验补丁和测量记录。

这组结果收窄了下一步方向：继续给状态加包装无法解释或消除主要成本。下一轮应把
目录场景拆成内容改变、顺序/分区改变和行高改变，观察布局传播；再根据同条件对照
决定是否需要 AppKit 列表原型。暂不迁移 TCA、SwiftData 或扩大缓存。

## 候选做了什么

候选 `SidebarSessionLink` 接收完整会话和任务组数据，并在行内观察选择、置顶、
忙碌及归档资格。`SessionSidebarRowPresentation` 将这些完整值交给第二层
`SidebarSessionContent` 比较。动作闭包在比较边界内部由当前 model/item 创建，
没有以“忽略闭包”的方式跳过比较。分区和顺序仍由原投影与 ForEach 管理。

原生挂载检查验证选择、单条内容、忙碌、任务组归属、置顶和重排，以及恢复原内容。
候选全部通过；随后撤回包装，在保留原生产实现的诊断构建中再次检查并计数：

| 操作 | 原实现重算行数 | 候选重算行数 |
| --- | ---: | ---: |
| session-0 → session-1 | 20 | 2 |
| 修改一条会话内容 | 20 | 1 |
| 一条会话进入忙碌状态 | 20 | 1 |
| 修改一条会话的任务组归属 | 20 | 1 |

两者在选择切换期间的 `WorkbenchSidebar.body` 重算都是 **0**。虽然选择读取写在
父视图的辅助方法中，它在 ForEach 行构造过程中执行；不能仅凭代码位置认为它会
使侧栏根 body 重算。这也是保留真实挂载计数而不只靠源码推断的原因。

计数是两个诊断构建分别执行同一场景得到的结果，不是时间收益；候选的一条编辑、
忙碌和任务组各一行由当时的断言验证。原实现与候选使用相同的原生行探针；时间
A/B 模式不挂载这些行探针，计数开关也关闭。编译期 fixture 与正式生产仍有区别。

## 三轮固定二进制 A/B

基线为上一轮 `6b4a973` 的固定应用，候选应用只增加本轮实现和验收代码。Apple M4、
16 GiB、macOS 27、Swift 6.4、release -O，窗口 1280×820；500 条目录记录，最近
会话最多显示 20 条，目录场景交替 0/4 条置顶，八个驻留会话各 200 轮历史。

每轮每个场景各 80 步。第一、三轮按切换/目录/联合顺序，先基线后候选；第二轮
反序且先候选后基线。18 次运行均通过，无 profiler，不与本任务编译并行；其他
桌面活动未控制。每步从模型修改前计时，到布局/显示/CA flush 后验证侧栏投影、
正文和草稿。fixture 数组构造不在每步延迟内，但包含在整个循环进程 CPU 中。

| 场景 | 基线 → 候选中位数 | 变化 | 循环 CPU 中位数 | 结束 RSS 中位数 |
| --- | ---: | ---: | ---: | ---: |
| 固定目录切换会话 | 52.53 → 52.82ms | +0.6% | 4.484 → 4.450s | 198.89 → 199.00 MiB |
| 固定会话刷新目录 | 25.35 → 26.39ms | +4.1% | 2.022 → 2.090s | 190.44 → 190.53 MiB |
| 同时切换和更新目录 | 73.37 → 73.70ms | +0.4% | 6.120 → 6.142s | 203.41 → 202.78 MiB |

延迟列为三轮中位数的中位数，RSS 是每轮之后再滚动 120 步并等待回收的结束值。
目录各轮中位数范围：基线 25.30–26.03ms、候选 26.04–26.46ms；对应循环 CPU
约增加 3.4%。纯切换 CPU 的不足 1% 变化和联合场景约 0.63 MiB 的 RSS 差异不足以
抵消这项退步，也不支持响应更流畅的结论。

压力目录场景每步会修改多行内容、顺序和置顶，因此行值比较不能跳过这些真实变化。
但即使固定目录只切换选择，减少 18 行 body 重算仍没有改善总延迟。这说明 body
计数不是主要成本的充分代理；不能据此宣称精细 Observation 已解决布局热点。

本轮没有重新采 CPU 栈。[此前诊断](../2026-09-29-render-isolation/REPORT.md) 的框架
图更新/布局归因仍只是后续调查入口，不能把所有剩余成本直接归给侧栏。

python3 scripts/run-native-acceptance.py --mode sidebar-invalidation --output <新目录>
