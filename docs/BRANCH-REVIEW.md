# 分支改动审阅

Git 面板增加“分支改动”：输入执行环境中已有的分支、远端跟踪引用或提交（例如 `origin/main`），点击“比较”。

- 比较目标与当前 HEAD 的共同祖先到 HEAD，显示当前分支已经提交的改动；目标分支独有的提交、暂存、未暂存和未跟踪文件不混入结果。
- 比较时固定目标提交、共同祖先和 HEAD。随后打开各文件仍读取这组提交，即使分支已移动；点击“比较”或“刷新”才更新版本。
- 选区反馈沿用加入草稿流程，附带执行环境、原/新行号、内容指纹及完整比较提交 ID，不自动发送。
- 重命名显示旧路径到新路径，并按两条精确路径读取；删除、二进制、截断差异沿用现有展示。路径按字面值传给 Git，不解释为 pathspec 模式。
- 缺失引用、无提交、无共同祖先会显示错误，清除上一份差异，不会呈现成“无改动”。
- 使用仓库中现有引用；不 fetch、不切分支、不修改索引或工作区。本机和 SSH 共用现有只读执行通道。

## 验收

`WorkbenchChecks` 使用临时 Git 仓库覆盖目标分支分叉、固定提交、未提交隔离、重命名/删除/二进制、路径字面值、外部 diff 禁用、截断、缺失引用和原仓库状态保留。

`run-native-acceptance.py --mode branch-review` 验证实际 RemoteFileBrowser：提交差异与工作区差异切换、错误清理和带提交信息的草稿。此模式加入 macOS 功能检查。验收使用本机临时仓库和内存 Agent，不代表真实 SSH/模型或双 Mac 恢复验收。
