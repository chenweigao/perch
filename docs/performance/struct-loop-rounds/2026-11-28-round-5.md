## 1. 方法与中立性

## 3. 口径纪律（本页所有数字的读法）

1. **嵌套 stage 严禁相加。** 源码原注释即规定「Nested stages are reported separately; their durations
   must not be summed」。`document_configure` ⊃ {`document_reconcile`, `refresh_total(source=configure)`}，
   而 `publishHeight` / `restoreReadingPosition` **未埋点**。
2. **三段相位可以相加**（连续且互斥），实测漂移 +0.000000ms；**轮询三段子span 也可相加**，
   残差 +0.001ms 记为循环开销、不折进任何产品成本。
3. **`poll_sleep_ms` 不是 harness 开销。** 它是围绕 `Task.sleep(for: .milliseconds(1))` 的实际经过时间，
   即 harness 任务**被挂起**的时长；挂起期间主 actor 正在跑延迟的产品工作
   （Observation 驱动的 SwiftUI 更新、模型投影、rail 发布）。它**既不是空闲也不是纯定时器超调**，
   只给出「产品按自己节奏完成的工作」的**上界**。该口径已写进 harness 自身的
   `struct_cold_poll_boundary` 键（v7 起），随 `result.json` 归档。
4. **inclusive 栈权重互相重叠**，不得相加为总量；哪一对可加由**样例栈的帧序**决定
   （`body.getter` ⊃ `presentation.update` 不可加；`body.getter` 与 `configure` 是兄弟、可加）。
5. **`summarize-time-profile.py` 的分桶规则决定可见性。** `ConversationTranscript.` 不在其规则里，
   于是 28ms 的最大应用帧被整块塞进 `framework_graph_remaining`；只看分桶表会误判为「框架、无法归因」。
   必须同时读 `main_app_inclusive_top` 与 `app_stack_examples`。
6. **同名符号跨多处出现时不得据单个样例栈归属。** `specialized Collection.map` 15ms 既可能来自 body 的
   `rows.map`，也可能来自 Auto Layout 的 `ViewLeafView.sizeThatFits`（归档样例恰是后者）——**本页不归因它**。
7. **采样下的 mount 值只作归因用，不作性能数字。** 中性数字来自 §1 的交替作业。
   （核对：捕获下窗口 156.7–179.1ms，与中立运行 165.1–168.7ms 同量级，说明采样未明显拉长窗口，
   但这只是核对，不改变本条口径。）
8. **消融不是固定场景。** catalog=8 的运行**不得**被引用为冷首访数字。

## 4. 裁决

### 4.1 更正终态一处论断

INDEX「循环终态（2026-11-28）」节与 round-2 详情页曾写「挂载另含约 165ms 视图/布局，shard A 不触及」。
**该论断两处都错**：

- 不是「视图/布局」：转录文档路径（含 reconcile、可见行刷新、行几何、host 创建、文本测量）
  只占窗口 **8–9%**，冷挂载只物化 **3 行**，`row_create` 1–3ms，`framework_layout` 不随规模变化，
  harness 自己的 layout/display/CA flush 全窗仅 **1.576ms**、收尾 flush **0.011ms**；
- 不是「另含」：`model.open` 同步段只有 **0.133ms（0.08%）**，模型层工作被 Observation
  推迟进**同一个**窗口，与视图工作交织在同一段轮询里。

「两个倍率不可相乘」「不得把模型层倍率当整窗交互倍率」这两条**结论不变**，变的只是理由。
这也解释了为什么模型层 2.117× 只换来整窗 1.15×。

### 4.2 立项提议「mounted 路径的视图/布局优化」→ **驳回**（不开队列项）

依据即 §4.1 与 §2 第1/5刀。

> **编号更正**：本轮初稿把该提议写成新队列项 ⑥，与仓内**既有** ⑥（`sameNavigation`
> 共享连续存储短路，round-2 评审 N4 登记）**撞号**。被驳回的是一项**本轮提出的立项提议**，
> 不是任何既有队列项；新项编号为 **⑦**。既有 ⑥ 处置**不变**。

### 4.3 新队列项 ⑦ — `ConversationTranscript.body` 的 O(turns) 投影与 16k 视图模型构造

**状态：立项为「待证明候选」，不记为可采纳收益。**

- **已测上界**：`body.getter` inclusive **28.0ms = 窗口 16.6%**；扣除嵌套的 `presentation.update`（18.0ms）后，
  属于 body 自己的约 **10ms = 窗口 5.9%**，高于本循环 **2.5%** 的同场景入口门槛——
  **但这是上界，不是净下界**。
- **入口判据未满足**，故只立项不采纳：
  1. **CPU 份额 ≠ 窗口份额。** 8000 turns 下主线程只有 **64%** on-CPU（1000 turns 下 95%），
     窗口并非纯 CPU-bound；另有 ≈36% 窗口时间主线程未被采样。省掉 28ms CPU **不等于**窗口少 28ms。
     收益**只认** `struct_cold_mount_ms` 的同机交替 A/B，不得用 CPU 时间替代。
  2. `presentation.update` 18.0ms 属**模型层**，与 round-2/4 的模型层基准
     （`update_wall_ms` 31–35ms、`make_total_ms` 14.9ms @16k）**口径不同，不得等同或相加**。
  3. 惰性化 `contents` = shard B 方向，须先满足 `shardB-A2-design.md` §11.4 的复活条件；
     `ConversationTimelineEntry.id` 是锚点 / 折叠 / 阅读位置的键，改其语义碰红线。
- **推进顺序（写死，避免下次再议）**：
  - (a) **先做不改语义的子项**：把 body 内每行 3 次 `entry.id` 计算属性访问降为 1 次（或缓存），
    单独在**窗口口径**上 A/B（同机交替 ≥5 对、逐对差超带、披露延期成本）；
  - (b) 若要动 `contents` 的构造时机（惰性/增量），须同时满足 §11.4 复活条件
    （行几何次线性化或 `O(n−i+k)` 线性增量 splice，且重测 C ≲0.5ms@16k 行——该 0.5ms 是设计目标值、非实证阈值）；
  - (c) 任何 ⑦ 候选**不得**引用本轮的 CPU 时间作为收益证据。

### 4.4 对其余队列项的影响

- **①B shard B**：`reconcileRows` 在窗口内实测 inclusive **11.5ms**（n=6），与 round-4 单次结构变更
  **C ≈ 10.0ms @16,000 行**同量级、互相印证。**不改变其缓议裁决**（收益侧 15.6ms 仍从未 A/B），
  只补上成本侧的第二次独立测量。
- **④ prepend 残余 / ⑤ cf-match / ⑥ `sameNavigation`**：本轮未触及，处置不变。
- **仍不可归因（明示，不做因果猜测）**：~62ms 主线程 CPU 是不含应用符号的纯框架栈
  （AttributeGraph 更新、Auto Layout、CA），≈36% 窗口时间主线程未 on-CPU。
  要继续推进**只能靠消融**（改一个变量再测），不能靠读栈。

## 5. 本轮新增方法学教训（编号续 INDEX「否定清单 / 方法学教训」）

16. **「另一个基准的值在这个窗口内」是推断，不是测量。** 本循环终稿就此写错过一次（§4.1）。
    跨场景搬数字前必须先在同一窗口内测一次。
17. **harness 的轮询 sleep 属被测窗口，必须自证代价。** 若没有第3刀，「99% 在 settle 里」
    会被两头误读（「99% 是 harness 开销」或「99% 是产品工作」）；两者都不成立：
    harness 实付 1.65ms，其余是挂起期间的产品工作，而挂起时长只是其**上界**。
18. **口径声明要写进产物本身。** `struct_cold_boundary` / `stage_boundary` / `phase_boundary` /
    `poll_boundary` / `signpost` 五个键随 `result.json` 归档，使证据脱离本次会话也能被正确阅读。
19. **Linux 侧无 Swift 工具链 ⇒ harness 编译错误只能在 Mac 构建时暴露。**
    v8 首次上传即 rc=1（`OSSignposter.beginInterval/endInterval` 要 `StaticString`，
    而 `let mountSignpost = "…"` 推成 `String`）。作业必须：构建先于任何运行、失败即 `exit 1` 并回显 log 尾部、
    EXIT trap 还原工作树、**被拒补丁连同失败原因一起归档而非覆盖**。一次失败作业成本约 15 秒。
20. **分桶规则决定你能看见什么，工具默认的分组不是事实的分组。**（见 §3 第5条）
21. **同名符号跨多处出现时不能据单个样例栈归属。**（见 §3 第6条）
22. **消融要给驱动方假设一个可失败的对照，且控制组放在两端。** catalog 500→8→500 让漂移表现为
    两个 500 之间的差（168.286 vs 167.988ms，0.18%），因此「8 会话反而略高」才能判为**阴性**而非噪声。
    **阴性结果同样是交付物**：它排除了两个候选解释之一。
23. **inclusive 上界必须按样例栈帧序扣除嵌套部分**才能当作「本层自己的」成本（见 §3 第4条）。
