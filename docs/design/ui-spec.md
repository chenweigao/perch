# UI / 交互规范

> Perch 界面与交互的**唯一约定来源**。凡是"两个地方长得不一样、动得不一样"
> 的问题，先在这里定一条规则，再改代码；代码里值得复用的做法，回写成规则。
> 做法移植自 ccgui 的 ui-ux-spec（MIT），内容按 Perch 实际落地。

## 维护约定

- **谁改谁更新**：新增或修改用户可见的交互反馈、基础组件视觉、动效时长时，
  在同一个提交里更新本文对应章节。
- **规则要能指到代码**：每条规则写清文件和类型名。文档与代码冲突时以代码
  为准，并立即修正文档（或改代码 + 补充说明）。
- 规则来自真实问题，不预先发明；同一条规则第二次被违反时才值得新增。

## 动效

- **展开/收起做高度过渡，推开下方内容，不允许条件渲染直接闪现。** 统一走
  `WorkbenchDisclosureContent`（`Sources/AgentWorkbench/WorkbenchGlass.swift`）：
  250ms easeInOut clip 高度；收起动画结束才卸载内容；记忆展开状态的行
  恢复时不重放动画。详见 `docs/design/disclosure-animation.md`。
- **列表行不用 opacity 淡出**，只裁切高度（淡出会在下方内容上留一帧残影）。
- **动效可降级**：所有过渡在 Reduce Motion（系统或会话覆盖）下直出。

## 表单与问答

- **单选圆形标记、多选方形标记**（`KimiQuestionView`、`NativeInteractionView`）。
- 单选答完自动推进到下一道未答题；中间多选题「确认本题并继续」；最后一题
  由底部「提交回答」统一提交；自由回答输入时不自动推进，已答摘要可「修改回答」。
- **禁用要看得见**：排队调序按钮在两端禁用但保留位置（置灰），不用隐藏代替。

## 正文刻度

- **14pt 主字号 + 12pt 辅助字号**。稳定界面取 `WorkbenchTheme.Typography`：导航、会话名、文件名、模型选择为 14pt；标题也是 14pt，以 semibold 和留白区分；次要说明仍为 14pt，以次级颜色、分组、折叠区分。只有时间、计数、快捷键等辅助信息用 12pt。SF Symbol 保留独立的光学尺寸。
- **阅读文字默认与界面同号**。`ReadingScale` 的正文、输入框、思考、代码、表格、过程标签均为 14pt，正文和思考行高 22pt。H1 / H2 为 18 / 16pt，H3 以下同正文，以字重和间距分层。文档阅读器默认也为 14pt，保留独立阅读偏好和文章标题层级。
- **保留阅读缩放**。设置 › 界面或「显示」菜单可选择 14–18pt；⌘0 回到 14pt。保留已有显式偏好。缩放时正文、思考、代码、输入框、过程标签共同变化，辅助字号为 max(12, 正文 − 2)；行高为 正文 × 22/14，段距按 正文 / 14 缩放。侧栏、工具栏和面板标题固定取界面字号，680pt 阅读栏和水平内边距不变。
- **视图里不写本地文字字号**：文章与对话取 `ReplyStyle`，稳定界面取 `WorkbenchTheme.Typography`；同号角色仍分别命名，避免未来各组件自行新增字号。
- **字号变化立即生效**：`ReadingBodySize` 是 `@Observable`，读取字阶的 SwiftUI 视图自动重绘；
  `ConversationEntryAppearance` 带上正文字号，变化时所有已挂载行重新排版、重新测量；原生行的预处理缓存以字号为键，
  复用的代码卡和列表标记按当前字号刷新。`reading-design` 阶段在 18/16/14pt 间切换并检查已挂载原生行的字号、行高和 H1。
- **气泡里的文字按光学居中**：TextKit 把行高多出的行距放在字形上方，正文行高下单行文字会在行框里偏下（14pt 约 3pt）。
  用户气泡（原生行、SwiftUI 回退、待发消息）共用 `UserMessageStyle.textLift`：按首行基线和大写字母高度算出上移量（取整点），
  上内边距为 `verticalPadding − textLift`、下内边距为 `verticalPadding + textLift`，气泡总高度不变。
  导航检查 `user-rows` 要求单行气泡里大写字母的中线与气泡中线相差不超过 0.6pt。
- **两种渲染共用节奏**：块间距统一走 `ReplyStyle.blockSpacing`，代码卡片、引用、列表分别用
  `ReplyStyle.Code` / `Quote` / `ListLayout`；SwiftUI 行与原生缓存行必须从同一组常量取值，
  流式结束切换渲染时不得跳动。

## 思考与过程

- **运行中的思考就地显示**：思考仍在流式输出时（`.thinkingPreview`），正文显示「思考中 · N秒」一行（只有标题每秒刷新），
  默认展开最多四行、跟随流式内容的预览（`ThinkingTextViewport`），超出时可打开全文；状态条只说阶段与动作。
  计时起点是本机第一次看到这段思考（`ConversationProcessClock.liveStart`）。只在流式期间默认展开；
  轮次结束仍没有回复的思考记录默认收起。
- **思考结束后显示用时**：该段思考出现在正文中，折叠头写「已思考 N秒」，展开为次要正文字号的全文；
  本轮结束后与工具记录一起收进「思考与工具」，第一个折叠头附「· 用时 X」（与状态条结束时的「用时」同一数值）。
- **只显示亲眼看到的时间**：用时来自本机客户端观察（`ConversationProcessClock`，仅内存），历史会话、重启后或
  只观察到后半段（observedOnly）的轮次不显示数字，仍写「思考」，不做估计。Kimi 的实时思考在结束时换成新消息 ID，
  因此只保留整轮用时。

## 窗口框架

`WorkbenchSplitController` / `WorkbenchDetailController`（`Sources/AgentWorkbench/WorkspaceSplitView.swift`）。

- **一整块液态玻璃底板。** `WorkbenchWindowBackdropView` 是铺满窗口的系统 Liquid Glass（`.regular`），
  窗口不透明度关闭，玻璃直接采样窗口后方的桌面，颜色随壁纸和后方窗口变化；圆角读取窗口自身圆角，玻璃边缘高光与窗口边缘重合。
  不叠加固定色、不降低玻璃 alpha（降低 alpha 会透出未模糊的桌面）；开启“减少透明度”时换成不透明的 window-background 色。
  侧栏和工具栏共用底板；侧栏不再单独加玻璃外框、描边或阴影。
  视图缓存截图（`cacheDisplay`）不含玻璃；`native-design` 阶段另存 `*-composited-*.png` 系统截图用于检查实际效果。
- **内容浮在底板上，圆角与窗口同心**：主内容卡片和窄窗侧栏覆盖层离窗口边缘 12pt，圆角取
  `WorkbenchTheme.Radius.framePanel`＝窗口圆角 − 12pt（不小于 10pt；窗口未报告圆角或全屏时按 26pt 工具栏窗口计算），
  随窗口圆角实时更新（`WorkbenchSplitController.panelCornerRadius`）。正文与检查器放在同一个 `WorkbenchContentCardView` 内：
  共用不透明底色、发丝线、连续曲率圆角和一层轻量 AppKit 阴影；检查器不再单独加外框或阴影。
  裁切内部页面，终端与滚动内容不越过圆角。玻璃表面（输入框、浮动控件）同样使用 `.continuous` 曲率。
- **正文为主，检查器融入主容器。** 画布、对话和草稿 hosting root 始终保留；右栏与正文共用外框，内部用 1pt 分隔线区分。
  右栏填满容器高度，目录、预览和任务在内部滚动；开合右栏不移动主容器外缘，正文与输入框在剩余阅读空间重新居中。
  保留侧栏默认 304pt 和已保存的拖拽宽度。三者放不下、但去掉侧栏能保留 600pt 阅读区时，侧栏让位（隐藏但不改保存的显示偏好，
  `isSidebarYieldingToInspector`）；此时点侧栏按钮会让侧栏浮回正文上方。更窄时右栏让出至少 320pt 阅读区，不覆盖回复或输入框。
- **标题锚定窗格，阅读栏居中**：工具栏标题只显示文字，14pt medium，距卡片左侧 24pt；最大宽度 360pt，长标题单行尾部截断，悬停显示完整标题、Agent、机器和目录。标题恢复或更换后仍保持此对齐；正文、活动条和输入区在卡片当前可用宽度内居中。
  右栏展开或关闭、左右侧栏缩放后必须重新居中，不能把正文固定在左边。对话和草稿宿主保持挂载。
  工具栏放在统一底板上，使用系统紧凑样式，正文卡片从窗口顶部 44pt 开始；hosting root 不重复应用标题栏安全区。
- **工具栏按钮一组胶囊**：改动、文件、任务面板和会话菜单共用一个玻璃胶囊，单个按钮不再各带底。前三项仅显示图标：改动采用加减号、文件采用文件夹、任务采用清单；保留悬停提示与辅助功能名称，不显示常驻文字。会话菜单保留省略号。整组固定在窗口右缘，不随检查器开合向中间漂移。
  机器和 Agent 只在输入框底部显示，标题旁不再重复。
  图标统一为 14pt 常规字重，保留 32pt 点击区域；改动、文件、任务哪个已打开，哪个显示内缩的轻量选中底色。
  选中底色与悬停、按压分级，不为每个按钮增加独立玻璃或阴影。
- **模型必须可见**：输入框底部明确显示实际模型名及独立的思考强度选择器，不能用 Agent 名替换模型名。
  运行环境作为次级信息；控制行不再给每组文字各套一层胶囊。窄窗口先将辅助控件移到第二行，保留模型与发送按钮。
- **输入文字与正文对齐**：正文最大 680pt，输入框外壳最大 704pt，内部 12pt 留白；
  两者共用中心线与文字左缘；窄窗下正文最少保留两侧 24pt，输入框两侧 12pt。外层继续使用系统 Liquid Glass，
  浮在正文之上（见「状态条」），输入文字与正文同为当前正文字号。
- **阅读上沿**：正文滚动视口上方固定留 12pt；滚动到中间时文字仍与卡片上沿保持间距。顶部没有覆盖正文的悬浮控件，不额外叠加渐隐。
  这条留白属于阅读容器，不随内容滚走；不改变工具栏、右栏或输入区的外层位置。
- **文件入口**：工具栏文件夹按钮打开主容器内的右侧检查器，默认浏览当前会话的工作目录；选中文件原位预览，返回按钮回到目录。与改动、任务共用同一个完整高度的检查器；仅「展开阅读」主动打开独立阅读窗口。切换会话重新定位其工作目录，关闭面板取消尚未完成的读取。
- **任务面板是清单，不是实况。** 「现在在做什么」只由状态条回答；任务面板列出要处理的事、结果、计划、改动和文件，
  内容照常按读取刷新（忙碌时约 2 秒，空闲时 8 秒），但没有脉动、没有逐秒走的时钟，也不列运行中的工具。
  运行中的任务行只写状态，结束后才写用时；头部不放「N 个运行中 · N 次调用」摘要。
  已结束的工具调用不在面板重复（完整记录在正文的「思考与工具」）；只有没人确认的结果（`VisibleTool.staysVisible` 且已不在运行）
  列在「需要你处理」之后的「需要你看一下」，状态条的「查看」打开这里。「本轮」分区的叙事与用时拆分在本轮结束后才出现，
  计划与本轮编辑原位更新。唯一会跟着输出走的是你主动打开的后台任务详情。
- **任务详情**：任务页的后台任务与子 Agent 行整行可点，右侧 `chevron.right` 表示进入；详情原位替换列表，顶部「‹ 后台任务与子 Agent」返回。
  摘要（状态、结束后的用时、命令、元信息、操作）按内容高度排布，下方输出或结果占满剩余高度并在内部滚动；运行中的输出贴底跟随最新。不弹模态表单，子 Agent 过程仍由会话里的表单承载。
- **检查器**：默认 312pt，可调范围 280–400pt；44pt 文件行、14pt 文件名、14pt semibold 面板标题，完整路径和 Git 状态按需查看。
  选中文件名放在差异上方，普通文本差异只显示 hunks；完整补丁在文件审阅窗口保留。
- **任务摘要**：保留 Agent 提供的任务名称；只有默认 Bash 标题才从真实命令提炼操作和程序名，完整命令在右栏原位详情页中可选中、滚动查看。
  已完成、已取消的后台任务默认收拢；运行中、失败和状态未知的任务继续显示，收拢不影响停止、查看输出与会话入口。
- **可读辅助文字**：正文工具摘要、文件名、进度数字与右栏状态使用 `WorkbenchTheme.quiet`；AppKit 文本使用同一动态 `quietNS`，两种外观保持一致。
  用字号和位置区分层级，避免将有用信息降到第三级灰色；警告、失败与禁用状态继续使用各自的语义样式。

## 侧栏

- **一套行几何**：导航、分区头、项目、会话共用 `SidebarMetrics`（`Sources/AgentWorkbench/SidebarMetrics.swift`）
  的图标列与内边距。导航 32pt、13pt 次级字重，分区上间距 12pt；会话行上下各留 10pt（`sessionVerticalPadding`），
  不设最小高度，单行与两行标题的留白一致；长标题继续支持两行，待处理状态继续向下展开，不能固定高度裁掉标题；分区标题从图标列开始。
- **项目子会话图标在项目图标正下方**（缩进 `childIndent`），标题与项目标题对齐。
- **分区头一种样式**：`SidebarSectionTitle`（12pt 半粗，62% 墨色，计数在后，箭头在后），比 14pt 会话标题低一级。
  置顶等分区头不能淡到像禁用。可折叠分区（`SidebarFoldHeader`）的箭头只在悬停、键盘聚焦或已折叠时显示，并始终占位，标题不横移；
  「项目」标题打开视图菜单，用弹出按钮的上下箭头，不与折叠箭头或截断省略号相混。
- **标题右侧操作一种样式**：置顶「+」、筛选、重试、新建任务组、项目行「+」与环境面板「+」共用 `SidebarActionGlyph`
  （12pt 次级色字形、24pt 点击区）。项目行「+」仍只在悬停或聚焦时出现。没有置顶时由「置顶常用会话」引导行提示置顶。
- **筛选可见**：筛选生效时，标题旁显示筛选名和 ×（`sidebar.filter.clear`），点一下回到全部会话。
- 侧栏直接绘制在整窗玻璃底板上；仅窄窗口覆盖正文时补一块同心圆角的浮动玻璃面板，避免文字叠加。白色卡片上玻璃边缘本身看不出来，
  所以覆盖层另加发丝线和只落在面板外侧的阴影（`WorkbenchOuterShadowView`，内部挖空，玻璃仍采样后方正文）。
- **选中行是一张小卡片**：`SidebarHighlight` 选中时为浅色卡片（`WorkbenchTheme.rowCard`，浅色 92% 白、深色 11% 白）加 1pt 发丝线和轻阴影，
  与正文卡片同一语言；悬停为半强度卡片，按下再叠一层浅灰。玻璃上不用灰色涂层表示选中。
- 默认宽度 304pt，可调范围 280–400pt；侧栏与正文卡片共用顶部 56pt、底部 12pt 的边界。顶部「新建会话 / 搜索」使用图标加文字按钮，留在内容区域内，不能用负间距抬到系统工具栏下面，否则鼠标点击会被工具栏拦截。
  初次使用默认显示最近会话，已有项目分组偏好继续保留，工作台、待处理、全部会话与任务组入口可用。
  「全部会话」与工作台、待处理同属页面导航，排在顶部；底部只留添加机器与设置，上方不画分隔线（玻璃上的硬线像接缝，列表底部的柔和边缘已足够区分）。
  快捷键只写在悬停提示里（新建 ⌘N、搜索 ⌘K、添加机器 ⇧⌘N）；设置弹层像菜单，保留「通用设置 ⌘,」。
  设置弹层里的「环境管理」原位换页，顶部有「‹ 设置与环境」返回；环境面板不再套内层卡片，名称 13pt、状态与错误 12pt。
- 会话标题 14pt，图标 14pt；时间与运行状态保留稳定空间，hover 只显示行卡片，不出现任何按钮。置顶和归档只放在会话右键菜单
  （`SessionActionsMenu`）。悬停按钮叠在标题上会压住标题末尾，而侧栏直接画在窗口玻璃上，给按钮垫材质又会透出壁纸颜色。
- **时间写时刻，不写时长**（`SessionTime.compactLabel`）：今天显示时刻（14:32），昨天显示「昨天」，一周内显示星期（周一），
  更早按本地习惯写月/日（3/26），跨年写年/月。标签只在日期变化时更新（`MinuteClock.day`），不随每分钟刷新。
- **状态各说一次**：未读标题加粗一级（semibold）并保留标识角上的蓝点；待处理为橙色角标。离线整行降到 65% 不透明度，
  行尾一个 `quiet` 色断网符号，标识上不再加离线角标；橙色只表示需要处理。
- **Agent 标识是线条字形，不是色块**：`AgentMarkArtwork`（`Sources/AgentWorkbench/AgentMarkArtwork.swift`）在 24 格网格里画
  1.75 格圆头线条（14pt 时约 1pt，与周围 SF Symbols 同重），活动区 18×18，最多一个小实心点（Kimi 的星、鲸鱼的眼）。
  线条保留品牌色，浅色压暗、深色提亮，在侧栏和选中卡片上都不低于 3:1；Kimi、Codex 品牌是黑白，取侧栏次级图标墨色，靠形状区分。
  Canvas 按 `colorScheme` 取色，菜单位图在绘制时按 `NSAppearance.currentDrawing()` 取色。新图形不得与侧栏已有图标同形
  （例如“圆 + 45° 外柄”就是搜索），也不得与同一行的忙碌指示相混。终端保留系统 `terminal` 字形。


## 状态条

`ConversationActivityBar`（`Sources/AgentWorkbench/ConversationActivityBar.swift`），位于正文与输入框之间。
显示什么由 `TurnStatus`（`Sources/WorkbenchCore/TurnStatus.swift`，纯值，WorkbenchChecks 覆盖）决定。
其中“等你 / 运行中 / 失败 / 已完成”取自 `SessionTurn`，与侧栏分区、Dock 角标、通知和 Goal 头部同一构造与同一优先级。
它与提示条、输入框一起构成对话滚动视图的底部安全区栏（`ConversationScrollView` 的 `bar`，`safeAreaBar`）：
正文从输入框玻璃下方滚过，跟随到底时最后一行停在栏的上沿。系统滚动边缘效果关闭（`scrollEdgeEffectHidden`）：
在工作区分栏里它总被画成带分隔线的硬边，与请求的 `.soft` 无关；改由栏背后一条 28pt、卡片底色的渐变把正文淡入栏内
（普通渐变视图，不给整段正文加遮罩）。`reading-canvas` 与 `native-design` 阶段检查栏上沿没有横贯卡片的分隔线。

- **只回答三个问题：还活着吗、在做什么、要我做什么。** 窗口里只有这一行表达实时活动（扫光、走动的用时、增长的产出数字）。
  计划、本轮编辑的逐文件明细、用时拆分、叙事来源、子 Agent 与后台任务都在任务面板的「本轮」分区（`TaskTurnSection`）及其下方各分区，
  面板静止，不重复运行中的动作与时钟（见「任务面板是清单，不是实况」）。没有弹窗。
- **点哪里去哪里。** 整行是一个按钮，铺在文字下面（文字、步数、用时不接收点击，点击落到行上）：
  - 打开任务面板（`ConversationMessageAction.showTurnDetails`，面板锁定在别的会话时改为跟随）：运行中、停止中、计划未完成、结果行；
    这些状态行尾有「›」（`TurnStatus.opensDetails`），与任务面板里可进入的行同一记号。
  - 等你确认或回答时，整行跳到正文里的待处理卡片；失败、有需关注、断连也打开任务面板，但它们有自己的按钮，不加「›」。
  - 右侧的本轮「+a −d」是独立按钮，打开右栏改动页（`showChanges`）；「查看」「重新连接」「Recap」各管各的。
- **一行、透明、恒定高度，没有前置图标。** 可见状态共用 `ConversationActivityBar.height`（32pt），不加整条玻璃、卡片或底色；
  开始运行、等待确认、断连或失败都不改变正文视口高度。要你处理的状态用橙色中等字重的文字和按钮表达，不再配 SF Symbol。
  空闲会话（本机没看到它运行，或结果已收起）不显示，高度为 0。
- **状态与优先级**（从高到低）：

  | 状态 | 文字 | 右 |
  |---|---|---|
  | 断连 | 连接已断开（橙） | 「重新连接」（提示里给出最后的连接错误） |
  | 等你 | 「需要你确认：<事项>」或「需要你回答：<问题>」（橙；`TurnRequest`，取第一项的原文一行），多项附「共 N 项」；取不到原文时「等待你确认 · N 项」 | 实心「查看」 |
  | 停止中 | 正在停止… | 计划 `c / n`、产出、+a −d、用时、› |
  | 运行中 | 计划中进行中的一步 → Agent 进度说明（≤48 字）→ 工具描述 → 通用阶段，有新进展时扫光；运行中工具的目标为次级文字 | 计划 `c / n`、产出（`↓ 3.2k chars`、`7 tool calls`）、+a −d、用时、› |
  | 一分钟没有新进展 | 动作不变；有工具在跑时次级文字为「swift build · 已运行 2分」，否则为「N 分钟没有新输出」（`quiet`） | 同运行中 |
  | 疑似卡住 | 动作不变、不再扫光，次级文字换成「N 分钟没有新进展」（`quiet`，不用橙色） | 同运行中 |
  | 失败 | 本轮失败（橙） | +a −d、「查看」（任务面板的「需要你处理」列出原因） |
  | 结束且有需关注 | 完成 · N 项需要你看一下（橙） | +a −d、「查看」（任务面板的「需要你看一下」列出这些结果） |
  | 结果 | 完成 · 用时 X | +a −d、Recap、› |
  | 计划未完成 | 计划尚未完成 | 计划 `c / n`、+a −d、› |

  运行中出现的需关注结果只加橙色计数，不改当前动作的颜色。+a −d 是本轮 Agent 编辑工具的增删（`TurnStatus.changes`，与正文折叠头同一口径），
  从运行中一直到结果行都在同一位置；本轮没有编辑时不显示。窄窗口先收起计划步数，再依次收起 tool calls、+a −d，chars 与用时留到最后（它是在干活的证据）；
  标题行再去掉次级文字与「· 用时」，标题最后截断。
- **产出数字证明在干活。** 运行中与停止中右侧显示本轮产出（`TurnStatus.output`）：`↓ 3.2k chars` 是本轮 Agent 写出的文字与思考
  （UTF-16 单位，`ConversationActivity.outputCharacters`），`7 tool calls` 是本轮工具调用数；两者只在有新东西到达时增长，为 0 时不显示。
  任何语言下都用英文，与 +a −d 一样是数字标签；超过 1000 写作 `3.2k`、`12k`、`1.3M`（`TurnStatus.compact`）。
- **结果行只说这一轮。** 只在本机看着这一轮运行时出现（有 `ConversationTiming`）。切走会话即收起（`TurnResultMemory`，
  按会话与结束时间，仅内存），下一轮开始前不再出现。轮次结束时「完成」由正文墨色淡回 `quiet`（约 1 秒，只一次；减少动态效果时不做）。
  上一轮的记录在正文末尾的折叠头里。
- **改动页标出本轮。** 右栏改动页列的是 Git 工作区（含你自己和之前几轮的改动）；本轮编辑过的文件排在前面并带「本轮」标签，
  标题旁写「N 个文件 · 本轮 M」（`TurnEditPaths.relative` 把工具给出的绝对或相对路径换成仓库内路径；`~` 开头的路径无法解析，不标）。
  标签在每次读取 Git 状态时按当前对话刷新，运行中不随每个流式片段重算。
- **用时 1 分钟内按秒，之后按分钟**（`TurnStatus.clock`），只在读数变化时重绘（`TurnClockSchedule`）；悬停说明计时起点。
- **安静与疑似卡住由本机判断。** 进度签名（`ConversationActivity.progressSignature`：本轮消息数、末尾文字长度、工具状态与进度、计划步骤）
  每 15 秒检查一次，签名写入引用对象，不让正文或状态条因进度而重算（`TurnProgressClock`）。
  60 秒没有变化（`TurnStatus.quietThreshold`）先说明在等什么：有工具在跑写出它已运行多久（从本机看到它开始运行算起），否则写多久没有新输出；
  3 分钟（有工具在运行时 10 分钟）判为疑似卡住。只判断正在打开的会话，切换会话后重新计时；
  每段安静期报一次 `turnStalled`，按「提醒」的「疑似卡住」档投递。
- **运行中只有标题在动，而且只在有进展时动。** 标题扫光（`ShimmerGlint`，参照 Codex 状态行）：`quiet` 文字上一道约 2.4 倍行高宽的光带，
  峰值为 90% 正文墨色，1.6 秒从左扫到右。它由进度签名驱动而不是定时循环：每次有新进展扫一次，连续到达时两次扫光的起点至少相隔 2.4 秒，
  没有新进展就不动；刚挂上标题时不扫。所以“在动”等于“有新东西到了”，静止配合安静提示说明在等什么。
  只扫标题，不扫工具目标和右侧数字；思考、读取、执行与回复用同一种扫光，标题已说明在做什么。标题本身是普通 `Text`；扫光是同一段文字按标题的框渲染一次的墨色图像
  （`ImageRenderer`，字形与截断和标题一致），由 CoreAnimation 移动的渐变遮罩露出，每帧不重算 SwiftUI 或 AppKit；
  文字、宽度、外观或缩放变化时才重新渲染。疑似卡住、停止中和其他状态静止；减少动态效果时不扫光。
- **“运行中”在列表里仍是日弧。** 侧栏与会话列表的运行中（`ConversationBusyIndicator`）和 Goal 头部的“当前一轮正在执行”
  是同一个追逐日弧（`PerchBusyIndicator`，几何在 `PerchLineMark`）：`quiet`、24 格尺寸、2 秒一圈，减少动态效果时停在 270° 的静止弧。
  品牌标识采用 D1 小鸟：App 图标为深珊瑚 `#E36D55` 底白线，首页品牌位（`PerchMark`）为随外观适配的单色小鸟。
- **Goal 保留执行反馈，断连提示不重复。** Goal 头部保留实际执行的追逐日弧和目标自身状态，状态行高度固定，
  不随一轮开始或结束变化（`GoalHeaderBar.status`）。日弧只在 `SessionTurn` 为运行中时转；目标进行中而本轮等你处理或失败时，
  标签换成橙色「等你处理」「本轮失败」，不再显示「待续跑」。会话可见时，断连只在状态条提示，
  不在底部再放一行（`NativeAgentView`、`KimiWorkspaceView`）。
- **可达性。** 行按钮的名称是「本轮状态」，可悬停、可键盘激活；VoiceOver 值包含标题、次级文字、需关注计数、
  步数与本轮编辑，不含时钟；行内文字对 VoiceOver 隐藏，不重复朗读。+a −d 按钮读作「查看改动」，值为本轮文件数与增删。
  操作按钮保留可见标题，用 hint 说明去向。
- 验证：`check-host-lifecycle.py` 的 `activity-bar` 阶段在宽/窄、浅/深色与六种状态下检查高度、视口不变，
  用真实鼠标事件检查点运行中与结果行的标题会打开任务面板、点等你的行会跳到待处理项、「查看」「重新连接」可点击，
  检查标题只在进度变化时扫一次（挂上时不扫、没有新进展不扫），并检查空闲时高度为 0；
  `TurnStatus` 的标题优先级、等待原文、结果、本轮改动、产出数字与缩写、安静与卡住阈值、扫光与「›」的条件、时钟和 `TurnEditPaths`
  在 WorkbenchChecks（`checkTurnStatus`）。

## 提醒

`AttentionRouter`（`Sources/WorkbenchCore/AttentionRouting.swift`）决定渠道，`WorkbenchNotificationState` 只负责投递。
目标是让人不必盯着运行中的会话：该你出场时由 Perch 叫你回来。

- **按读者所在位置分三种场景**：正在看这个会话（Perch 在前台、主窗口可见且显示该会话）→ 不弹提示，状态条自己说明；
  在看别的会话或工作台 → 窗口内提示条；Perch 不在前台 → 系统通知（设置里开启时）。
- **提示音只给需要你处理的事**：确认、回答、失败、疑似卡住在前台也会响；一轮结束只在后台随系统通知响。
  Perch 不从后台自己放声音，后台的声音只跟着系统通知走。
- **每类事件三档**：不提醒 / 静默 / 提示音（设置 › 任务通知 › 提醒方式）。默认：一轮结束、确认或回答、失败为提示音，
  疑似卡住为静默。旧的“仅通知需要我处理的任务”迁移为一轮结束“不提醒”。会话右键菜单的静音优先于所有档位。
- **疑似卡住来自状态条**：只有正在打开的会话能判断（见「状态条」），由 `turnStalled` 交给 `deliverStall`；
  在看这个会话时状态条自己说明，只在档位为提示音时响；不在前台时发系统通知「任务几分钟没有新进展，可能卡住了。」
- **Dock 角标**：数字是等你处理的会话数（与侧栏“待处理”同一口径：在线、未归档、等你处理分区）；没有时若有未读结果显示圆点。
  可在设置中关闭。完成通知仍在 2 秒内合并。

## 轮次刻度导航

- 操作顺序为悬停预览、上下扫读、点击定位、移开收起。首次驻留 120ms 后展开局部刻度；离开保留 90ms 容错，重新进入取消关闭。只悬停不滚动正文。
- 刻度围绕共同中心线伸缩：普通短线、邻近渐进加长、当前阅读深色长线、悬停浅底、点击反馈可叠加；键盘焦点另有轮廓。局部映射变化用 180ms 缓出，扫读强调用 100ms 缓出。Reduce Motion 跳过动画。
- 摘要卡片只显示一行问题和最多三行回复，14pt，按内容自适应高度，在视口边缘内夹紧；相邻轮次共用卡片位置，文字立即切换。不显示轮次计数或收藏按钮。
- 动画只插值刻度 Canvas 的坐标和强调程度，不能传播到正文；摘要复用投影缓存，不在鼠标移动时解析 Markdown。绘制数量保持有界，快速连续定位只执行最后一次，远距离跳转保持虚拟化，不遍历挂载途中所有正文。
