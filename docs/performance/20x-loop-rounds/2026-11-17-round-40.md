## 方法学发现（入册）

1. **bench 内建 oracle 封锁 stale 探针**：benchStreamingDelta 每 prepend
   周期执行 warm-vs-fresh 参考比较（StreamingBench.swift:213-215
   「a prepended page must present like a full projection」）——stale
   输出探针必死（探针 3 实证）。全流水线上界只能以完全正确的实现测得
   =设计本身。**探针 1 不触雷的机理（评审 F2 更正）**：门为 **tail
   口径**（prefixCount=tail 消息数-1），prepend 只增长历史 prefix 不改
   tail ⇒ 分页周期门**命中**（插桩实证 hits=75/misses=8）——初稿
   「count 变化必 miss→全量重算」解释**错误撤回**。oracle 全程通过的
   真实原因=split 构造（make(prefix)+make(suffix)）与全量构造在该
   fixture 全部命中点**逐位相等（fixture 偶然等价，实证非普适）**：
   make 存在跨消息分组上下文（answer/final lastIndex 扫描、
   thinkingPreview 仅末 phase），一般形态下 split≠whole——这正是
   正式设计需解决的核心等价性问题，也是「设计风险高」的实证依据。
2. **live-turn 稳定性初步分析**（设计资产，未来若重启直接复用）：
   纯文本 delta 下 phases.count 不变、仅末 phase 消息内容增长 ⇒ 前缀
   entries 稳定；**新消息到达**可 retroactively 改变 presentation
   （answer/final 判定 lastIndex 扫描、thinkingPreview 仅末 phase）⇒
   稳定前缀=「除末 entry 外」仍需在每次新消息时全量校验合并边界
   （coalescingAdjacentAssistantParts 可使增长消息并入前一 entry ⇒
   entry 边界不随消息边界——round-39 列出的局部性问题在探针设计中
   确认为实质障碍）。
