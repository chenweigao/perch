# 工作台、待处理与任务组增强

本轮在现有三类页面职责上增加结果交接和归组建议，不改变远端会话的执行权限。

## 工作台与待处理

- 工作台的“新进展”展示当前范围内新出现或版本变化的请求与结果。首次使用包含当前事项；手动“确认看过这些变化”保存本机检查点，独立于结果已查看和远端审批。离线、归档不参与；正常运行和其他状态作为下一次变化的基线。
- 检查点使用原生完成计数、Kimi 完成时间、Herdr revision 等现有信号。相同状态下的同类新提问若上游目录没有新的标识，不能保证区分；这不是完整的离线事件日志。
- 点击待处理或结果打开详情面板：原生 Agent 与 Kimi 使用原有审批/提问组件，错误保留具体信息和完整会话入口。Herdr 终端仍回到原会话处理。
- 最后一个请求在真实快照中消失后，自动进入当前筛选范围的下一项；失败或断线不触发前进。请求绑定原会话，界面中的待处理顺序保持稳定，新到事项追加。
- 结果面板展示最新公开回复，最多 3000 字，可打开完整会话、按当前展示版本标为已查看、调用已有 Recap，或保存至关联任务组成果。Recap 仍沿用用户配置，点击后才生成。

## 任务组

- 增加人工维护的完成标准与进行中/暂停/完成阶段，勾选标准或会话运行结束均不自动改变组阶段。
- 成果可保存结论、链接/路径与来源会话。网页链接可打开，远端路径只显示为可复制文字。
- 旧 workspace.json 的组和关联不变，新字段按空列表与进行中读取。

## Agent 归组

- 从工作台或任务组菜单打开“Agent 帮我归组”。使用现有的可选摘要服务，点击生成前展示将发送的数据范围。
- 每批最多 40 个未归档会话，优先未归组会话；最多 24 个进行中的任务组。只发送标题、目录末三级、已有归属、组名、目标及最多 6 个示例标题，不读取或发送聊天正文、工具输出、凭据。
- 模型按目标给出关联建议和原因，允许多个组；没有足够依据时应留空。仅接受输入中存在的会话与任务组 ID，去重，忽略已有关联，拒绝格式错误的响应；输出被长度截断时保留其中已完整的建议，完全无法解析时才报错。
- 用户可取消选中不适合的建议，一次应用。应用仅追加关联；撤销只在该批关联尚未被后续人工调整时执行，保留其他组信息。撤销记录保留于当前 App 进程。
- 本轮不自动创建任务组，不在后台发送分类请求，也不自动应用建议。先验证实际归类质量，再考虑可信规则下的自动归组。

## 验证

- `scripts/build.sh` 构建正式 App；`WorkbenchChecks` 覆盖旧格式迁移、保存/恢复、结果版本、稳定队列、归组响应校验、幂等追加与撤销冲突。
- `scripts/build-native-acceptance.sh` 后运行 `scripts/run-native-acceptance.py --mode workspace --output <新目录>`：使用完整生产界面和内存原生 transport 检查连续处理、独立确认变化、成果来源和人工完成阶段。不连接真实 Agent，不加载用户工作区。
- 真实 Kimi/原生 Agent 审批往返，以及实际摘要模型的归类准确率，需要另行实测。编译与内存 fixture 不代表这些已通过。

### 本次验证结果（2026-09-26）

- 正式 Release 构建、严格深度签名校验、WorkbenchChecks、ConnectionChecks、629 项本地化源键覆盖和 diff 检查均通过。
- `.local/workspace-actions-acceptance-final/result.json`：连续处理、独立确认变化、成果来源与人工完成均为 true；只有预期的内存审批写请求，进程退出码 0。
- 在独立 Perch Acceptance 窗口实际查看任务组、请求面板和归组入口；结果预览改为复用正式 Markdown 渲染。
- 未发起真实 SSH/Agent 审批或外部模型分类请求，未替换用户安装的 App。归组准确率、真实 Kimi 往返仍未验证。
