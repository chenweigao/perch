# 侧边栏结构、身份与尺寸的对照实验

本轮把此前混在一次置顶更新中的因素拆开，完成 17 组配置 × 3 轮，以及两组候选各
3 种混合负载 × 3 轮配对，共 87 次初始实验。**采用同一列表中的稳定会话身份**；
空标题常驻、统一 48pt、副标题常驻均保留为验收程序里的实验选项。

收益有明确范围：跨分区移动显著改善；完整会话切换没有获得同等幅度的提速。
没有迁移状态框架或存储，没有更改最近会话额度、正文、草稿和原生玻璃外观。

## 17 组独立因素

同一个固定二进制、release -O、1280×820 窗口。每轮 80 次状态变更，取三轮各自
中位数的中位数；CPU 为整个循环的进程 CPU 时间。普通场景使用 500 条规范化记录，
选中会话与草稿不变。固定成员的置顶场景特意只提供 20 条记录，避免置顶后从目录
补入额外四行，因此不能把它与 500 条场景相减，声称得到某项独占成本。

**标题增删、可见集合变化与结构身份变化是不同成本。** 标题控制没有任何成员变化，
1600 次已有行位置移动全部保留探针身份。成员替换创建/移除各 320 个探针，但共同
存在的 16 行始终保留身份。跨分区控制没有成员增删，却仍创建/移除各 320 个探针。

完整置顶场景原结构创建/移除各 480 个探针：320 次共同 ID 的替换，加上 160 次
确实进入/退出可见集合。统一列表保留共同 ID，仅剩各 160 次必要的成员增删。
这解释了一个可消除的结构成本，不意味着这 480 个对象就是 AppKit 的所有行宿主。
探针是行背景中的 NSViewRepresentable，UUID 标识其生命周期；它不枚举 SwiftUI
内部所有宿主，也不单凭身份计数证明鼠标、焦点或滚动体验。

状态切换两组都有 1600 次实际行高变化；固定高度两组都是 0。所有独立目录场景
正文 configure/reconcile/host-create/host-measure 均为 0。普通内容和行高场景中，
统一列表的耗时基本持平；其主要收益发生在跨分区移动。

## 带回完整工作台

每种候选各自与原结构交错运行三个轮次；每轮依旧 80 步。这里没有行级原生探针，
验收边界是挂载的侧栏投影、选中正文、可见草稿和 layout/display/CA flush。
与逐行几何核验的独立实验边界不同，不能交叉比较绝对毫秒数。

| 候选 | 场景 | 配对原结构 | 候选 | 原结构 / 候选 CPU |
| --- | --- | ---: | ---: | ---: |
| 统一列表 | 仅切换 | 58.417ms | 58.969ms | 4.916 / 4.972s |
| 统一列表 | 目录混合更新 | 25.498ms | 24.599ms | 2.022 / 2.029s |
| 统一列表 | 目录更新＋切换 | 74.236ms | 74.255ms | 6.167 / 6.207s |
| 副标题常驻 | 仅切换 | 62.796ms | 59.410ms | 5.263 / 4.981s |
| 副标题常驻 | 目录混合更新 | 25.976ms | 25.696ms | 2.048 / 2.046s |
| 副标题常驻 | 目录更新＋切换 | 73.845ms | 73.541ms | 6.173 / 6.193s |

统一列表在目录混合更新中约快 3.5%，CPU 基本相同；联合更新中位数持平，CPU 约
多 0.7%；纯切换中位数约慢 0.9%、CPU 多 1.1%。不能宣称整体性能提升 20%。
其采用依据是明确的跨分区收益与身份稳定，而不是完整工作台显著提速。

副标题常驻在独立动态高度场景约快 10.9%，CPU 仅省 3.5%；混合目录/联合更新
中位数约省 1.1%/0.4%，CPU 没有相应改善。其纯切换看似快 5.4%，但这组原结构
三轮中位数跨度 58.95–63.11ms，明显比前一组波动大；候选联合场景也有一轮到
77.72ms。原始数据全部保留，未删掉较慢轮次。没有依据把这部分差值都归因于代码。

## 采用与保留

- **采用统一列表和稳定会话 ID。** 分区标题、任务组块、会话行和尾部动作构成同一个
  ForEach；会话在同一 `Entry.session` 分支里移动，ID 不包含所在分区。仍由现有
  Observation 状态和投影供数，没有新增第二份业务状态或常驻的隐藏行缓存。
- **不采用空标题常驻。** 对完整置顶约省 10.5%，仍有 320 次跨分区替换，且会留下
  无内容标题。统一列表无需这个界面代价即可获得更大收益。
- **不采用全行固定 48pt。** 本轮复现约 19% 的局部改善，同时确实降低内容密度。
- **副标题常驻暂留实验。** 隐藏节点使用零高度和间距补偿；联合收益不足以支持
  扩大正式文本布局改动。后续若尺寸热点仍主导，可围绕文本布局做独立验收。

当前可确认的瓶颈是目录视图的结构与尺寸更新；上一轮框架图更新/布局采样提供背景，
本轮以身份、几何和实际耗时验证其中的具体因素。本轮没有测试 TCA、SwiftData 或
AppKit 整表替代，不能声称它们更快或更慢。当前证据支持先改列表组织方式；只有
剩余成本在真实使用中继续形成问题，才值得扩大到列表控件原型或其他架构迁移。

## 最终版本复核

最终整理版共享分区控件，避免把原型里复制的按钮和菜单带入正式代码。另做三轮
带/不带行探针的置顶对照、固定成员对照，以及真实 AppStorage 折叠/展开、隐藏期间
更新、运行中筛选和最后一条置顶移除的挂载验收。最终数据与命令记录见
[measurements.json](measurements.json) 的 `final-*` 与 `checks`，不与原型构建混算。

| 最终版三轮 | 原结构 | 统一列表 | 原结构 / 统一列表 CPU |
| --- | ---: | ---: | ---: |
| 置顶，带行探针 | 27.861ms | 22.090ms | 2.086 / 1.558s |
| 置顶，关闭行探针 | 23.501ms | 18.822ms | 1.779 / 1.412s |
| 固定 20 成员，带行探针 | 19.805ms | 12.642ms | 1.632 / 1.050s |

关闭行探针后响应仍改善 **19.9%**、循环 CPU 改善 **20.6%**。该控制以侧栏投影和
布局/显示/CA flush 为就绪边界，不宣称此时验证了逐行几何。带探针的相同代码路径
另行验证了内容、物理顺序、高度和生命周期，原结构共同 ID 替换 320 次、统一列表
0 次的结果稳定复现。无探针时的生命周期字段全零表示未测量，不表示没有原生行。

最终源码摘要为 `aa6b6d4816aba890e4390dae43f2ff9d4643a773d72c1c811493f5e557b257ad`。
结构检查分别运行新旧两种布局；还验证 all、sidebar-invalidation、invalidation、
detail-lifecycle、render-combined，以及生产构建/签名、WorkbenchChecks、
ConnectionChecks、性能工具测试和本地化检查。

## 复现与边界

初始 87 次实验使用源码摘要 `cab20dd368d659f69b635b87fd72969470ec050fd0bd8a37444784d72c4fa636`，
二进制摘要 `854f9d5b40046a6b84baab7df73e7fef09a44e7b3d11c0247d374a68f6477625`。
[experiment.patch](experiment.patch) 在 `6299514` 上应用，可精确重建该源码摘要，已
独立核对。逐轮清单保存 Swift 6.4、release -O、窗口、源码/二进制摘要、各轮统计及独立布局场景
的 80 步原始样本；混合负载保存统计，没有逐步原始时间。

```sh
bash scripts/build-native-acceptance.sh
python3 docs/performance/2026-09-29-sidebar-sweep/run-matrix.py --app <固定应用> --output <新目录>
python3 scripts/run-native-acceptance.py --app <固定应用> --mode render-combined --sidebar-variant flat --output <新目录>
python3 scripts/run-native-acceptance.py --app <固定应用> --mode sidebar-layout-pins-unprobed --sidebar-variant baseline --output <新目录>
```

`--sidebar-variant` 还有 `keep-header` 和 `persistent-subtitle`；最终默认是 `flat`，
其余变体只编译进验收应用。原始记录和两个固定应用在 `.local/sidebar-sweep/`。

所有计时串行执行，未与本任务的构建、测试或 profiler 并行；外部桌面进程不受控制。
1ms 异步等待、布局/显示/CA flush 与就绪核验均计入响应，输入数组生成和逐行身份/
几何统计计入循环 CPU、不计入每次响应。无变化底数不可直接相减为业务独占耗时。
结果覆盖局部离线 fixture，包含更新时的新行创建，**不覆盖冷启动全窗口首屏、真实
SSH/模型、硬件输入/输入法、鼠标焦点完整体验或显示器 FPS**。未推送或部署。
