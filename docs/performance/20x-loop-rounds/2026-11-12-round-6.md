# Round 6：未知/只读工具免做路径检查（2026-11-12）

产品基线 `0711150`（#325 已合并）；本地 `6a85376` 只有合并记录的文档差异，
修改前与 origin/main 的产品和测试源码一致。

## 归因和单一假设

对 round 5 候选 `9f73166`（产品源码等于新 main）做独立 Mac CPU profile：
全部测试进程采样 251ms，包含 fixture 构造；SessionEditStats inclusive 71ms，
其中 StringProtocol.contains inclusive 19ms。不可将嵌套栈相加，也不是 A/B 耗时。
profile 前后 binary hash 一致，见 [采样摘要](round-6/profile.json)。

`compute` 原来先读取 file_path/filePath/path 并做 Foundation `contains("://")`，
再按工具名 dispatch；未知/只读工具总是返回 nil，路径工作没有消费者。

## 修改（产品只有 Core 8 行净变化）

先取同样的 `tool.lowercased()`，只接受原来五个 alias：edit、edit_file、write、
write_file、apply_patch；其余先返回 nil。已识别工具继续走逐字相同的路径优先级、
Foundation URL-ish 拒绝与 payload switch，后者复用规范化名字。

没有用 byte contains 改写 Unicode 规则。`tally` 的 normalized apply_patch changes
数组分支不变（它本来在 compute 之前处理）。没有缓存/异步工作、连接或权限修改，
`Sources/AgentWorkbench` 零差异。

## 冻结行为检查

`checkEditToolClassification` 用原来的“先 path，后旧 alias switch”公开结果为预言机，
known payload 的 counts 固定；行扫描仍由 round 5 的独立 Character oracle 覆盖。

- 25 种 known/unknown 名称、混合大小写、Unicode casefold/dotted I/全角字母；
- 16 种字段组合：优先级、null/非字符串/数组/缺失、empty string、URL、Windows-like
  与 canonical/补充平面路径，以及不能当成 ASCII 的标点；
- unknown 工具有完整 Edit/Write/patch payload 仍不能变成 edits；
- changes 数组对 normalized apply_patch 生效，其他工具仍按原规则；数组内 URL 拒绝、
  空 diff 的零 stat 保留；envelope 级 URI path 不干扰 changes 自身路径；
- 重复 message/tool ID、只读消息夹住真实 edit，不污染累计结果。

共 800 个单消息矩阵组合及累计检查；原先 Unicode 行扫描、nil/empty 与 paging oracle 全绿。
