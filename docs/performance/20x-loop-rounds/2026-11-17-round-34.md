| string-compare | 9.35% | 字典键相等比较+input sameWindow |
| dict-find | 9.22% | __RawDictionaryStorage.find 7.03% |
| teardown | 7.82% | 临时字典/数组析构 |
| narrative | 3.94% | ActivityNarrativeProjection（inclusive 7.4%） |
| timeline-make | 3.80% | ConversationTimelineEntry.make（inclusive 13.1%） |
| tool-visibility | 3.31% | ToolVisibilityProjection（inclusive ~4.6% 含 Pass.*） |
| model-update 本体 | 2.86% | update 框架残项（inclusive 91.6%=容器） |
| input-compare | 2.28% | sameWindow 输入比较（含 1.65% 叶） |
| cf-match | 0.82% | 匹配残余（分页无查询，近零 ✓） |

**hash/dict 叶消费者归因**（prepend 相）：`History.joined(_:foldsProcess:)`
5.20% + `History.init(turns:turnCount:source:)` 2.67% +
`ToolVisibilityProjection.projectTurns` 5.09% + Pass.collect/normalize/
present ~1.0% + String.hash 内联 7.51%。**字典机械（hash+find+compare+
breadcrumbs ≈ 36%）+其触发的 ARC/桥接 ≈ 分页成本主体**；消费者几乎全部是
History 构建/拼接与 ToolVisibility 全窗口投影。

**结构根因（评审 F1 更正后，双侧源码核对一致）**：初稿"prepend 平移 turn
序号 ⇒ memo 失效 ⇒ 全 turn 重拼"**错误，已撤回**。源码事实：
- **turn 粒度复用已存在且生效**：`HistoryTurn` 按（首条消息 ID + chunk 引用
  同一性）复用（ConversationPresentation.swift:377-385 `prior.chunk === chunk`
  → `reusedTurnCount`）；`HistoryTurn.presented` memo 只键于
  (activity, foldsProcess)，**与位置无关**（:88-98）；`projectTurns` 的 chunk
  复用按内容验证（count+sameWindow）+ 位置无关锚点 ID（ToolVisibility-
  Projection.swift:208-259）。**剖面佐证**：timeline-make inclusive 仅
  4.16%——只有页边界切开的 ~1-2 个 turn 重投影，其余全部复用。
- **每次 prepend 真正重建的是全局索引与容器层**：`projectTurns` 的 owner
  字典（**全窗口每 identity 一次 string-hash 插入**，~16k）+turnAnchors+
  prefixIdentities 全集 union+chunks 字典+新 Prefix 容器；`History.init` 的
  entryTurns（全窗口 ~9k row-ID 插入）+rows/navigation 逐 turn 拼接；
  `joined` 的 rows/parents O(output) 拼接容器（ARC 拷贝）；外加 input
  sameWindow O(窗口) 验证。区域表的 string-hash 17.5%+dict-find 9.2%+
  string-compare 9.4% ≈36% 与 ARC/桥接大头（arc-copy 18.2%+utf16-bridge
  16.3%+teardown 7.8%）即这些全局结构的构建/销毁成本；inclusive 消费者
  （评审独立复算，与本报告归档输出逐值一致）：projectTurns **18.24%**、
  History.init **15.74%**、History.joined **13.43%**、model.update 74.25%
  （容器）。
- 结论修正为：**O(窗口) 的是全局字典/集合/验证与 O(output) 的容器装配，
  per-turn 投影本身已 O(页)**——优化面在全局结构层，不在 turn 记忆化
  （其已存在）。

**find-bar 份额的两口径更正（评审审计）**：innermost 区域口径下 find-* 仅
~2%，但那是**低估**——find 内部的 ARC/哈希/比较叶被通用机械区域吸收；
inclusive 口径（含 ConversationSearch 帧的样本）=**全 trace 16.27%、
decode-free 口径 27.30%**，与 bench find_bar_query_update 0.25ms/更新吻合。
正确表述：**rounds 27-33 消除的是重建机械**（渲染/序列化/全历史匹配——
cold 路径），**留下的正是设计内残项**：每更新一次整窗前缀验证（round-33
归因 27µs 量级）+后缀 per-entry 路径+hits 共享（round-33 守卫后零拷贝）。
另评审审计给出 decode 污染更精确口径：事件解码 inclusive **40.4%**（其中
3,735 样本的解码衍生 ARC/比较散落通用区域）——decode-free 口径
（n=12,272）才是链构成：arc-copy 17.9%、utf16-bridge 17.6%、narrative
12.2%、cf-match 11.1%、teardown 8.4%、input-compare 6.9%、string-compare
6.8%、find inclusive 27.3%。

**判定**：流式链路无单点可立项主导（最大可命名非 find 机制 narrative
inclusive 13.1%，round-20 已双机制否决在案；input-compare 为变更检测语义
本体；cf-match 为 live-turn 匹配语义红线；find 残项=round-33 已关闭方向的
设计内剩余）——**流式方向本轮不立项**；narrative 若重估须先过否定清单核对
（round-20 H1-H5）。

**相位切分敏感性（评审审计披露）**：lookahead 与 previous-marker 双规则在
2,953 样本（14.5%）上不一致（相位边界样本）；两规则相位计数一致
（J=2,548/P=17,861），归档输出经评审独立复算**逐值一致**
（archived_output_exact_match=true，双 XML sha256 在案）。

## Round-35 候选方向（草图，按评审 F1 重构；五点门控论证留待立项轮）

**前提修正**：turn 粒度记忆化**已存在**（HistoryTurn/chunk 复用+位置无关
memo），不是候选。候选目标是评审更正后剩下的实测大头——**全局索引与容器
装配层**：
1. **prepend 感知的全局索引增量化**：owner/entryTurns/turnAnchors 三大字符串
   字典每次 prepend 全量重建（~16k identity 插入 + ~9k row-ID 插入）；
   prepend 语义下既有 identity→turn 映射只需**序号平移**（+页数 delta），
   新页 identity 增量插入——O(页 identity + turns) 替代 O(窗口 identity)
   哈希插入；prefixIdentities 全集 union 同步增量化。
2. **容器装配**：rows/navigation 每次全量 append（O(output) ARC 拷贝）——
   评估 prepend 友好的分段/持久结构或容量复用（Swift Array 语义内可行域
   立项轮回答）。
3. **键驻留/哈希复用**：同一批 id 字符串在 owner/entryTurns/chunks 多处反复
   哈希（breadcrumbs 桥接开销符号在案 1.7%）——评估 intern 或每行一次哈希
   复用。
- 预期：older_page 三件套中字典机械 ~36%+伴随 ARC/桥接的可去除部分 ⇒
  目标 -40~60%（4.1ms→~1.6-2.5ms，Mac 可测面充分）不变——机制份额不因
  归因表述修正而变。
- 关键设计问题（立项轮回答）：owner 字典的**重复检测语义**（updateValue==nil
  守卫）与 prefixIdentities 全集语义在增量化下的等价保持；序号平移与
  observedByTurn/anchored 的位置消费方梳理；ConversationPresentationCache
  内存放位置与预算（有界缓存五点论证）；失效语义沿 round-12/30/32 谓词族。
- 红线检查：展示层行为等价钉死密集（presentation/paging/fold 测试族既有），
  等价断言零放松；不碰 Sources/AgentWorkbench。
- 风险：全局索引增量化触碰**折叠/可见性正确性**（用户可见缺陷类）——钉死
  密度须对齐 round-30/32 水准；重复 id/跨页 turn/页边界切分等边界矩阵。
