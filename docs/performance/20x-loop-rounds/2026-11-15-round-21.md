## 归因（miss-heavy KB 画像 ×3：base/v1/v2，全部归档 [round-21/attr/](round-21/attr/)）

harness：唯一文本/更新（表永不预热）、0.7～4KB 循环、20s xctrace。
与 round-20 首跑（缓存热循环）的关键差异：**MISS 分布保真**。

| 口径（of narrative 段） | base（String 键） | v1（字节键逐字节回退） | v2（字节键 withUTF8） |
| --- | --- | --- | --- |
| make() inclusive（of all） | 86.85%（17,383/20,014） | 85.04%（17,022/20,017） | 82.76%（16,561/20,012） |
| **phase 闭包**（lowercased+32 contains） | **60.82%** | 67.34% | **75.07%** |
| String 键 `_normalizedHash` | **29.56%**（find 3,088+insert 2,050） | **0** | **0** |
| ByteText 机制合计 | — | **24.30%**（UTF8View 逐字节 subscript 11.08% 全部在 `==` 的 elementsEqual 下 + combine(bytes) 6.77%） | **9.51%**（combine(bytes) 7.88% 叶；withUTF8 帧 2,407；逐字节 subscript **0**） |
| 字典 ensureUnique / _unsafeInsertNew | 11.86% / 11.80% | — | 3.30% / 3.20% |
| L() 默认参数链 | 4.79% | — | — |

**v1 粗筛零收益之谜（决定性实验）**：v1 确实清零了 NFC 哈希，但
`utf8.elementsEqual` 走 `IndexingIterator` 的逐字节 `Collection.subscript`
witness（1,892 样本），且 `withContiguousStorageIfAvailable` 对 clean/
narrativeText 产出的 substring-backed String 返回 nil → 每次哈希落入
`Array(text.utf8)` 逐字节回退——ByteText 机制 24.30% ≈ 被替换的
25.68%（of all），净省 ~5% ⇒ 与 v1 Mac 粗筛 +0.67% 吻合。**v2 修复**：
等值/哈希统一 `String.withUTF8`（mutating，经 COW 局部副本；任意存储给
连续缓冲）——逐字节路径清零、ByteText 降到 9.51%。双平台探针先行验证
（withUTF8 为 mutating 的编译陷阱在探针中拦截）。

**份额-墙钟转化失配（第三维非同构，HYPOTHESIS）**：v2 画像显示表机制
从 base ~46%（hash+ensureUnique+insert，含重叠）降到 ~16%，预示 wall
-30%；实测仅 **-3.5%**（~1/7 转化；对照 round-17/19 扫描类机制 ~1:1）。
推断：画像循环万次更新使表达 8,192 上限**反复驱逐重建**、桶探针跨
cache line，而 bench 25 更新表 <150 条目 **L1 常驻、零驱逐**——画像的
insert/ensureUnique/桶探针成本被系统性过代表（ensureUnique 11.86%→
3.30% 的候选侧变化亦部分系表操作绝对量差异）。**归因 harness 同构性
要求扩展至第三维：输入规模（round-20）→ 缓存命中分布（round-20 F3）→
表规模/驱逐动力学（本轮）**。phase/clean 等纯 CPU 文本扫描不受此维度
影响，其份额（60.82→75.07%）跨画像可信——round-22 选靶依据。

## 机制与方法学记录

- **归因→墙钟转化率第三数据点（新形态）**：round-13 self-time 8.64%→
  -1.65%、round-18 归属 1.88%→-0.07%、本轮表机制 ~30pp 份额差→-3.5%
  wall。新维度：份额的**可迁移性取决于机制成本对运行环境的敏感度**——
  内存层级敏感机制（字典探针/驱逐/大表）在画像与 bench 间不可线性迁移；
  纯 CPU 扫描机制（round-17/19 的守卫搜索）迁移 ~1:1。round-22 的 phase
  候选属后者（预期迁移保真）。
- **stdlib API 热路径陷阱 ×2**（入否定清单附注）：①
  `String.UTF8View.elementsEqual`/`Array(text.utf8)` 经 IndexingIterator
  的逐字节 subscript witness，KB 级文本上与 NFC 哈希同量级；②
  `withContiguousStorageIfAvailable` 对 substring-backed String 返回
  nil——trim/join/String(slice) 产物在文本管线中占比极高，回退分支
  即热路径。正解：`String.withUTF8`（mutating，任意存储给连续缓冲）。
- **粗筛均值回归**：n=3 的 -9.5% 在 n=6 回归至 -2.52%；临界候选必须
  扩展粗筛再裁决。
- mini harness 无新伪影：本轮全部二进制原地运行、等价输出非空校验、
  Mac 双侧 checks 全绿。
