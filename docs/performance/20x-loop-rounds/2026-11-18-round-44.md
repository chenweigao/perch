## 方法：round-39 F3 教义落地

round-39 F3 记录「ARC/bridge 等通用叶桶是非互斥分类桶，不是可攻性分区」，round-43 的
分析器只对 hash/dict 叶做了消费方归因。本轮把它扩展到 utf16-bridge / arc-copy /
cf-match / teardown 四桶，方法是：对 decode-free 的每个样例，从叶帧向上走，跳过
**机制帧**，把样例记给第一个「真实代码」帧。

关键实现细节（首轮错误与修正，如实披露，见 `round-44/ATTRIBUTION-NOTE.md`）：
ARC 慢路径（`RefCounts::doDecrementSlow`）、数组扩容/复制（`_ContiguousArrayBuffer.
_consumeAndCreateNew`、`Array._createNewBuffer`、`_copyToContiguousArray`）、字典写入
（`_Variant.setValue`）等**仍是运行时机械帧**。首轮实现停在「第一个非桶帧」，把 60-70%
的样例记到这些辅助帧上（数字留档）；修正后继续上溯到产品代码，才得到可裁决的分解。

## 验证族统一净估复核（round-37/39 遗留队列项②）

源码复核（本轮新增证据）：

- `ConversationPresentation.swift:604-610`（cost-reuse）：深值比较仅对
  `reuseEnd..<input.messages.count` 的**新索引**做 `previous.messages[index - shift] == message`；
  `cost(_:)` 也只对没有 `==` 命中的新消息计算。**不扫整窗**。
- `ToolVisibilityProjection.swift:432-446`（canReuse）：`KimiMessage.sameWindow(messages[..<split],
  prefix.source)` **整窗**扫描——bitwise 层（`memcmp`）失败后走逐元素深值回退
  （profile 叶 `closure #1 in closure #1 in static KimiMessage.sameWindow` 4.14%）。

⇒ 两层的重叠只在「新追加段」，不是 round-37/39 表述的「每 prepend 各扫同一后缀窗口」。
按本轮口径，去重可消除的量 ≤2%（cost 侧 ~2% 中与新追加段重合的部分），**低于带下沿，
不立项**。

**方法学入册**：重叠消除的净估必须按**每层实际扫描范围**重算（源码级确认范围与触发条件），
不能用并集份额相减；并集份额只说明「同一机制在多个消费方下出现」，不说明可去重量。
