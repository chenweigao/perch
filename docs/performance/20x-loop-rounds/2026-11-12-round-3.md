# Round 3：单文本摘要省去重复 Character 计数（2026-11-12）

紧接 round 2 继续。基线产品代码 `3b679fb`（round 1）；round 2 未采纳，无代码依赖。

## 单一假设和修改

`ConversationTurnSummary.make.excerpt` 对常见的单 text part 消息：
1. 从原文本取 `prefix(320)`；
2. 前置一个空格，复制为 value；
3. **再计数 value 的 Characters**，只为判断停止循环；
4. 空白规范化。

只有一个 part，步骤 3 无任何预算消费者。单 part 且为非 runtime-context text
时直接做原来相同的 `(" " + String(text.prefix(320))).collapsedWhitespace`；
多 part、附件、runtime-context 和 cron envelope 仍走原路径。skill 激活仍取
`skillContextSplit.prefix`。不改 320 的 Character 语义，也不以 UTF16/UTF8 长度替代。

产品差异只有 WorkbenchCore 的 8 行分支；`Sources/AgentWorkbench` 零差异。
没有新增缓存、异步工作、用户数据访问或连接行为。

## 行为等价

`checkTurnExcerpt` 冻结修改前的 Character-budget 算法作为预言机，比较 prompt/reply：
- 单 part 与五种混合 part 形态（两个 text、前置 text、附件、runtime context）；
- 318/319/320/321 等截断边界，空字符串，中文、补充平面、旗帜和 emoji ZWJ；
- combining marks、Prepend、CRLF、Unicode 空白、3,000 段混合语料；
- skill 激活与 cron prompt 提取，空摘要的附件名称 fallback。
