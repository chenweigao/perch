## 方法：round-39 F3 教义落地

round-39 F3 记录「ARC/bridge 等通用叶桶是非互斥分类桶，不是可攻性分区」，round-43 的
分析器只对 hash/dict 叶做了消费方归因。本轮把它扩展到 utf16-bridge / arc-copy /
cf-match / teardown 四桶，方法是：对 decode-free 的每个样例，从叶帧向上走，跳过
**机制帧**，把样例记给第一个「真实代码」帧。

关键实现细节（首轮错误与修正，如实披露，见 `round-44/ATTRIBUTION-NOTE.md`）：
ARC 慢路径（`RefCounts::doDecrementSlow`）、数组扩容/复制（`_ContiguousArrayBuffer.
_consumeAndCreateNew`、`Array._createNewBuffer`、`_copyToContiguousArray`）、字典写入
（`_Variant.setValue`）等**仍是运行时机械帧**。首轮实现停在「第一个非桶帧」，把 60-70%
的样例记到这些辅助帧上（数字留档）；修正后继续上溯到产品代码，才得到可裁决的分解。

## 验证族统一净估复核（round-37/39 遗留队列项②）

源码复核（本轮新增证据；**按形态分口径**）：

- **流式形态（本轮数据所在）**：`ConversationPresentation.swift:598-614` 的 cost-reuse，
  历史被重用时 `reuseEnd == split`，循环只覆盖 `split..<count`（live 尾部）——深值 `==`
  不进前缀窗口；TV 侧 `canReuse` 的 `sameWindow` 才整窗扫描（bitwise 层失败后走逐元素
  深值回退，profile 叶 `closure #1 in closure #1 in static KimiMessage.sameWindow` 4.14%）。
  ⇒ 流式下两层重叠仅在尾部，可去重量 ≤2%，低于带下沿。
- **分页形态（prepend）**：`oldCosts.count < split` 使 `reuseEnd = 0`，且 `shift > 0`
  （历史整体后移），循环退化为对**每个** index 做
  `previous.messages[index - shift] == message` = **整窗深值比较**；TV 侧 `canReuse`
  同样整窗扫描。⇒ round-37/39「两层各扫同一后缀窗口」的表述**在分页形态成立**，
  其 3-4% 净估**未被本轮推翻**，只是不适用于流式链。

⇒ 本轮裁决限定为流式链：≤2%，**不立项**；分页链（older_page）的双层去重仍留队列，
将来若重新评估必须按分页形态自身重算。

**方法学入册（修正版）**：重叠消除的净估必须按**形态 × 每层实际扫描范围**重算
（源码级确认 `reuseEnd` / `shift` 等触发条件），不能用并集份额相减；同一机制在不同形态下
扫描范围可以完全不同——本轮初稿把流式范围的结论无条件外推到分页，经评审（Codex P2）
更正。
