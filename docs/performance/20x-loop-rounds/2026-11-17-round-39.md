## 立项与假设

**本轮不立项（评估轮，round-34/37 先例）**；交付 **round-40 组合候选
设计**：「live-turn 增量派生族」——单一机制类（**前缀稳定的 live turn
在 delta 间复用已派生结构，只重算增长的尾部**），覆盖两个消费方：
1. **ConversationTimelineEntry.make 增量化**（8.45%）：live turn 的
   messages 前缀在 appendDelta offset 校验下物理稳定；新增 per-turn
   派生缓存（前缀消息数+物理同一性快路径验证【buffer 地址比较，
   O(1)】+深值 == 回退），前缀 entries 复用、仅尾 entry 重派生。
   设计问题：coalescingAdjacentAssistantParts 的局部性（追加 assistant
   消息仅影响尾 entry 的合并边界——需源码论证+钉死）；
2. **NarrativeTextCache.steps 增量派生**（narrative 残余主体）：增长
   entry 的 steps 派生按 part 前缀复用（part 级粒度天然对齐 append-only
   流），全文键控静态表的 8192 全清驱逐风暴随之缓解（派生次数从
   每 delta 全量降到尾 part）。
   组合预期 9-11%（make ~7% + steps ~4-5% − 验证开销 ~1-2%），高于
   分类器可信阈；单点拆分则均低于阈——**合并立项符合单一机制类纪律
   （round-35 先例：prepend 感知增量化覆盖 owner+identities+entryTurns
   双结构）**。红线预检：make/steps 输出逐位等价（oracle 差分钉死）、
无 API 形变、无全局 memo（per-model/per-turn 有界缓存，五点论证适用）。

**队列其余项（降级/搁置，数据在案）**：双层验证统一（净 3-4%，需先
完成红线评估——round-41+ 视 round-40 结果）；displayMessages（仅 API
层提案渠道）；narrative steps 单独立项（并入组合候选）。

**停止规则计数 1/3**（本轮评估不立项）。
