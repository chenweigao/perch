# 200 轮历史：本轮收尾，验收未全部通过

2026-09-21。按用户要求结束本轮性能工作，不再增加实验，不启动 20 分钟长跑；保留实现和证据，后续回到侧边栏、功能整合与开源准备。

## 保留的修改

热点是 `ConversationEntryController.measure` → `NSHostingController.sizeThatFits` 及 SwiftUI 布局事务。原实现切换时同步创建、测量整份 200 轮历史，修正会话身份后的短测中位耗时约 4.30 秒。

- 用一个原生文档视图保留行的位置，只为视口中的行创建宿主。未读行先估算高度，读到时替换为实际高度；已访问行保留控制器及展开状态。
- 使用滚动内容的逻辑坐标计算可见范围。曾出现第 44、114、169 轮跳过的问题，最终完整遍历检查已覆盖全部 200 轮和末尾行。
- 历史宿主通过一个主线程队列分批释放，兼顾替换内容和销毁整个页面；避免多组释放任务在快速切换时叠加。
- Kimi 保留滚动容器，新会话到达时重置跟随状态。对话行仍按会话身份重建；工具和思考的展开内容继续单独测量。
- 删除不再使用的逐行 SwiftUI 包装器。未使用 SwiftUI 惰性列表，未加入产品功能。

这是历史视图挂载及生命周期的修改，没有调整远端 Agent、会话协议或权限。

**结论：秒级历史重建成本已明显下降，但短测仍有尖峰，不能作为性能验收通过。** 缓存切换 p95 ≤100 ms、选择反馈 ≤50 ms 尚未稳定达到；首次遍历仍会掉帧，不能将已读历史的滚动结果代表所有浏览场景。

早期同实现附近曾记录切换 p95 72.34 ms、已读滚动 p95 10.06 ms；最终两次较差结果均保留，未挑选最好一次。后台应用负载存在波动，但没有证据将尖峰归因于某个系统服务，也没有修改系统安全设置。

旧版约 4.30 秒切换的 4 次短探针只用于判断大幅改进，不能提供可靠 p95。旧版首次滚动与当前已读滚动的预热条件不同，因此本轮不据此宣称滚动严格提升 3×。原正文流式 3× 目标未重测。

这些是程序化选择/滚动到布局、显示提交的隔离测量，不包含鼠标事件、网络、解码及 GPU 最终呈现，也不代表正式 App 已完成验收。测试侧栏只复用生产筛选逻辑及行几何，未运行完整 WorkbenchModel。

## 实验与验证边界

- 重建整个对话页的对照 p95 约 151 ms；加入统一释放队列后约 135 ms；保留容器的对照约 72 ms。均为短测，不外推为全 App 加速比。
- 延后未挂载视图的测量、下一主循环再创建正文，两项候选没有明确改善，均已撤回。诊断打印也已移除。
- fixture 的页面观察边界对齐生产 Kimi 页面；就绪判定同时要求会话标记和该会话实际挂载的原生行，完整阅读检查读取原生文本并核对 1–200 轮及最后一行。
- 前序隔离 UI 检查确认中文、表格、代码、末尾内容及展开工具在离开/返回视口后保留状态。最终候选又通过两次完整原生内容覆盖检查。没有使用正式会话完成 UI 验收。
- 最终 Release 编译通过；现有 WorkbenchChecks 通过。没有设置 `WORKBENCH_LIVE_HOST`，真实 SSH 检查明确跳过。未替换或启动正式 Perch，未合并 A 到 main。

## 长跑报告保障与后续缺口

fixture 新增启动、每分钟进度及最终结果文件，失败退出码为 1。`scripts/run-navigation-check.py` 记录二进制指纹、PID、退出码和超时；正常退出但没有最终报告仍视为失败。重建场景的内容等待失败已验证错误报告和非零退出路径。

JSON 中 `status: passed` 仅表示 fixture 执行和内容断言完成，**不表示延迟指标达标**。此前 21 分钟缺报告的根因仍未确认；这轮未重跑长测，也不能把新增记录机制当成该问题已经修复。
