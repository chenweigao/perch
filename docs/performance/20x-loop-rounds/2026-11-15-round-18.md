# Round 18（2026-11-15）：TimelineEntry visible() 去 trimmingCharacters 分配——不采纳（Linux 特有收益，Mac 噪声内）

**结论：不采纳（候选已撤回，产品零改动）。** 候选在 Linux 冷投影四档
**-54～-55% 六对全分离**，但**采纳平台 Mac 上 cold@2000 仅 -0.07%**
（worst +3.90%、spread 4.37%——变化为噪声带的 1/60，分布完全重叠），
Mac 全部 80 项指标零正向零回归。机制与 round-10 否定清单条目完全同构：
`trimmingCharacters` 的开销是 **swift-corelibs-foundation 走 UTF-16 物化的
Linux 特有成本**，Apple Foundation 无可比开销——按 INDEX 红线（"不能把
Linux 特有开销的降低算成产品收益"）与"Linux 筛选、Mac 仲裁"规则**否决**。
这是该机制的**第二次实锤**（round-10：定时信封 O(1) 守卫，Linux -17.89% /
Mac -0.96%；round-18：visible() 分配消除，Linux -55% / Mac -0.07%），
否定清单条目已强化。

## 候选来源（round-17 四场景复剖 @76940c0）

cold 场景 `ConversationTimelineEntry.make` 12.1%（2,427 样本，此前从未
动过）为红线外最大未触碰块。caller 级下钻（方法同 round-16/17）：
`flush` 1,027 / `make` 本体 522 / **`visible(_:)` 376 样本**。flush 的
主体是每 part 构造 `KimiMessage(content:[part])` 的结构性 ARC/malloc
搅动（改动高风险，未选）；visible() 则含一个干净机制：
`(part.text ?? "").trimmingCharacters(in: .whitespacesAndNewlines).isEmpty`
——**仅为判空而分配整段裁剪副本**，对长文本 part（bench 与真实会话的
prose/answer 均数百字节到 KB 级）是逐 part 的 O(n) 拷贝。

## 候选改动（已撤回；补丁归档 [round-18/rejected-visible-whitespace.patch](round-18/rejected-visible-whitespace.patch)）

`visible()` 改调 `isAllWhitespace`：`s.unicodeScalars.allSatisfy {
whitespacesAndNewlines.contains($0) }`（同一 CharacterSet，短路、零分配）。
等价论证：trimmingCharacters 从两端裁剪集合成员，结果为空 ⟺ 全部 scalar
属集合；空串两侧同为"不可见"。**输出等价经双端实测**：mode-1 四档
cold_rows/appended_rows/actual_parts/text_bytes 全等（Mac
ROWS_IDENTICAL_NONEMPTY、Linux 逐字段一致），两端检查双侧全绿
（Mac 99/99、Linux 98+1 SKIP）。

## 机制与方法学记录

- **归因 self-time 严重低估分配的系统性成本（Linux）**：visible() 在
  cold 归因仅 376 样本（~1.9%），但消除其分配后 Linux cold 全窗 -55%——
  corelibs trimmingCharacters 的 UTF-16 物化+分配+ARC 释放成本散布在
  Foundation/malloc/release 帧与下游缓存压力中，不落在 visible() 名下。
  round-13 教训（"归因 self-time 不保证可转化"）的镜像：**低 self-time
  也可能掩盖大系统性成本**——但跨平台可迁移性仍只能由 Mac 仲裁裁决。
- **Apple Foundation 的 trimmingCharacters 对首尾非空白串近乎免费**
  （两端扫描即止+轻量 substr），故 Mac 无可测收益。凡以"消除
  trimmingCharacters"为机制的候选，立项前必须先过 Mac 上下文内粗筛
  （否定清单已按双案例强化）。
- **harness 伪影披露**：Mac 粗筛首次尝试把二进制 cp 到日志目录运行——被
  macOS SIGKILL（exit 137），产出的 "ROWS_IDENTICAL" 为双空假阳性；
  改原地运行 SwiftPM 产物（round-16/17 A/B 同法）后重测并加非空校验
  （ROWS_IDENTICAL_NONEMPTY）。教训：**Mac 上被测量的二进制必须原地
  运行；等价校验必须断言非空**。
- 停止规则计数：本轮无"可采纳收益"，计数 1/3（rounds 14-17 连续采纳后
  的首个不采纳轮）。
