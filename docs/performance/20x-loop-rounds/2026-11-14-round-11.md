# Round 11：collapsedWhitespace 零拷贝字节路径与永不绑定预过滤（2026-11-14，候选）

产品基线 `93b9ad3`（#331，纯 CI 基建；测量子树 Sources + Tests/WorkbenchCoreTests +
Package.* 与 `d1590e4` 逐字节一致，ls-tree sha256 `8a4de619…`，故无基线漂移，
昨晚基于 d1590e4 的完整 Mac 六对作为复现 run 保留）。单一假设：round 10 报告指名的
Mac 侧归因已完成——冷投影的大头是每轮摘要的字符串构造，其中 `collapsedWhitespace`
字节路径存在三项**可省的机械开销**：输入整体 `Array(utf8)` 拷贝、每个多字节标量走
slice 迭代器的 `append(contentsOf:)`、以及空白后每个非 ASCII 标量都付两次完整
Unicode 属性查询（CJK 文本必付）。

## 修改（两个提交）

1. **fix(core)：补全钉死的 Prepend 集**（契约修复，先行提交）：新增的"空白邻接
   全标量走查"（110 万标量，逐个对比字节路径与属性逻辑推导的应然结果）在**未修改
   产品**的匹配基线上失败于且仅于 U+111C3、U+113D1——工具链 Unicode 数据已把这两个
   标量列为 Prepend，而 round 1 钉死的集合缺它们（两端匹配基线均 exit 133、恰好
   两条 MISMATCH，见 [linux.json](round-11/linux.json) / [macos.json](round-11/macos.json)
   checks 字段）。按该集合自身注释的契约（"数据更新必须以测试失败显形"）补入；
   过包含是安全方向（多一次 strict 回退，不会错答）。
2. **perf(core)：字节路径去机械开销**：`Array(utf8)` 改为 `withUTF8` 就地读
   （对本地原生连续串零拷贝，闭包内 COW 局部变量仅 refcount）；多字节标量按已解码
   长度直拷替代 slice 迭代；`beginsBindingMark` 前置钉死的"永不绑定"区间
   （CJK/假名/谚文/全角等 15 段，已扫描确认区间内无任何融合标量，U+FF9E/FF9F 因
   Grapheme_Extend 被排除），命中即跳过两次属性查询。**输出逐字节不变**：预过滤只
   在"完整属性逻辑必然返回 false"的区间生效，由上述穷举走查按当轮工具链数据钉死。

## 特征化的既有缺口（未修复，已钉住）

穷举走查同时把字节路径与 strict 契约的**既有**分歧特征化：7 个标量类在"空格邻接"

安全）。走查按其现状钉住（防漂移），修复列入候选队列；本轮不扩大范围。

## 下一轮入口

冷投影剩余最大单块是 excerpt 的 `prefix(320)` 字素行走（归因 20.81%：
`String.index(offsetBy:limitedBy:)` + 字素断 machinery）。320-Character 语义是产品
行为不可改；可行方向是避免 `String(prefix)` 物化与 `" " +` 拼接的中间分配、或
在 UTF-8 字节上做等价截断的保守快路径（全 ASCII/全 BMP 非组合场景），需先设计
等价性钉法再动手。其次：7 标量特征化缺口的契约修复（扩展 `beginsBindingMark`
的钉死融合集）与 `validateUTF8` 输出校验（~3.9%，无公开 API 绕过，暂挂）。
