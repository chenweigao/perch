## 方法学发现（入册）

1. **bench 内建 oracle 封锁 stale 探针**：benchStreamingDelta 每 prepend
   周期执行 warm-vs-fresh 参考比较（StreamingBench.swift:213-215
   「a prepended page must present like a full projection」）——任何
   输出不正确的上界探针在该 bench 上必死。全流水线上界只能以完全正确
   的实现测得=设计本身。**上界探针可行性分类**：门条件在探针期间保持
   输出正确的探针可行（探针 1：前缀稳定门在纯文本 delta 下 entries
   前缀确实不变——bench oracle 不触发，因为 oracle 比较发生在 prepend
   周期而前缀门在 count 变化时 miss→全量重算→输出正确）；stale 复用型
   探针不可行。
2. **live-turn 稳定性初步分析**（设计资产，未来若重启直接复用）：
   纯文本 delta 下 phases.count 不变、仅末 phase 消息内容增长 ⇒ 前缀
   entries 稳定；**新消息到达**可 retroactively 改变 presentation
   （answer/final 判定 lastIndex 扫描、thinkingPreview 仅末 phase）⇒
   稳定前缀=「除末 entry 外」仍需在每次新消息时全量校验合并边界
   （coalescingAdjacentAssistantParts 可使增长消息并入前一 entry ⇒
   entry 边界不随消息边界——round-39 列出的局部性问题在探针设计中
   确认为实质障碍）。
