## 归因依据（round-12 复剖 + round-9 队列遗留）

round-12 的 Mac activity 复剖（[归因](round-12/macos-xctrace-streaming-activity-attribution.json)）：
`ToolVisibilityProjection` 帧占测量段 **18.3%**（running-ids 区域，叶表以
swift_retain/release、bridgeObjectRetain、`__RawDictionaryStorage.find`、
`Hasher.combine`、`initializeWithCopy for KimiPart`、`Pass.normalize` 为主）。
机制（round-9 队列已指出）：`ConversationActivity.init` 每次状态栏派生都
new 一个全新 `ToolVisibilityProjection` 走完整 `update()`——collect 把当前轮
**每个工具 part 拷贝**进 calls/results 两个字典，normalize **重建整轮
normalized 消息数组**（每消息新 content 数组、tool_use 替换为合成 part、
orphan 追加合成消息），再包一层 Snapshot——而消费端只做一件事：按源顺序
走一遍 normalized 消息取 `tools[toolCallId]`。

与 round-13 被否决的"遍历形态微优"不同，这是**结构性消除工作**（round-13
教训后队列重排的选型偏好）：不优化的遍历，而是让中间产物根本不存在。

## 假设与改动

假设：状态栏可见工具列表可以在**不物化** normalized 消息、Snapshot 与
字典内 part 拷贝的前提下直接产出，顺序与值逐点等价。

改动（810b025）：
- `Sources/WorkbenchCore/ToolVisibilityProjection.swift`：新增静态出口
  `visibleTools(in:live:running:online:)`。calls/results 字典记 **(消息,part)
  位置**而非 part 副本；单遍按源顺序直接产出 `[VisibleTool]`：首见 tool_use
  （emitted 去重；重复 call 保持首槽位、但取**最后记录**的 call 数据——与
  投影的 collect last-wins + 首见发射语义一致）、每条消息的 orphan result
  紧随该消息自有工具之后（与 tool-orphan 合成消息位置一致）、observed live
  工具按观察序（首见定序、末次定载荷）最后补入；未标识 part 的位置身份
  `unidentified:<message>:<offset>`、状态矩阵（failed/succeeded/returned/
  disconnected/running/missingResult）、`calls[id] ?? part` 回退、
  `hasCall`、progress/name/input 取值全部逐点复刻 `present()`。
- `Sources/WorkbenchCore/ConversationActivity.swift`：init 中的
  update+快照遍历（12 行）替换为一次出口调用。
- 其他投影调用方（ConversationPresentation 的 Chunk/Prefix/Split 机制、
  runningIDs、TaskContextFiles、NativeSubagents、AgentWorkbench 两处
  runningIDs 调用）**零改动**；`Sources/AgentWorkbench` 零差异。

## 行为等价钉死

新增 `checkActivityToolsMatchProjection()`（[ActivityToolsProjectionTests.swift]，
注册于 checkToolVisibility 之后）——**只用既有公共 API**：
`ConversationActivity(...).tools` 必须逐元素等于"完整投影 update() + 原
遍历"的 oracle（oracle 内含 activity 同款 last-prompt 切片）。因此在
matched baseline 上它比较的是投影与自身（必然通过），在候选上钉死
出口 ≡ 遍历。覆盖：

- 九个手工场景：普通循环、**重复 call id（首槽位/末数据）**、孤儿 result、
  **先 result 后 call**（collect 先行 ⇒ 非孤儿）、未标识 call/result、
  live 工具有/无窗口记录 + live 重复 id（观察序/末次载荷）、离线状态、
  running 集合、无 prompt 窗口、多 prompt 切片。
- **2000 个种子化差分用例**（固定 LCG 种子；小 id 池强制重复/孤儿/跨消息
  配对，随机 role/text/thinking/tool 混合、1/6≈16.7% 未标识、随机 live/
  running/online），并断言语料非空产出占比 >75%（防空转假通过）。评审方以
  Python 独立重放语料：1,982/2,000 非空、六种状态全覆盖、534 例跨消息重复
  call、719 例先果后因、435 例重复 live id。
- **契约边界（评审 NB1 如实记录）**：出口的文档契约是**单轮窗口**（activity
  的 last-prompt 切片保证）。未切片的多 prompt 窗口且**重复 prompt id** 时
  存在已知顺序分歧反例（[user("u"), user("u"), assistant(call)] + 未记录
  live：完整投影 [live, recorded]，出口 [recorded, live]）——重复锚点使投影
  的中途 appendUnrecorded 提前发射。生产路径经切片不受影响；差分语料因先
  切片 + id 唯一而不覆盖该反例，作为契约外行为如实记录。空 id、合成 id
  碰撞、空窗口、缺 name/input 字段等边角由源码检视支持（评审确认），无专门
  钉死用例，一并记录。

两端基线/候选四项全绿：Linux 95 PASS + 1 SKIP、Mac 96 PASS（含数学），
均 exit 0——本轮**无预期失败**（等价钉死不含只在新产品成立的断言）。

## 伪影与不主张的变化（如实记录；披露数组由原始 pair 日志程序化计算入 JSON）

- **find_bar_query_update +3.64%**（0.275→0.285ms，最差对 +7.41% = spread，
  未越出）：逐对 [+20,0,+10,0,0,+10]µs——搜索路径本轮零改动，打印网格级
  抖动（**推断**：网格步长 + 形态与 round-12 起九组同类数组一致；"路径零
  改动"本身不构成因果证明），不作回归信号。
- **conversation_activity（Mac 0.00% vs Linux -28.57%）**：两端同用 0.01ms
  打印网格（StreamingBench 同一格式化器）。Linux 该段 0.07→0.05ms、逐对
  一致 -20µs（两格）；Mac 0.03→0.03（逐对差在网格之下，spread 50%）。以
  Mac 主指标（single_turn 两档，直接测量同一 init）为准。
- **activity_init@320/@6400 的 16.67%/25% spread**：0.006→0.004ms 为
  0.001ms 网格上的两格移动，百分比放大是小值刻度效应；@1280 六对一致
  -33.33%（spread 0.00）。
- **"无正向超 spread"的准确口径（评审批注）**：指**中位数**变化无一越出
  自身 spread 且全对同向；单对差值可越界（如 Linux older_page_full_chain
  最差对 +11.94% > spread 9.33%，其中位数仅 +1.96%）——单对波动，无方向
  一致性。其余中位数在 spread 内的行（cold@100 +2.78%/spread 44.44、
  stage_conversation_activity -25% 小值档等）均为噪声或刻度效应，不主张。
