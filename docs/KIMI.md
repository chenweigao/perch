# Kimi 原生对话

连接现有 Kimi Web 服务，Mac 本地使用 SwiftUI 渲染会话、正文、代码、工具结果和交互卡片。
Kimi 与 Herdr 共用任务组、侧栏、打开标签和待处理队列；两种连接与内容视图独立。每台 SSH 机器保存独立的 Kimi 配置，可在新建任务中切换。端口默认 `58627`，令牌路径默认 `~/.kimi-code/server.token`；两者均可在接入向导的高级设置修改。

## 使用

1. 从「环境 → ＋」验证 SSH 并选择 Kimi。向导可打开终端安装、登录，并通过「启动 Kimi Web」启动后台服务；已有服务可直接检查。手动启动命令为 `kimi web --host 127.0.0.1 --port 58627 --no-open`。
2. 在统一侧栏按标题、目录或工具名搜索，点击对话图标的会话，继续 Web 上已有的对话。单击切换，右键可置顶、分组与归档。
3. 从“新建 → 原生对话”或 ⌘N 创建，选择机器与 Kimi；接入向导支持浏览和验证远端项目目录；新会话第一次发送需要选择服务端已配置的模型。任务组内新建会话时自动关联到该组。
4. Return 发送，Shift Return 换行。运行中发送的新消息按 Kimi 的 prompt 队列处理。
5. 附件按钮选择本地文件，点击发送时上传；历史图片支持服务端文件和会话媒体引用。
6. 工具参数与输出可展开；提问支持单选、多选和自由回答。确认卡片的允许只针对本次，不创建会话级允许规则。
7. 输入框底部可直接选择 `manual`、`yolo` 或 `auto`，所选值随下一条 prompt 的 `permission_mode` 发送。新会话使用设置中的 Kimi 默认值；历史会话没有可识别的权限字段时显示“沿用会话设置”，Perch 不主动注入或放宽权限。`auto` 属于高风险模式，启用前需要再次确认。
8. 浏览旧记录时暂停跟随，并可加载更早消息；正文底部的居中向下按钮返回最新回复。

## 界面布局

统一侧栏按当前任务组或机器筛选 Kimi 对话与终端；正文与输入框共用居中阅读宽度。用户消息使用浅灰气泡，回复直接显示。工具调用按发生顺序穿插在会话中，默认显示工具名、操作摘要与状态，完成后保留；仅参数、进度与输出按需展开。思考与运行上下文分别折叠，实时思考预览按内容收缩并限制最大高度，溢出时在标题右侧显示“查看完整思考”。输入框底部集中放置附件、模型、权限模式和发送操作；审批与提问仍独立显示。

## 会话管理与切换

- 侧栏是唯一会话导航；省略号与右键菜单提供置顶、分组、归档和永久删除。
- Kimi 归档使用现有服务 archive 接口，恢复使用 v2 restore 并检查每项结果；已归档列表来自服务端。
- 永久删除需确认，并在执行前重新读取会话状态；运行中的会话不允许归档或删除。
- 最近 8 个已打开对话缓存在当前进程。切回时先显示缓存，再读取新快照；同步成功前不允许发送、审批或回答，避免基于旧状态操作。
- 对话流更新仅通知内容视图，目录仅在会话元数据或连接状态变化时更新。切换后的本地保存通过串行后台队列写入，正常退出时完成最终写入。

## 协议边界

- 实际对接版本为 Kimi Code 2.0.2（Node 版），WebSocket protocol_version 2。
- 通过独立 SSH TCP 转发访问服务。本地端口随机分配且仅监听 loopback。
- SSH 读取该机器配置的令牌文件（默认 `~/.kimi-code/server.token`）；Bearer 仅留在进程内存，不写入本地配置、日志或 URL。
- 直接使用 REST 和 WebSocket，不嵌入网页，也不抓取终端文本。
- REST 检查业务 envelope 的 code；HTTP 200 不等于业务成功。
- 会话列表显式分页。历史使用 snapshot 最新 100 条及 before_id 分页，保留已加载的更早记录。
- snapshot + seq/epoch 恢复订阅；文字增量按照服务端 UTF-16 offset 去重，缺口触发快照恢复。旧步骤的增量不能覆盖新快照。
- 所选会话订阅 main agent；子 Agent 工具输出可在主会话结果中出现，但尚无独立子 Agent 视图。
- 消息请求带客户端 prompt_id；结果未确认时保留草稿并提示核对，不自动重发。
- 连接丢失会标示旧内容并禁用发送；自动重连重新读取快照。退出客户端不终止远端任务。

## 当前范围

支持会话列表、新建、历史翻页、文本发送、模型选择、附件上传、图片预览、工具详情、停止、审批、结构化问答和恢复所选会话。
使用系统字体、原生文本选择和代码复制。Markdown 支持行内样式、基础标题、围栏代码和表格；图表、完整文件差异和独立产物面板尚未验收。
外部 URL 图片及任意远端 path 不自动下载。视频附件不内嵌播放。
草稿和待发附件当前只保留于本次 App 进程；置顶会话、打开的工作现场、所选会话和任务组一并保存。
归组只建立本地关联，不把对话内容发送给另一个会话，也不把 Kimi 的工具终端当成 Herdr 会话。

参考：[官方服务 API](https://moonshotai.github.io/kimi-code/en/reference/server-api.html)、
[官方源码](https://github.com/MoonshotAI/kimi-code)。具体字段以运行服务的 OpenAPI、AsyncAPI 及已安装 2.0.2 实现验证。

## 运行中引导

运行中发送默认先 `POST /sessions/{id}/prompts`，再对返回的排队消息 ID 调用 `POST /sessions/{id}/prompts/{prompt_id}:steer`。选择“下一轮发送”只提交排队；若提交时任务已经空闲、返回状态为 running，则直接开始新一轮。

客户端读取 `GET /sessions/{id}/prompts` 恢复待发消息，按 `user_message_id` 与历史合并（历史对照取会话已加载消息与快照页的并集，长任务把用户消息挤出快照尾页时仍能识别）。会话空闲且服务端不再报告的 running 或已引导消息视为已随本轮完结，气泡退场——已引导内容会以合并后的新消息 id 进入历史，客户端无法按 id 匹配，本轮结束即其退场信号；排队、受阻和未确认的消息不以此规则清除。引导接口失败时保留已接收的消息及错误，不把同一内容重新提交。HTTP 接收与上下文回显分开显示。
