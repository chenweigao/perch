# 工作台与任务组统一（2026-09-28）

工作台回答“现在该做什么”，任务组保存“一个目标怎样推进”。任务组成为工作台的范围，
侧栏、工具栏、首页组行都进入同一布局、读取同一队列。会话仍是执行载体，可跨机器、多组关联。

## 结构与交互

- 首页依次提供待处理预览、正在推进的任务组、待查看结果、运行中、最近会话。
- 任务组概览展示人工下一步、待处理/结果/运行数量和未同步状态；最近成果保留标题。
- 默认显示五个进行中目标，完整目录提供名称/目标/下一步搜索，也能找到暂停和完成的组。
- 侧栏显示所有置顶组及五个最近访问组，并保留当前组。全部任务组回到工作台目录。
- 保留主线的新进展确认、行动详情连续处理、可预览撤销的 Agent 归组与文件审阅；待处理入口优先于新进展。
- 组内仍使用 WorkbenchDashboard，仅增加目标、下一步、继续入口、完成标准、成果与历史关联。
- 组内待处理保留组和机器范围。侧栏全局待处理清除范围，与全局徽标口径一致。
- 工具栏选择组与侧栏组入口等价；机器条件独立，切换组不清除机器条件。筛选可见且可单独清除。
- 组内搜索收窄会话和批量归档，不改变目标、成果、完成标准；进入待处理时清除搜索。
- 全部会话/已归档仍是全局目录。已归档关联在组内保留，可恢复。尚未同步的引用可管理。

## 状态与数据

- 唯一组状态为 selectedGroupID，不再保存一份独立的“任务组筛选”。机器筛选不持久化。
- 阶段（进行中/暂停/完成）由人维护；会话结束、全部标准勾选均不自动完成目标。
- 完成目标不会隐藏仍需处理的审批。全局计数按会话身份，不对各组数量求和。
- 离线会话及尚未同步引用不计入实时动作数；仍可看到未同步提示。
- 组顺序按置顶、最近访问和原顺序决定，避免流式更新使目标不断跳动。
- 旧工作区缺少 criteria/outcomes/stage/isPinned/lastOpenedAt 时使用兼容默认值。
- 成果保留说明、链接或路径及来源会话；仅 HTTP(S) 链接直接打开，路径保留为可复制文本。
- 归组不共享模型上下文、不启动任务、不改变远端进程。原生 Liquid Glass 外壳保持不变。

## 验证

核心检查覆盖多机器范围、离线与归档计数、跨组动作不重复、手工完成、旧数据迁移和往返保存。
原生 dashboard 验收使用完整生产页面与内存 transport，核对实际导航、组内待处理、空范围、
搜索、阶段、来源与置顶持久化，并执行 60 轮队列变化/滚动检查。

命令：

```sh
./scripts/build.sh
swift run --build-system native -c release WorkbenchChecks
swift run --build-system native -c release ConnectionChecks
python3 scripts/check-localization.py
./scripts/build-native-acceptance.sh
python3 scripts/run-native-acceptance.py --mode dashboard --output .local/unified-workbench-final-mounted
python3 scripts/run-native-acceptance.py --mode workspace --output .local/unified-workbench-actions
./scripts/build-task-group-preview.sh
```

隔离验收不证明真实远程审批、模型质量、用户效率提升或设备 FPS。
后续用现状/新布局的等难度任务交替顺序试用，记录恢复工作耗时、正确成果查找、遗漏与误操作；
样本小时按具体卡点迭代，不宣称统计显著收益。
