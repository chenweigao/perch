# 分支改动审阅

Git 面板增加“分支改动”：输入执行环境中已有的分支、远端跟踪引用或提交（例如 `origin/main`），点击“比较”。

- 比较目标与当前 HEAD 的共同祖先到 HEAD，显示当前分支已经提交的改动；目标分支独有的提交、暂存、未暂存和未跟踪文件不混入结果。
- 比较时固定目标提交、共同祖先和 HEAD。随后打开各文件仍读取这组提交，即使分支已移动；点击“比较”或“刷新”才更新版本。
- 选区反馈沿用加入草稿流程，附带执行环境、原/新行号、内容指纹及完整比较提交 ID，不自动发送。
- 重命名显示旧路径到新路径，并按两条精确路径读取；删除、二进制、截断差异沿用现有展示。路径按字面值传给 Git，不解释为 pathspec 模式。
- 缺失引用、无提交、无共同祖先会显示错误，清除上一份差异，不会呈现成“无改动”。
- 使用仓库中现有引用；不 fetch、不切分支、不修改索引或工作区。本机和 SSH 共用现有只读执行通道。

## 验收

`run-native-acceptance.py --mode branch-review` 验证实际 RemoteFileBrowser：提交差异与工作区差异切换、错误清理和带提交信息的草稿。此模式加入 macOS 功能检查。验收使用本机临时仓库和内存 Agent，不代表真实 SSH/模型或双 Mac 恢复验收。

## 审阅连续性与文件引用

- 分支按钮列出执行环境已有的本地/远端跟踪分支，仍可输入任意提交；每个环境和工作树记住比较目标与范围。
- 手动标记文件已读，使用上一个/下一个文件继续审阅。比较目标、最后一个文件、滚动位置和已读进度保存在本机。
- 刷新按两侧 Git 对象、文件模式和重命名来源判断是否改变：没有变化的文件保留已读状态；发生变化的文件标为“有新改动”并清除旧阅读位置。已删除出比较列表的条目不计入进度。
- 比较版本默认折叠。引用或选区反馈加入草稿后，显示确认和“查看草稿”入口。
- Kimi 与原生对话输入框支持 `@` 搜索当前执行环境、当前 Git 仓库内的项目文件；任务位于子目录时仍覆盖根目录和同级目录。列出跟踪文件与非忽略的未跟踪文件，不读取正文；列表过大或非 Git 目录明确提示改用文件面板。
- 精确文件名和文件名前缀优先于路径中的其他匹配，最多显示 30 项；短列表按条目数量收缩。刷新后从首项重新选择，悬停可查看完整路径。
- 上下键选择、Tab/Return 引用、Esc 关闭；中文输入法确认继续由编辑器处理。引用以带引号的绝对路径保留在普通草稿中，支持预览和移除；补全不会发送消息，也不上传本机文件。
- 新建任务输入框也支持 `@`，按所选执行环境与项目目录搜索，尚未建立会话也能使用。点击引用在当前新建任务页面打开只读预览，关闭后继续编辑原草稿；不会打开已有会话的文件面板。切换环境或目录会取消旧预览读取。

`branch-review` 原生验收新增已读恢复、逐文件导航、滚动位置、内容变化失效和实际输入框文件补全。初次测试对 macOS 临时目录别名的比较不一致，已修正为解析两侧路径别名；原始失败结果保留。上述验收使用本机临时 Git 仓库，不能代替真实远程恢复。
