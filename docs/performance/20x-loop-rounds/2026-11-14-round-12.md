## 假设

开查找栏后每个流式 delta 都会重搜"最近轮"（最新提示之后的消息）：已渲染文本
缓存（`previous.sources == sources`）只省去重新渲染，**locale 匹配与 excerpt/
hit 构建仍对每个条目每次重跑**——包括消息完全未变、甚至零命中的条目（无命中
也要全文扫描）。而一个条目的 hits 是 `(entry.messages, isRunning, query,
options)` 的纯函数：校验通过即可整体复用该条目的 hit 列表。

## 改动（最终态 = v1 候选 + 两个评审修复提交）

`Sources/WorkbenchCore/ConversationSearch.swift`（+78/-16）、
`Sources/WorkbenchCore/KimiProtocol.swift`（+134）、检查 +252 行；
`Sources/AgentWorkbench` 零差异；`git diff --check` 干净。

- **v1（c0a88f8）**：`Entry` 增加 `messages/isRunning/query/options/hits`；
  `search()` 循环顶部当四项校验通过时整体复用 hit 列表，跳过 sources 构建、
  渲染、匹配与 excerpt 构建，并**收养**新 messages 副本（round 8 教训：让下次
  比较读到最新载荷字节）。校验失败落入既有路径（sources 相等复用渲染文本，
  否则重建），原缓存语义不变；role 过滤语义保持（被过滤条目从不入缓存，
  lookup 必然落空）。prefix 整体复用（`Earlier`）与失效逻辑不变。
- **修复 1（c0092e1，Codex P2）**：查询缓存键改为编码精确比较
  （`sameQueryKey`：UTF-8 字节），同时用于新的条目级校验与**既有的**
  prefix 级 `Earlier` 校验——规范等价（NFC/NFD）的查询在 regex 模式下是
  不同的 pattern，字面量匹配也不保证折叠一致；round 8 起的 `earlier.query == query`
  同样有此漏洞（matched baseline 在该转换处失败即为证）。
- **修复 2（23bebb2，独立评审 BLOCKING）**：消息校验升级为"可搜索同一性"
  `sameSearchableWindow` = 字节层（位相同 ⇒ 渲染必相同，稳态每 delta 的
  快路径）∨（值相等 ∧ 渲染字节相等）。渲染层比较覆盖到达
  `ConversationSearch.sources` 的全部字段（type、text/visibleText、toolName、
  name、input、output）：字符串按 UTF-8 字节（CoW 共享存储走指针快路径）、
  JSON 数值按 bitPattern（-0.0 渲染 "-0" 而 `==` 判等）、对象键按字节
  （`display` 用 sortedKeys，插入序不影响渲染，但键自身编码影响）。只参与
  值判定的字段（thinking、source、metadata、isError、fileId、id、role、
  createdAt）由值层钉住，其规范等价差异不改变渲染字节。两个缓存层
  （Earlier 与条目级）同用。窗口比较的规范值语义（round 8 钉死的"重解码
  窗口必须可复用"）不受影响：同 wire 字节重解码 ⇒ 渲染字节相同 ⇒ 复用存活
  （WindowIdentityTests 继续通过）。

每 delta 剩余固定地板：prefix 全窗字节比较（~16k 消息 memcmp）、数千 hit
数组的 CoW 拼接、最近轮 `ConversationTimelineEntry.make`、live entry 重搜
——入队列第 2 项。

内存（评审 Q3 如实记录）：`Entry` 额外保留 messages 浅副本与 per-entry hits；
保有量随加载窗口与命中数有界（与既有渲染文本缓存、`Earlier.hits` 同界），
字典逐调用整体替换、不随查询/选项切换次数累积；prefix 条目的 excerpt 字符串
与 `Earlier.hits` 共享存储，不重复计数。未建立 RSS 上界实测；命中密集的查询
相比旧的纯文本缓存会增加保有量。

## 行为等价钉死

`checkSearchEntryReuse()`（[SearchEntryReuseTests.swift]，注册于
checkWindowIdentityReuse 之后）：warm 实例每次 `hits(...)` 必须逐字段等于
全新实例的完整重算，覆盖矩阵——

- token 增长 ×（ALPHA/BETA 查询轮换 + **固定查询增长**：每步第一个 BETA
  紧跟上一步 BETA，仅 live 消息变化，且断言命中数随 tokens 增长——钉死
  "变化的 live 条目下缓存的非空 hits 必须失效"，评审 Q4(a)）；
- 查询切换（工具 input、数值键、CJK、切回）；大小写敏感开关（sensitive
  命中必须为 0）；regex 开关（`AL+PHA` 与折叠字面量命中数一致 + 同 pattern
  作字面量）；role 过滤轮换（user/assistant/all）；
- **零号符号翻转**（评审 Q1(b)）：prefix 变体与"仅最近轮"隔离夹具各一组，
  同查询紧邻前后调用（邻接是触发复用路径的前提）；断言翻转后 "-0" 命中
  清空、live 条目缓存 hits 不得存活、而字节未变的 prefix 条目 hits 必须存活；
- **NFC/NFD 编码键转换**（Codex P2）：regex 与大小写敏感字面量两种模式的
  往返切换，并钉住"规范相等不蕴含编码相等"；
- 条目内时间戳就地改写（隔离：其余不变）、被 make() 跳过的 tool-result
  消息的时间戳与 role 翻转、metadata-only 改写（不参与渲染）、toolCallId
  改道（断言 hit.toolID 跟随）、同字节长度 answer 就地改写（ALPHA→ALPHB）、
  同 wire 数据重解码窗口（复用必须存活）、prepend 更早页、running 旗标翻转。

engaging（复用确实生效）不由检查断言而由 A/B 指标证明——检查因此不依赖任何
新 API，matched baseline 可编译；基线在**两处既有漏洞**的转换处按设计失败
（先零号符号翻转，其后是 NFD 查询键；后者另有 v2 测试态的独立证据
`checks-base-matched-v2.log`，崩溃帧 SearchEntryReuseTests.swift:117），
候选必须全过——round 11"基线预期失败"先例。既有钉死不变：bench 每 delta
`found.hits.count >= completedTurns`（v3 两端 12/12 streaming run 通过，
见 Q5 更正）、WindowIdentityTests 全套继续通过。
